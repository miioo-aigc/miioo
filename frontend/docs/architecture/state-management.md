# 状态管理规范

> 文档类型：页面状态、Hook、Store 与副作用边界
> 最后更新：2026-07-15

## 1. 状态分层

### 页面状态

只影响当前页面或当前页面实例的状态放在页面或页面 Hook，例如当前标签、打开的面板、表单草稿、当前分页、临时加载态和弹窗开关。

### 业务 Store

多个页面或多个业务区块需要共享、恢复或持久化的状态才进入 Zustand Store。Store 不应承载某个页面的 JSX、DOM ref、临时弹窗开关或一次性请求细节。

### 组件内部状态

只影响自身展示和局部交互的状态放在组件内部，例如下拉菜单展开、悬停、输入法局部状态和试听播放状态。组件卸载后不需要恢复的状态不要上提到页面或 Store。

### API 状态

请求函数只负责请求、鉴权入口和响应适配，不保存页面 UI 状态。请求失败由调用方决定如何显示错误；API 层不得引用页面组件。

## 2. Hook 规则

- Hook 负责组织可复用状态逻辑和副作用，不负责大段页面 JSX。
- 一个 Hook 只围绕一个主要职责，例如数据读取、选择状态、生成动作或任务生命周期。
- Hook 的输入和返回值必须明确，不返回无法理解的巨大匿名对象。
- 使用定时器、事件监听、AbortController 或流式请求时，必须在清理函数中释放资源。
- 拆分 Hook 前先列出闭包依赖；迁移后检查依赖数组、取消逻辑和组件卸载后的状态更新。

## 3. API、Store 与组件的边界

```text
页面 / 页面 Hook
  ├── 调用 API
  ├── 读取或更新 Store
  └── 向组件传递明确 props 与回调

业务组件
  ├── 可以管理局部交互状态
  ├── 需要明确业务动作时可调用 API 或业务 Hook
  └── 不读取页面闭包，不反向引用页面

基础 UI
  └── 只管理视觉和通用交互，不接触 API / Store / 页面
```

## 4. 任务和轮询

- 页面或业务 Hook 保留轮询循环、状态更新、缓存、Toast 和失败清理等副作用。
- 任务状态字段兼容、终态判断、结果字段读取等无副作用逻辑可以抽成纯函数。
- 轮询必须有终止条件、失败处理、组件卸载清理和重复任务保护。
- 拆分轮询逻辑时必须保持任务 ID、主体 ID、终态集合和结果映射规则不变。

## 5. 防止引用缺失

每次状态或 Hook 拆分都必须执行：

1. 记录原函数读取的变量和 setter；
2. 为每个外部依赖决定 props、Hook 参数、Store 选择器或工具函数参数；
3. 全局搜索原名称和新名称；
4. 检查依赖数组和清理函数；
5. 定向运行 ESLint 与构建；
6. 在真实页面入口验证打开、关闭、保存、失败和刷新恢复路径。

不可用“页面能编译”代替运行时验证；`onDraftContentChange is not defined` 这类错误必须在迁移完成前被扫描和验证路径捕获。
