# 素材范围分页与定稿筛选接口交接

日期：2026-10-22。状态：前端契约核查完成，待后端确认；未实现、未联调，不是已修复待验。

## 目标与范围

面向成千上万分镜的项目，日常按集/场景读取素材，仅搜索和汇总允许跨整个项目。首屏不应以扫完项目全部分镜及候选为前提；不能用截断数量、只筛首批或漏掉历史定稿实现提速。此次不审查或修改自由画布、剪辑业务。

## 已核查证据

| 位置 | 已有能力 | 尚未保证的能力 |
|---|---|---|
| `src/api/openapi.json` 的 `GET /api/assets` | 项目、类型、分类、收藏、主资产、搜索与游标分页；每页最多200 | 没有集/分镜过滤参数；`is_primary`仅描述主资产，不保证与候选定稿等价 |
| 同文档的资产响应 | 资产编号、可扩展元数据、集展示名称 | 没有保证顶层集/分镜稳定编号；展示名称不能替代编号 |
| 同文档的项目分镜列表 | 支持 `episode_id` 及分页 | 没有定稿素材分页或多编号批量查询合同 |
| 同文档的候选列表 | 单分镜候选、`is_finalized`、历史媒体回显 | 无项目级定稿分页；候选没有保证 `asset_id` |
| `docs/backend-storyboard-media-candidates-requirements.md` | 原约定以候选定稿为可信来源，兼容同步分镜媒体字段 | 未约定同步资产主标记；该文档不是后端实现证明 |
| `src/pages/StoryboardPage.jsx` 的 `handleFinalizeToggle` 与 `src/api/storyboard.js` | 前端调用候选定稿更新 | 前端没有额外同步资产主标记；不能据此断言后端没有同步 |

当前仓库及相邻项目目录未提供后端源码。本结论仅指现有契约不足，不代表已验证线上缺少能力。候选接口已列在当前接口文档中，不应将历史交接中的“建议新增”理解为尚未存在。

## 后端需确认或补齐

1. 确定定稿唯一来源。如果复用资产 `is_primary`，需明确它是否与候选定稿等价，以及设置、取消、删除和历史数据回填的一致性保证；否则提供权威定稿查询能力。
2. 支持项目、集/场景、媒体类型/分类、定稿、收藏、搜索的组合过滤，并在分页之前完成筛选。场景范围的稳定编号和归属模型需确认，不由前端猜测。
3. 当前页提供可靠资产、候选、分镜、集的关联标识。明确无资产编号的历史候选如何迁移，以及同一资产被多个分镜引用时按资产还是按候选返回和去重。
4. 返回稳定排序及下一页信息；明确并发新增、删除、切换定稿时分页的一致性和失效规则。不默认承诺快照隔离。错误不能返回成功空列表。
5. 明确跨项目内各集的搜索字段及范围，确保未加载页面的命中也能找到；普通浏览仍限制当前范围。
6. 更新接口合同、提供可用版本与不含隐私的联调样例。优先确认已有能力，再决定扩展现有接口或新增接口，不预设新路径。

## 前端接入顺序

合同确认后，先接当前范围首屏及追加分页，再接定稿/收藏/搜索组合；切换条件重置分页并隔离过期响应，失败保留已读页并允许重试。复核任意 `assetFilter`、空可见页、去重、跨页选择及现有调用方兼容。移除全项目补全必须以完整定稿与历史关联得到保证为前提。

资产库独立分镜入口的首批200条无后页问题（CAP-003）仍单独待修；不能因共享补全已修而标通过。按集/场景入口设计尚待确认，不擅自增加控件。

## 验收条件

| 场景 | 通过条件 |
|---|---|
| 一万分镜起步的模拟项目 | 首屏请求不随项目全部分镜逐个增加；记录实际请求数与响应时间，一万不是产品上限 |
| 定稿出现在后续页、历史候选无资产编号 | 不误报空，不遗漏；没有可靠关联时报告明确错误或迁移状态 |
| 切换/取消定稿、同素材多分镜引用 | 刷新、翻页与筛选后仍符合已确认定稿和去重规则 |
| 搜索/收藏与定稿组合 | 服务端按完整查询范围筛选，未加载页命中可见 |
| 慢网、失败、重试、关闭或切账号 | 加载不显示成功空态；失败可重试；旧请求不覆盖新范围或账号 |
