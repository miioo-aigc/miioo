> 文档状态：产品边界与历史需求；当前状态见10月21日快照
> 更新时间：2026-10-21
> 适用范围：自由画布项目、项目下多画布、节点式工作流

## 2026-10-21 最新对接状态

后端三项补齐说明已明确无风格 canvas 项目、自由节点 Run 映射及分享导入目标项目，不再重复索要。前端已接正式项目新建与原子首张画布、分页列表和重开、独立项目改名，正式新建不再使用模拟项目。已有文档保存/恢复、永久资产解析、多画布及本站分享仍待真实验收。Run 完整页面链路、分享导入目标项目及排序页面尚未接完，不是上述契约缺失造成的全面阻塞。部署迁移、OpenAPI 同步和项目复制关系仍待核对。详见 [当前进度](canvas-integration-status-2026-10-20.md) 与 [剩余交接](canvas-backend-followup-2026-10-20.md)。下文为历史需求和阶段快照，旧阻塞结论以本节为准。

## 一、需求背景

2026-10-19 当前决定：Suzy 再次确认独立项目包含多画布、项目名称与画布名称分离。只接入不依赖缺口且契约完整的独立能力；不以顶层画布树替代项目，不新增本地持久化，不推进存在契约缺口的保存和真实生成联调。

契约核查：本地 OpenAPI 已声明文档读写、版本校验、副本、归档、资产解析和运行接口；2026-10-19 交付另有分享与导入接口，本地 OpenAPI 尚未同步。前端已具备 `nodes/edges/viewport` 文档读写及列表逻辑，不代表与后端 `records/businessBindings` 协议兼容。最新逐项反馈见第十二节。

当前后端的 `canvas-documents` 接口将一个画布文档按“一个项目”使用。前端当前也暂时通过该接口进入已有画布详情，但产品规划要求自由画布采用两级资源模型：一个项目包含多个画布。

2026-10-10：开发环境默认开放首页与画布项目菜单的模拟新建入口，使用 API 层 `CanvasDevelopment.js` 内存适配，不要求登录或真实后端。模拟项目与真实编号隔离，刷新后内容可丢失，原模拟地址重新进入空白画布；不增加持久化。设置 `VITE_CANVAS_DEV_MOCK=false` 可关闭开发模拟并恢复真实列表联调。生成、资产库等能力仍依赖原有真实服务。

2026-10-10：前端已完成并由 Suzy 手动验收四类节点顶部工具栏。文本、图片、视频、音频均支持当前节点的工具栏入口；图片/视频编辑结果在前端按“新增结果节点、保留源节点”展示，更多菜单复用当前节点右键菜单，工具栏和输入框不因画布缩放改变屏幕尺寸。上述是前端交互和结果编排状态，不代表后端已保存编辑任务或画布文档；后端仍需按本清单提供真实任务、资产关系、画布文档及恢复协议。

正式环境仍允许使用已有画布详情作为入口，但不复用普通工作流项目创建接口，也不把 `POST /api/canvas-documents` 当作“新建项目”接口。正式环境“新建项目”继续提示能力建设中，等待后端项目级接口完成后再接入。

2026-10-10：图片、视频节点的“查看详情”及卡片内容双击预览、视频悬停播放已由 Suzy 手动验收通过。预览直接消费当前资产地址，不新增后端接口；卡片隐藏控制条，详情展示播放控制，并在双击打开时接续进度、音量及静音状态。有声自动播放受浏览器权限限制，失败时前端降级静音。这些播放状态仅用于当前页面交互，本轮未增加持久化协议，不代表画布保存恢复或后端资产可用性联调已验收。

## 二、目标资源关系

```text
项目 Project
└── 画布 CanvasDocument（一个项目可有多个）
    ├── 节点 Node
    ├── 连接 Edge
    └── 视口 Viewport
```

- 左上角显示项目名称，不显示当前画布名称。
- 工具栏“画布列表”显示当前项目下的画布，并支持新增、切换和重命名。
- 节点、连接和视口只属于具体画布。
- 项目级权限、分享范围和未来全局 Agent 作用于项目；节点生成仍由用户在节点中主动确认，Agent 不得直接触发扣费生成。

## 三、项目接口需求

建议提供以下接口，具体路径可按后端规范调整，但必须保持项目与画布的资源语义分离：

```http
GET    /api/canvas-projects
POST   /api/canvas-projects
GET    /api/canvas-projects/{project_id}
PATCH  /api/canvas-projects/{project_id}
```

项目响应至少包含：

```json
{
  "id": "project-id",
  "name": "项目名称",
  "revision": 1,
  "created_at": "2026-09-23T00:00:00Z",
  "updated_at": "2026-09-23T00:00:00Z"
}
```

创建项目时，后端应在同一事务中自动创建第一张画布，默认名称为“画布1”。创建请求应支持 `client_request_id`，网络重试不得重复创建项目或初始画布。

## 四、项目下画布接口需求

```http
GET    /api/canvas-projects/{project_id}/canvases
POST   /api/canvas-projects/{project_id}/canvases
GET    /api/canvas-projects/{project_id}/canvases/{canvas_id}
PATCH  /api/canvas-projects/{project_id}/canvases/{canvas_id}
DELETE /api/canvas-projects/{project_id}/canvases/{canvas_id}
```

画布响应至少包含：

```json
{
  "id": "canvas-id",
  "project_id": "project-id",
  "name": "画布1",
  "revision": 1,
  "nodes": [],
  "edges": [],
  "viewport": { "x": 0, "y": 0, "zoom": 1 },
  "created_at": "2026-09-23T00:00:00Z",
  "updated_at": "2026-09-23T00:00:00Z"
}
```

要求：

1. 新增画布只创建当前项目下的画布，不创建新项目。
2. 画布名称与项目名称必须是两个字段，不能共用 `title`。
3. 画布名称由前端限制最多 30 个字符，并禁止特殊符号；后端也必须再次校验。
4. 删除或归档当前画布时，必须明确是否禁止删除项目最后一张画布。
5. 画布列表返回稳定排序字段，默认创建顺序或显式 `sort_order`，不能依赖数据库自然顺序。

## 五、保存与并发要求

项目名称、画布名称和画布文档内容都需要版本控制：

- 请求携带 `base_revision`；
- 成功后返回新的 `revision`；
- 版本冲突返回 HTTP `409`，并返回服务端最新版本或可重新读取的资源地址；
- 保存项目名称不能覆盖画布节点数据；
- 保存画布节点不能覆盖项目名称或其他画布；
- 保存请求建议支持幂等键，避免网络重试产生重复版本。

## 六、节点文档最小要求

节点和连接暂可作为画布文档的一部分保存，但字段必须能稳定映射到 React Flow 之外的业务模型：

```json
{
  "schema_version": 1,
  "nodes": [],
  "edges": [],
  "viewport": { "x": 0, "y": 0, "zoom": 1 }
}
```

节点至少需要稳定的业务 `id`、`type`、`position`、`data`；连接至少需要 `id`、`source`、`target`，以及必要时的端口字段。不能只保存 React Flow 内部临时对象作为长期协议。

## 七、资产选择与绑定

本轮前端会尽量复用现有资产库查询和选择弹窗，但后端需确认：

- 自由画布资产是否按 `project_id` 隔离；
- 是否允许选择项目外的用户资产；
- 节点保存 `asset_id`、资产引用快照，还是两者同时保存；
- 原资产删除、归档或权限失效后节点如何展示；
- 图片、视频、音频是否统一使用 `asset_type`；
- 资产选择是否需要记录使用关系，避免资产删除后无法追溯。

## 八、分享与导出

后续需要确认：

- 分享范围是整个项目还是单张画布；
- 分享链接是只读还是可编辑；
- 是否支持过期时间、撤销和权限校验；
- “导出节点”是当前选中节点还是当前画布全部节点；
- 导出是否包含节点参数、端口连接、资产 ID、视口和 schema 版本；
- 导入时是否重新生成节点 ID，并校验资产访问权限。

## 九、本轮前端暂缓项

- 不调用普通工作流项目创建接口。
- 不调用 `POST /api/canvas-documents` 作为新建自由画布项目的替代。
- 不把当前画布的 `title` 当作最终项目名称。
- 不宣称项目创建、多画布持久化、项目名称保存和分享导出已经完成。
- 允许使用已有画布详情作为工具栏、React Flow 和节点交互的开发入口。

## 十、后端就绪后的联调范围（2026-10-12，按第十二节分项恢复）

前端当前可作为联调入口的节点能力如下：

| 节点 | 已验收的前端入口 | 后端需要确认的闭环 |
| --- | --- | --- |
| 文本 | 编辑内容、复制内容、下载内容、更多 | 文本生成请求的输入快照、幂等、任务状态、结果写回及刷新恢复 |
| 图片 | 裁剪、翻转、多机位、局部重绘、智能超清、消除笔、扩图、下载、更多 | 源图片资产编号、编辑模式/模型、蒙版或扩图参数、业务归属、新图片资产关系及任务恢复 |
| 视频 | 智能超清、去字幕、选帧、剪辑、下载、更多 | 源视频资产编号、分辨率/区域/时间参数、视频或图片输出类型、业务归属、音轨和任务恢复 |
| 音频 | 下载、更多 | 音频资产地址和下载权限；若后续接入音频处理，还需补充模式、任务和结果资产契约 |

后端联调必须区分以下状态：前端点击已受理、任务处理中、任务成功且资产已落库、任务失败、任务取消。只有返回新资产编号及业务归属并完成关系写入后，前端才能把编辑结果标记为真实保存成功。结果应保留 `source_asset_id` 与编辑模式，源节点/源资产不得被覆盖。

当前阻塞是完整产品契约与可用性尚未对齐，而非所有接口路径缺失。前端已有工具栏和结果节点不能替代后端闭环，也不应通过浏览器本地存储伪造正式保存能力。

## 十一、后端缺口与恢复开发条件（2026-10-12）

以下区分“文档未声明”“已有声明但协议不完整”“已有声明待验证”，不把未验证直接判定为后端未实现。接口路径可由后端调整，资源语义不得降级。

| 范围 | 当前证据与缺口 | 后端需要交付或确认 |
| --- | --- | --- |
| 项目与多画布 | 有 `project_id` 归属与筛选；未找到本清单要求的专属画布项目契约 | 项目列表、创建、详情、重命名；原子创建首张画布；项目内新增、切换、排序、重命名与删除规则；项目复制/删除的明确语义 |
| 文档结构 | `document` 仅声明任意对象，未定义内部节点及连接结构 | 版本化结构与完整可运行样例，覆盖四类节点、参数、资产引用、端口、分组、堆叠和视口；明确与运行输入解析的映射 |
| 版本与幂等 | 已有 `base_revision`，创建画布、副本及运行有幂等键；更新未声明保存幂等键，409 错误结构未明确 | 冲突响应样例、保存重试语义、并发保护及未保存内容保留方案；不能因网络重试重复创建或执行 |
| 素材持久化 | 已有批量资产解析及缺失/无权限编号返回，前端未接入 | 明确本地上传如何取得永久资产编号、项目归属、跨项目引用权限及失效展示；文档不能依赖临时媒体地址 |
| 生成与恢复 | 运行接口明确支持图片/视频/音频，提供输入快照、结果资产和对账字段；文本不在声明范围内 | 补齐或明确文本任务方案；提供状态枚举、失败/取消/重试、刷新恢复、运行列表超过上限时的恢复策略和结果幂等回填样例 |
| 媒体编辑 | 前端已有编辑入口，不能据此确认画布任务归属与恢复 | 按第十节逐项确认源资产、结果资产、宿主画布/节点、编辑模式与刷新恢复协议 |

恢复顺序：按第十二节和最新交接反馈逐操作判定；契约完整的独立能力可推进页面接线和验证，不限于接口层准备。前端先核查无损映射，仅无法承载的字段和未定义行为交后端补齐。不得仅因更新 OpenAPI 就标记产品闭环完成。
