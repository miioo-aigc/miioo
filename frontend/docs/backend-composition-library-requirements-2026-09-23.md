# 剪辑草稿素材区持久化：后端需求与联调事项

登记日期：2026-09-23  
状态：待后端确认契约 / 待实现 / 待前端对接。本文是需求记录，不代表已上线。

## 1. 问题与交互边界

用户上传或从资产库选择的素材，仅进入左侧素材区；用户明确点击素材卡片后才加入时间线。保存草稿必须同时保存素材区内容，包括未使用的素材，关闭、刷新及跨设备重新打开同一草稿时能够恢复。不能通过自动插入时间线、伪造时间线片段或浏览器本地缓存替代正式持久化。

当前前端上传/选择只更新页面 album 和编辑器 Store。保存只提交 name、timeline、resolution、aspect_ratio。已检查的 OpenAPI CompositionCreate/Update/Response 没有独立素材列表字段；未加入时间线的素材无法随草稿恢复。此前对时间线补取和页面筛选的修改没有解决此问题。

## 2. 建议接口契约（字段名待后端确认）

新增有序数组 `library_asset_ids: string[]`，元素为真实资产 UUID，而不是分镜候选、创作记录或文件 ID。记录用户手动添加的素材；分镜定稿素材仍可按当前业务规则动态加载，不必把项目全部资产写入草稿。

涉及接口：

- `POST /api/projects/{project_id}/compositions`：创建时可提交素材列表，省略默认空数组。
- `PATCH /api/projects/{project_id}/compositions/{composition_id}`：更新素材列表。
- `GET /api/projects/{project_id}/compositions`：每个草稿返回素材列表；如另有单草稿读取接口，同样返回。
- 创建及更新成功响应：返回实际持久化后的素材列表。

示例（ID 为说明用占位符，实际传 UUID）：

```json
{
  "name": "草稿01",
  "timeline": [],
  "library_asset_ids": ["asset-uuid-new", "asset-uuid-old"],
  "resolution": "1080p",
  "aspect_ratio": "16:9"
}
```

PATCH 语义：未传字段表示保持不变，`[]` 表示清空素材区手动引用列表，非空数组表示替换；建议拒绝 null，避免清空语义歧义。按首次出现顺序去重，保留前端“新素材置顶”的顺序。素材列表与时间线等同次提交字段应原子保存，失败不能部分更新。旧草稿读取默认 `[]`，兼容旧客户端不传此字段的更新。

## 3. 数据与权限要求

- 素材列表按草稿隔离，同一项目的不同草稿互不串数据。
- 复制草稿时复制素材 ID 列表及顺序，不要求复制底层媒体文件；前端通过创建接口复制时需能提交此字段。
- 校验项目/草稿访问权限和资产访问权限；跨项目资产及创作资产是否允许引用、是否需要导入，请后端明确规则和接口，不能由前端假设。
- 允许时间线为空但素材列表非空；素材区引用不得触发渲染或影响成片时长。
- 删除草稿或移除素材区引用不能连带删除共享资产。时间线引用与素材区引用独立处理。
- 素材保存后被删除或权限变化时，读取草稿不能整体失败。保留引用并提供可识别的不可用状态，前端以占位/提示展示，不返回无权限媒体地址。
- 新增无权限或不存在的引用需返回结构化错误；已存在但后来失效的引用应允许用户打开、移除和保存其他内容。具体错误码和失效引用处理策略需在契约中明确。
- 提供或确认按 ID 获取媒体详情的能力：真实 ID、类型、名称、源地址、封面/缩略图、时长（秒）。可选增加有权限校验的批量读取以减少请求，不要求重新全量读取项目素材。
- 更新数据库迁移及 OpenAPI（创建、更新、读取响应），明确数组长度限制。

## 4. 前端待对接工作

- `src/api/compositions.js`：规范化保留字段、创建/更新请求透传字段。
- `src/stores/compositionEditorStore.js`：维护独立素材 ID 列表；添加/移除/排序标记 dirty；保存与初始化对接，不修改时间线。
- `src/pages/CompositionEditorPage.jsx`：按素材列表 ID 和 timeline.clip_id 的并集去重补取详情；保留手动列表顺序，与定稿素材合并展示。
- `src/components/compositionEditor/AssetLibraryPanel.jsx`：上传/选择只更新素材列表；占位结束后标记未保存，用户点击才加入时间线。
- 草稿复制入口：透传素材列表。保存失败不能显示“已保存”，重开时单条失效素材不能阻塞列表。

## 5. 独立待排查：视频加入时间线后保存失败

用户实际看到提示：“时间线中存在不可用的视频素材，请先生成、上传或重新选择素材”。尚未确认后端拒绝的具体引用及原因，不得将此问题视作新增 library_asset_ids 后自动解决。

联调需核对上传返回 asset_id、资产详情 ID、提交 timeline.clip_id 三者；后端明确时间线是否支持普通资产、创作资产、跨项目资产及对应类型/状态/文件可用性约束。返回能定位失败片段的错误信息，不泄露无权限资源详情。用本地上传视频及资产库选择视频分别验证保存、重开、预览和导出。

已确认的另一项历史上传错误：视频上传传 category=storyboard 返回 422，响应为“参考视频上传 category 仅支持 reference”。前端已改传 reference 并检查 HTTP 错误；这是已修正的参数错误，不是需要新增上传接口。

## 6. 验收清单

- [ ] 空草稿上传视频，不加入时间线，保存后关闭重开：素材仍在，时间线仍为空。
- [ ] 从资产库批量选择素材，保存重开：数量、顺序正确，无重复。
- [ ] 上传/选择不自动播放或插入时间线，新增状态显示未保存。
- [ ] 新素材置顶；素材区资源与时间线资源不同集合时均可保存恢复。
- [ ] 旧客户端省略字段不清空列表；显式空数组清空列表但不删除资产或时间线。
- [ ] 复制草稿保留素材列表；不同草稿/用户之间不串素材。
- [ ] 刷新、重新登录及另一设备打开同一草稿可恢复。
- [ ] 单个失效引用可识别、可移除，不阻塞读取；无权限引用不得泄露媒体地址。
- [ ] 保存失败不丢原有数据、不显示成功；草稿其余字段与素材列表原子更新。
- [ ] 用户主动加入时间线后，本地上传与资产库视频均可保存、重开、预览、导出（独立问题验收）。
