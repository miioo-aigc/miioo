# 剪辑模块后端交接文档

> 文档类型：剪辑模块前后端联调与后端补齐清单  
> 审查日期：2026-10-09  
> 适用范围：`CompositionEditorPage`、`compositionEditor` 组件、`compositionEditorStore`、`src/api/compositions.js`

## 1. 结论摘要

审查边界：本次检查前端源代码、本地 OpenAPI 和历史联调记录，未检查后端实现、未调用生产接口或执行真实渲染。下文“需补齐”包含已确认前端协议缺口和待验证服务端能力，不能据此断言后端完全没有实现。`has_audio`、轨道设置、素材列表等新增字段均为建议，需双方确认后再接入。

前端剪辑工作台已经具备较完整的编辑交互：素材添加、重复添加、视频/图片/音频/字幕片段、多轨、跨轨拖拽、吸附、切割、左右裁剪、倍速、音量调整、字幕样式和成片导出入口。

当前前端接口适配仅覆盖“成片工程基础草稿 + 提交渲染”的最小路径。以下能力仍不能视为已完成前后端闭环：

1. 字幕时间线条目和字幕烧录渲染。
2. 单片段音量、轨道音量/静音及视频原声关闭的持久化和最终渲染。
3. 分离音频的真实音频流渲染。
4. 多视频、音频、字幕轨道的独立排布与最终合成。
5. `speed`、`offset`、`transition` 等时间线参数在最终渲染中的实际生效。
6. 左侧素材区中“已添加但未上轨”的素材列表持久化。
7. 草稿复制时的完整时间线、素材区引用和相关状态继承。

现有前端会把这些字段放入时间线或本地 Store，但 OpenAPI 对时间线条目仍是无结构 `items: {}`，没有足够契约约束；此前真实保存字幕时已出现“时间线第 11 项类型不支持”，需要优先处理。

## 3. 前端实际发送的时间线协议

前端 `serializeTimeline()` 当前按照片段类型输出以下字段：

### 3.1 视频片段

```json
{
  "type": "video",
  "clip_id": "asset-uuid",
  "start": 0,
  "duration": 4.2,
  "offset": 1.5,
  "track": "V1",
  "speed": 1.25
}
```

后端需要：

- 校验 `clip_id` 属于当前用户可访问资产，并且是可用视频媒体。
- 按 `offset` 从源视频取源窗口。
- 按 `speed` 改变播放速度，同时保持前端提交的时间线 `duration` 语义一致。
- 按 `start` 和 `track` 放置片段，不要仅按数组顺序重排。
- 支持源视频不存在音频流的情况。
- 支持视频片段关闭原声，见第 5 节 `has_audio` 缺口。

### 3.2 图片片段

```json
{
  "type": "image",
  "clip_id": "asset-uuid",
  "start": 5.5,
  "duration": 3,
  "offset": 0,
  "track": "V1",
  "transition": "fade"
}
```

后端需要：

- 按 `duration` 输出静帧视频片段。
- 支持 `transition: "fade" | "none"`，默认值为 `fade`。
- 不能把图片当成视频处理，也不能忽略图片片段导致时间线缩短。

### 3.3 音频片段（含建议新增的 volume）

```json
{
  "type": "audio",
  "clip_id": "asset-uuid",
  "start": 0,
  "duration": 6,
  "offset": 0,
  "track": "A1",
  "speed": 1,
  "volume": 1.5
}
```

当前前端实际序列化函数还没有把 `volume` 写入请求，这属于前端待补字段和后端待接能力，不能只在后端猜测。后端方案确定后，前端需要同步把 `volume` 写入时间线。

后端需要：

- 支持 A1 至 A6 的独立音频轨。
- 尊重显式 `start`，关闭吸附时允许轨道留空。
- 按 `offset`、`duration`、`speed` 截取和变速。
- 支持 0–2.0 的片段音量增益。
- 支持分离视频音频的同一资产引用，见第 5 节。

### 3.4 字幕片段

```json
{
  "type": "subtitle",
  "start": 0,
  "duration": 2.4,
  "offset": 0,
  "track": "S1",
  "text": "字幕内容",
  "style": {
    "fontFamily": "Alibaba PuHuiTi 2.0",
    "fontSize": 42,
    "color": "#FFFFFF",
    "textOpacity": 100,
    "align": "center",
    "x": 50,
    "y": 86,
    "outlineOn": false,
    "outline": 2,
    "outlineColor": "#000000",
    "outlineOpacity": 100,
    "backgroundOn": false,
    "background": "#000000",
    "backgroundOpacity": 60
  }
}
```

字幕没有 `clip_id`。后端目前曾将其判定为不支持的时间线类型，必须明确支持或单独设计字幕轨道协议。建议支持上述结构，并在 OpenAPI 中把 style 定义为明确 schema，而不是任意对象。

上述样式为示例，不是默认值。实际默认字体为 `sans-serif`、字号 48、位置 (50,90)、描边宽度 0、背景关闭，三种不透明度均为 100。坐标单位为画面百分比，(x,y) 是文本框中心；对齐只影响框内文字，不改变锚点。字号和描边按画面高度 / 1080 缩放，行高 1.3，文本最大宽度为画面 90%，保留换行。`outlineOn` 缺省时按描边宽度判断，显式 false 才强制关闭。需约定输出画面而非整个预览容器作为统一坐标系。

SRT/ASS 当前由浏览器解析，不需要后端另建上传解析接口。单文件上限 5MB、单次 5000 条；支持 UTF-8 和 GB18030 回退。ASS 只转换基础样式，行内覆盖、动画、绘图、颜色原透明度、粗斜体、旋转和阴影等有降级提示，不能要求后端还原前端已丢弃的数据。OpenAPI 已有工程级 `subtitle_style`，但前端适配未读写；需明确它与逐片段 `style` 的优先级，不能直接视为已支持本方案。

后端需要：

- 支持 S1 至 S6 的独立字幕轨。
- 按 `start`、`duration` 放置字幕，不改变字幕在时间线中的位置。
- 支持文字、字号、字体、文字颜色和不透明度。
- 支持文字对齐、水平/垂直位置。
- 支持可关闭的文字描边、描边宽度、描边颜色和不透明度。
- 支持可关闭的字幕背景、背景颜色和不透明度。
- 明确字体白名单、字体文件部署方式和找不到字体时的回退规则。
- 在最终视频中完成字幕烧录，而不仅是在草稿中保存文本。

## 4. 优先级 P0：必须补齐的后端能力

### P0-1 时间线协议正式化

当前 OpenAPI 的 `timeline.items` 为空 schema，导致前后端无法共同校验字段，且后端已经拒绝字幕项。建议：

- 增加 `TimelineItem` 的 `oneOf`：Video、Image、Audio、Subtitle。
- 明确字段类型、范围、必填项、默认值和未知字段处理方式。
- 明确 `start` 是最终时间线位置，单位为秒，允许小数，最小值为 0。
- 明确 `duration` 是时间线时长，不是源素材时长。
- 明确 `offset` 是源媒体入点，图片固定为 0。
- 明确 `track` 允许 `V1-V6`、`A1-A6`、`S1-S6`，并校验类型和轨道前缀一致。
- 明确空时间线、同轨空隙、同轨重叠、跨轨重叠的服务端处理策略。
- 错误返回必须定位到 `timeline[index]`，同时返回字段和原因，例如 `timeline[10].type` 不支持。

### P0-2 多轨合成与渲染

渲染任务必须真正识别 `track`，不能把所有片段按数组顺序拼成单轨：

- 视频轨：当前预览按编号从高到低挑选一个活跃、未隐藏的片段，只显示该画面及其原声，不是同时渲染所有视频图层。后端需要确认采用相同遮挡规则，还是升级为真正图层叠加；后者需前端同步改造，不能单方实现。主轨选择仅影响编辑落点，不等于画面层级。
- 音频轨：A1-A6 混音，按照各片段 `start`、`duration`、`volume` 合成。
- 字幕轨：S1-S6 按时间叠加；同一时刻多条字幕的层级规则需要明确。
- 没有视频轨但有音频/字幕时，是否允许导出需要明确；建议至少要求存在一个视觉输出轨，或返回结构化校验错误。
- 每条轨道的空隙必须按真实时间保留，不能因后端重新串行化而消失。
- 工程时长当前为所有 V/A/S 片段 end 的最大值；只有音频/字幕的工程、视觉末尾之后的黑场和静音策略待确认，不能直接按视频时长截断。图片 fade 当前预览时长为 min(0.4秒, 片段时长/2)，不代表已约定相邻片段交叉溶解。视频采用 contain 显示，输出画幅、补边和帧率需一并约定。

### P0-3 字幕保存、回读与烧录

必须先解决真实保存失败，再进行 ASS/SRT 导入后的端到端验收：

- 创建、更新、列表回读原样保留字幕项。
- 字幕样式字段不能被后端丢弃或转成不可逆格式。
- 渲染任务支持至少一种稳定字体回退。
- 字幕越界、重叠和非法颜色等错误应在保存或渲染提交前返回明确字段错误。
- 需要至少验收普通手动字幕、SRT 导入字幕、ASS 导入字幕、同轨多条字幕、S1-S6 多轨字幕。

### P0-4 片段参数在最终成片中生效

以下参数不能只在浏览器预览生效：

- 视频/音频 `offset`。
- 视频/音频 `speed`。
- 图片 `transition`。
- 音频片段 `volume`。
- 视频原声开关。
- 轨道静音/音量。

每个参数都要有保存回读和最终导出的验收，不接受仅返回 200 但成片忽略参数。

## 5. P0：分离音频协议

当前前端“分离音频”不会创建新的后端资产，而是在时间线上：

1. 将视频片段的 `hasAudio` 置为 `false`。
2. 新增一个 `type: "audio"` 的片段。
3. 音频片段复用原视频的 `clip_id`、`offset`、`duration`、`speed`，并设置 A1 的显式 `start`。

但 `hasAudio` 当前没有被 `serializeTimeline()` 写入，刷新后视频原声关闭状态会丢失。建议后端契约采用：

```json
{
  "type": "video",
  "clip_id": "video-asset-uuid",
  "start": 0,
  "duration": 5,
  "offset": 0,
  "track": "V1",
  "speed": 1,
  "has_audio": false
}
```

后端渲染时：

- `has_audio: false` 的视频只输出画面。
- `type: audio` 且 `clip_id` 指向视频资产时，从该视频的音频流取音频，而不是要求资产类型必须是 audio。
- 视频无音频流时，分离出来的音频应返回可理解的渲染错误或在前端禁止该动作。
- 同一个视频可以存在多个音频引用时，按时间线条目分别处理，不要用 asset_id 全局去重。

## 6. P1：草稿素材区独立持久化

左侧素材区和时间线是两个集合。用户可以把素材加入素材区但不加入时间线，也允许同一素材多次加入时间线。当前只有 `timeline` 会保存，因此刷新后未上轨素材会丢失。

建议在 Composition Create/Update/Response 增加：

```json
{
  "library_asset_ids": ["asset-uuid-1", "asset-uuid-2"]
}
```

要求：

- 有序、去重、草稿隔离。
- `[]` 表示明确清空，省略表示 PATCH 保持不变。
- 素材区引用不能因为移出素材区而删除共享资产。
- 失效资产不能阻塞整个草稿读取，应返回可识别的 unavailable 状态。
- 复制草稿时复制该列表及顺序。
- 与 `timeline` 同次保存时原子更新。
- 定稿素材由页面动态加载，单有手动 `library_asset_ids` 无法记住用户移除的定稿素材。需增加草稿级排除列表（例如 `excluded_asset_ids`，建议名），或改为完整素材快照；重新添加应取消排除。当前删除仅移除本工程素材区及所有关联片段，不调用共享资产删除接口。

详细背景已记录在 [`backend-composition-library-requirements-2026-09-23.md`](./backend-composition-library-requirements-2026-09-23.md)。

## 7. P1：属性、轨道和会话状态的持久化边界

当前以下状态只存在编辑器 Store，刷新或换设备会丢失：

| 状态 | 当前行为 | 建议 |
|---|---|---|
| 单片段音量 | 预览实时生效，当前未写入 timeline | 确认 `volume: 0-2` 是否进入片段协议 |
| 视频原声关闭 | `hasAudio` 在本地存在，当前未序列化 | 增加 `has_audio` |
| 轨道隐藏 | 仅当前会话 | 若导出应生效，增加轨道设置协议；否则明确仅预览 |
| 轨道静音/音量 | 仅当前会话 | 建议轨道级 `muted` / `volume` |
| 吸附开关 | 仅编辑行为，不影响成片 | 可不持久化，除非需要恢复编辑偏好 |
| 主轨道 | 新建字幕时影响落点，当前仅会话 | 建议第一版不进入渲染协议；如需跨设备恢复再持久化 |
| 时间线缩放 | 仅 UI 状态 | 无需后端 |
| 播放游标 | 仅 UI 状态 | 无需后端 |
| 选中片段/撤销栈 | 仅 UI 状态 | 无需后端 |

建议后端先只承担影响保存和导出的业务字段，避免把游标、缩放、撤销栈等编辑器状态混入成片协议。

## 8. P1：资产可用性与保存错误

前端打开草稿时会按 `timeline.clip_id` 补取缺失资产。当前真实使用中出现过“时间线中存在不可用的视频素材，请先生成、上传或重新选择素材”的错误，后端需要提供可定位的原因：

- 上传返回的 `asset_id` 是否就是时间线允许的 `clip_id`。
- 普通资产、创作资产、分镜定稿资产是否都允许加入时间线。
- 跨项目资产是否允许引用。
- 资产未完成、已删除、无权限、缺少媒体地址时分别返回什么错误码。
- 保存失败时指出具体 `timeline[index].clip_id`，不能只返回笼统错误。
- 成功保存的草稿重新打开时，资产元数据至少包含 `id`、`asset_type`、媒体地址、缩略图和 `duration`。

## 9. P1：任务和导出结果契约

前端导出流程：保存草稿 -> `render` -> 读取返回的 `task_id` -> 轮询 `/api/tasks/{task_id}` -> 读取 `results[0].asset_id` 或 `output_url` -> 下载。

后端需确认：

- `render` 是否总是返回 `task_id`，还是可能同步完成。
- 任务状态枚举：前端识别 `completed / success / done / partial` 为成功，`failed / cancelled / expired / error` 为失败；建议固定枚举并写入 OpenAPI。
- `progress` 是 0-100 数值还是 0-1 小数。
- 失败信息统一放在 `error_msg`，并保留 `results[].success/error` 兼容字段或统一一种结构。
- 成功结果是否一定创建资产；若只返回 `output_url`，URL 的鉴权、有效期和下载方式需明确。
- 任务是否支持关闭弹窗后继续，是否支持重复提交幂等键。
- 同一工程并发 render 时如何处理，建议返回冲突错误或复用已有任务。
- `partial` 是否代表可下载成片；不能让前端把部分失败误判为完整成功。

## 10. P2：剪映格式导出边界

产品规则是：用户在开始选择时决定“在线剪辑”或“导出剪映格式”；一旦进入在线剪辑，不再导出剪映格式。现有 `export-jianying` 接口属于进入在线剪辑前的独立流程，后端无需把在线编辑后的字幕、轨道和样式强行转换成剪映工程，除非产品后续重新开放该能力。

需要后端确认的仅是在线剪辑入口前的既有契约：

- 允许导出的分镜/资产 ID 范围。
- 重复 ID 去重规则。
- 空列表、失效 ID、无权限 ID 的错误返回。
- 导出包中的媒体下载权限和中文文件名。

## 11. 建议接口演进顺序

1. **第一阶段：协议可保存**：正式定义四类时间线条目，先让视频、图片、音频、字幕都能创建、更新、读取；补充字段错误定位。
2. **第二阶段：协议可渲染**：实现多轨、起始时间、源入点、时长、倍速、图片转场和字幕烧录。
3. **第三阶段：声音能力**：接入片段音量、视频原声关闭、轨道静音/音量、分离音频。
4. **第四阶段：草稿完整恢复**：增加 `library_asset_ids`，补齐失效资产、复制草稿和跨设备恢复。
5. **第五阶段：任务稳定性**：统一任务状态、进度、错误、幂等和结果下载契约。
6. **第六阶段：OpenAPI 与联调验收**：将所有字段、枚举、错误码和示例写回 `openapi.json`，完成前后端自动化契约测试。

## 13. 前端后续配合项

### 13.1 已确认的前端缺口（不得全部交给后端）

| 证据入口 | 发现及风险 | 前端动作 |
|---|---|---|
| `compositionEditorStore.js:134` serializeTimeline、`:575` init | 不提交/恢复 volume、hasAudio；后端即使保存也不能闭环 | 同步序列化、恢复、默认值及往返测试 |
| `compositionEditorStore.js:734` commitAudioVolume | 音量提交仅写撤销栈，不置 dirty | 协议就绪后接入 dirtyRev 和自动保存 |
| `compositionEditorStore.js:400` setMainTrack、`:516` setTrackSetting | 主轨、隐藏、静音不完整触发持久化 | 按确认后的业务/会话边界补 dirty 与保存 |
| `compositionEditorStore.js:1032` closeExport、`:958` poll | 关闭将 status 置 idle，后续 poll 直接返回；并无任务恢复逻辑 | 分离弹窗可见性与任务状态，重开从 task_id 恢复 |
| `compositionEditorStore.js:966` 任务成功分支 | partial 直接当成功，未要求有效输出；只读 results[0] | 校验结果成功与可下载文件，处理部分失败 |

音频分离、音量和轨道设置的保存往返测试应优先补充。当前 init 为片段重新生成本地 ID，后端若需要稳定实例 ID，建议另设 segment_id，不能把 clip_id 当实例 ID；该字段也需前端迁移。

### 13.2 保存一致性与版本建议

- 最近保存时间使用服务端 `updated_at`；需确认任务进度/渲染完成是否也会更新它。若会，新增独立 `saved_at`，避免列表把导出时间当编辑保存时间。
- 当前 dirtyRev 只是前端判断保存期间是否有新修改，不是服务端版本。建议增加 revision / expected_revision 与冲突响应，避免多窗口覆盖；渲染绑定已保存快照或 revision，不能在后台运行时读取不断变化的草稿。
- 草稿名称编辑器限制 60 字符；服务端统一校验并明确 Unicode 计数方式，复制“副本”后也要满足限制。
- 媒体地址需支持浏览器 CORS、Range 和有效期刷新；Web Audio 增益、视频截帧都依赖可访问的真实媒体，元数据缺失时当前前端会以 3 秒回退，不能替代服务端探测源时长。
