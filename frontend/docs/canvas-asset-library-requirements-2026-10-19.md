# 画布资产库需求与接口契约草案

> 日期：2026-10-19
> 状态：左右结构与资产集合模型已完成前端改造；2026-10-21 确认仅取消资产库本地上传，其他操作保持不变；正式接口仍待后端联调。
> 范围：资产库新增画布资产入口，以及画布媒体资产的入库、整理、引用和删除联动。
> 阅读约定：“已确认”代表产品决策；“建议”代表实现提案，不代表现有接口能力或用户已逐项确认。

## 一、目标与边界

### 1.1 真正要解决的问题

让用户在项目内部像整理电脑文件一样整理画布媒体，同时保留项目自动归档能力。集合内部可以真正移动，跨集合只允许添加引用；整理位置变化不应破坏画布，删除原生资产则应准确影响所有使用它的画布。

支持自由整理的最强理由，是实际创作素材经常跨项目复用；反对无限自由的最强理由，是跨项目移动原件和多处收录后用户容易误判删除影响。本方案限制真正移动在同一集合内，跨集合通过引用复用，通过原生归属、删除预检与二次确认管理风险，不以引用角标增加日常视觉负担。

### 1.2 本期范围

- 图片、视频、音频等重资产；不管理文本节点正文或文本文件。
- 左侧资产集合列表、右侧集合内部目录、多层子文件夹、素材收录；不允许自由新增项目级普通文件夹。
- 集合改名、独立复制、递归打包下载、删除；历史集合保留访问入口。
- 添加已有素材引用、重命名、移动、拖拽、删除、批量操作；画布资产库不提供本地上传。
- 新上传、成功生成及编辑结果自动归档；与画布节点的可用性联动。
- 仅覆盖功能上线后的新数据，不迁移或补录开发阶段历史素材。

### 1.3 明确不做

- 本期不提供回收站、恢复入口、保留期限设置或永久删除入口；删除后存储由后端处理，不向用户承诺可恢复。
- 本期确认集合级递归打包下载；普通子文件夹单独打包未确认，不据此扩展。下载不做名称唯一性校验，重名不能导致覆盖或漏文件，归档路径冲突由后端评审安全编码方案。
- 不改变其他资产库的目录模型，不默认支持跨库移动原生素材。
- 本文不代表画布项目、保存协议和资产权限等既有依赖已经完成。

## 二、入口与页面交互

### 2.1 顶部入口

标签顺序为「项目资产 → 创作资产 → 画布资产 → seedance素材库」。采用与项目资产一致的左右结构：左侧显示资产集合列表，右侧显示所选集合内部的文件夹与根目录素材，不再套一层同名项目文件夹卡片。

左侧包括关联现存画布项目的集合、项目删除后保留的历史集合、复制生成的独立集合。没有自由新增项目级集合或顶层文件夹的入口；复制是允许产生独立集合的操作，不代表允许空白新建集合。

再次进入画布资产时，优先恢复上次选中的集合。首次进入或上次集合已删除、无权访问时，自动选中列表中的第一个可用集合。左侧所有类型的集合统一按创建时间倒序排列，新集合在前；重命名、整理素材不改变集合创建时间及排序依据。

集合列表成功加载且没有任何集合时，仅在右侧内容区显示空状态图标及文案“暂无画布资产，请先创建画布项目”，不提供按钮。图标与文案作为整体，在右侧内容区内水平、垂直居中；页面宽高变化时仍保持内容区居中，不使用相对整页定位或固定偏移。此状态不等同于已有集合内的空目录，也不能用于掩盖加载失败；加载失败仍展示错误提示及文字“重试”按钮。

集合选择仅在当前浏览器本地持久化，按登录账号隔离，不跨设备同步，不新增后端用户偏好接口。本地记录仅用于恢复选择，不作为访问权限依据；恢复时仍须校验集合可访问性。本地记录不存在或被清除时，按首次进入规则处理。

选中集合后，右侧提供新增文件夹卡片及批量操作；各级目录均可新增子目录。新增卡片、文件夹卡片和网格复用现有组件与自适应规则。引用与原生素材外观一致，不增加引用角标、徽标或其他可辨识标记。

左侧集合菜单提供重命名、复制、下载、删除。关联项目集合改名与画布项目名双向同步；历史及复制集合只改自身名称。复制只创建独立资产集合，不复制画布项目；下载为递归打包；删除须预检和二次确认，删除集合及内容并移除左侧入口，不删除画布项目。不另设“清空项目资产”入口。

### 2.2 文件夹内部

- 子文件夹在前、媒体素材在后，同屏网格展示；分页也必须保持这一整体顺序。
- 支持多层目录。建议使用面包屑返回任意祖先目录，进入目录后清除上一目录的选择状态。
- 提供新增文件夹、添加已有素材、批量操作，以及条目菜单；不提供本地上传入口。
- 点击文件夹进入；点击素材沿用对应媒体预览能力，视频、音频可播放。
- 普通目录和素材可重命名；集合根目录不作为卡片展示，集合改名通过左侧菜单执行，关联项目时由服务端同步项目名称。
- 建议编辑名称时校验非空及长度，不校验重名；长度上限由后端统一给出。

### 2.3 添加与移动的区别

| 操作 | 实际结果 | 原位置 | 是否新增素材本体 |
| --- | --- | --- | --- |
| 画布资产库本地上传 | 不提供此操作 | 不适用 | 不适用 |
| 添加已有素材 | 当前目录新增收录引用 | 保留 | 否 |
| 集合内移动原生条目 | 更改原生所在目录 | 不保留原生条目 | 否 |
| 集合内移动引用条目 | 仅改变该引用所在目录 | 不保留该引用条目 | 否 |
| 拖拽条目到文件夹 | 默认执行上述移动，不隐式添加引用 | 同移动规则 | 否 |

“添加”允许从项目资产、创作资产、画布资产、seedance素材库选择当前用户有权限且可用的媒体，不提供本地上传选项。跨库选择须有正式身份映射，不能拿媒体地址当唯一编号。

建议拖动至合法文件夹时高亮目标；非法目标不高亮并禁止提交。触屏和无法拖拽时可通过“移动到”完成等价操作。不得移动集合根目录，不得将目录移动到自身或任一后代；目标目录内同名不影响移动。文件夹、原生条目和引用条目均禁止跨集合真正移动，包括历史集合及复制集合；跨集合复用素材只能添加引用，不递归引用整个文件夹，也不将跨集合拖拽暗中转换为引用。

### 2.4 批量操作

| 操作 | 支持对象 | 限制 |
| --- | --- | --- |
| 移动 | 素材条目、普通目录 | 仅限集合内；根目录不可移动；仍须检查循环 |
| 添加引用 | 已有媒体素材 | 不递归引用整个文件夹 |
| 下载 | 媒体素材 | 右侧普通子文件夹打包未确认；左侧集合打包见第3.4节 |
| 删除 | 素材条目、各类目录 | 先预检再确认，区分原生与引用 |

建议混选不支持的对象时禁用对应动作并说明原因，不静默忽略部分选中项。列表未加载部分不能被前端误当作完整目录，也不能用当前页推算删除影响。

右侧项目根目录及子目录始终提供批量操作入口。“全选”覆盖当前目录下全部直接条目，包括未加载条目，不直接展开后代选择；删除所选文件夹时递归处理。取消全选、切换集合或目录须清理旧选择。全选应由后端生成有范围版本的选择快照，不能依赖前端已加载编号；范围变化时重新确认，不悄悄扩大删除范围。

## 三、项目与目录生命周期

### 3.1 自动项目目录

- 一个独立画布项目可包含多张画布；自动目录对应项目，不对应单张画布。
- 创建项目时自动创建同名目录，首次预建「角色、场景、道具、分镜、音频」五个分类。
- 项目改名与关联资产集合名双向同步；通过服务端统一事务或可靠一致性机制处理，前端不得分别改两处冒充成功。集合根目录不能移动，删除改由左侧集合菜单触发。
- 默认分类可改名、移动、删除；使用稳定目录编号关联分类，不能按显示名称识别。
- 用户删除默认分类后不自动补建。普通子目录创建时为空，不允许创建集合外的顶层普通目录。
- 删除关联资产集合不删除项目。此后项目首次成功上传、生成或编辑产生新素材时，重新建立同名集合及默认分类；只收录新素材，不找回已删素材。并发入库只能重建一个关联集合。
- 尚无目录的旧开发项目可在首次新素材入库时懒创建目录，不扫描补录历史素材。

### 3.2 删除画布项目

删除画布项目不影响资产库内素材或任何收录引用。原集合保留在左侧，解除活动项目绑定成为历史集合，允许继续整理资产及独立改名；来源项目记录保留，不能移动到其他集合。此后创建同名项目，按新项目编号建立新集合，不自动绑定历史集合。

项目删除与“删除资产文件夹”是两种完全不同的操作，接口不能互相替代。单张画布归档也不等于删除项目。

### 3.3 自动入库和分类

| 事件 | 归档规则 |
| --- | --- |
| 画布上传成功 | 新建原生素材并归入项目目录 |
| 生成成功 | 所有成功媒体结果入库，包括最终未采用结果 |
| 编辑生成新结果 | 新建素材，不覆盖源素材 |
| 从已有库选入画布 | 添加项目收录，复用原素材编号，不创建副本 |
| 替换节点内容、删除节点或删除画布 | 不删除资产库中的历史素材 |
| 上传或生成失败、临时预览 | 不作为成功素材入库 |

有明确业务分类且对应目录仍在集合内时归入该分类；无法分类、分类被删除时归入集合根目录，不补建分类，右侧按文件夹在前、素材在后展示。分类改名不改变分类关系。禁止真正移出集合；集合内部整理后，不因重新打开画布而自动搬回；用户主动再次添加引用属于新的收录操作。分类目录在集合内部被移动后的自动归档关联仍按稳定目录编号识别。

建议由服务端在上传确认、任务成功落库等持久化环节保证资产和收录一致，不能仅靠浏览器在线时补建。生成结果按任务与结果编号幂等，上传按上传会话幂等，重复通知不应重复入库。

### 3.4 集合复制与下载

- 复制整个目录结构及全部层级素材，不复制项目、画布、节点或连线；副本不与来源项目建立名称同步绑定。
- 原生及引用素材均生成独立资产身份与原生条目，副本与源素材改名、删除互不影响。底层可安全复用文件存储，但不可共享删除状态等业务身份；复制权限不等于预览或引用权限。
- 任一素材不可用或无复制权限，阻止整次复制，不发布残缺集合；中途失败由后端清理暂存产物。
- 点击复制后直接执行，不先弹窗输入名称。后端按本次复制源版本的集合名称追加“-副本”，如“甲项目-副本”；允许重名，不自动追加序号，用户可在成功后重命名。复制副本时仍对该源名称追加一次后缀；幂等重试返回同一次复制结果，不重复创建集合。
- 集合下载递归包含原生及引用的实际文件，保留目录组织。发现不可用或无下载权限条目时先返回遗漏数量、原因，用户确认后可只下载可用部分；不静默跳过，不将部分包称为完整包。
- 打包完成返回实际包含与遗漏清单；下载权限不因预检而豁免，执行时再次校验。全部不可下载时不生成假成功空包。下载预检后范围改变须返回变化信息，不能默认用户同意新的遗漏范围。

## 四、身份、命名与归属模型

### 4.1 核心概念

| 概念 | 含义 |
| --- | --- |
| 素材 `asset_id` | 媒体本体的稳定身份，不因改名、移动、添加引用变化 |
| 目录 `folder_id` | 目录身份；名称不是身份，可重复 |
| 条目 `entry_id` | 某个目录对某素材的一次收录，用于移动或移除当前位置 |
| 原生条目 `native` | 素材当前真正存放位置；一个存活素材只有一个原生归属 |
| 引用条目 `reference` | 指向相同素材的额外收录，不拥有独立媒体副本 |
| 来源记录 | 最初上传、生成或所属项目的信息，不随整理位置改变 |
| 资产集合 `collection_id` | 左侧入口及其根目录的稳定身份，独立于画布项目编号；每个目录属于一个集合 |
| 节点名称 | 画布节点独立名称，不是素材名称 |

素材改名是全局改名，所有收录位置同步；节点名称保持不变。目录、素材均允许重名，按编号执行所有写入操作。

外库素材的原生位置可能不在画布目录树内。画布资产库仅持有其引用，不得因为删除该引用或所在目录而删除外库原件。同一素材在同一目录是否允许重复收录尚未单独确定，建议按素材编号去重并返回已有条目；此建议需评审，不能与“允许重名”混为一谈。

### 4.2 建议数据结构

集合建议字段：`id`、`name`、`kind`（`project` / `historical` / `copy`）、`bound_project_id`（仅活动关联）、`source_project_id`、`source_collection_id`、`root_folder_id`、`revision`、`permissions`、`created_at`、`updated_at`。不得仅从存活画布项目列表拼装集合列表，否则会漏掉历史及复制集合。

目录字段：`id`、`collection_id`、`parent_id`（仅隐藏根目录为空）、`name`、`kind`（`root` / `normal`）、`category_key`、`revision`、`created_at`、`updated_at`。项目绑定属于集合；不再通过创建普通目录接口创建项目级根目录。

条目字段：`id`、`folder_id`、`asset_id`、`relation`（`native` / `reference`）、`revision`、`created_at`。`relation` 只用于操作判断，不展示引用标记。

素材摘要字段：`id`、`name`、`media_type`（`image` / `video` / `audio`）、`availability`、`origin`、`native_location`、`revision`、`thumbnail_url`、`preview_url`、`width`、`height`、`duration_ms`、`size_bytes`；不适用的媒体字段可为空。

建议 `origin` 含来源库、来源资源编号、来源项目／画布／节点／任务编号；`native_location` 表示当前原生库及目录，二者不能混用。预览地址属于短期视图，不作为持久身份，不假定可公开访问。

## 五、删除规则与画布联动

### 5.1 删除矩阵（已确认）

| 删除对象 | 素材本体 | 其他收录 | 画布影响 |
| --- | --- | --- | --- |
| 引用条目 | 保留 | 保留 | 无 |
| 原生条目 | 失效 | 所有位置不再展示该素材 | 所有引用节点清空媒体内容 |
| 文件夹中的原生素材 | 随目录递归删除而失效 | 同上 | 同上 |
| 文件夹中的引用条目 | 仅移除该目录树内收录 | 目录树外保留 | 无，除非原件也在本次删除范围 |
| 画布节点 | 保留 | 保留 | 只移除该节点或其内容 |
| 画布项目 | 保留 | 保留 | 资产目录解除绑定并保留 |
| 左侧资产集合 | 递归删除集合内原生素材 | 移除集合内引用；外部原件保留，已删除原件的其他收录失效 | 清空相关节点媒体内容，保留画布项目；移除集合入口 |

文件夹删除遵循本地文件整理的直觉，但只对目录中真正存放的原生素材执行本体删除；不能递归追踪引用去删除外部原件。原生素材已真正移动出目录后，不再受旧目录删除影响。

### 5.2 删除前预检与确认

1. 用户选择一个或多个条目、目录并点击删除。
2. 后端按完整目录树、原生归属和跨项目节点引用计算实际范围；合并祖孙目录，按素材编号去重。
3. 返回原生删除数、仅移除引用数、受影响项目／画布／节点数及有权限可见的项目摘要。涉及原件删除的引用不重复计为“仅移除引用”。
4. 展示二次确认。纯引用文案说明原素材和画布不受影响；原生或混合删除说明会清空所有相关画布节点的媒体内容，包括其他项目。
5. 用户确认后提交本次预检凭证；执行时影响范围改变须重新确认，不能沿用旧范围扩大删除。
6. 成功后刷新当前目录与受影响缓存；失败明确提示，不伪造已删除。

建议混合删除文案：“将删除 {N} 个原生素材，并移除 {M} 个引用；影响 {P} 个项目、{C} 张画布、{K} 个节点。节点和连线将保留，相关媒体内容会被清空。”不承诺可恢复，也不宣称立即物理清除。

预检失败不能视为“没有引用”。无权查看其他项目时不泄露项目名称，但仍需给出合法可披露的影响提示。预检不授予额外权限，执行时再次鉴权。

### 5.3 节点清空的精确定义

- 保留节点编号、类型、名称、位置、尺寸、分组、连线、提示词、模型与生成配置。
- 清除该素材的媒体绑定、预览、播放地址及派生媒体缓存；图片节点仍是空图片节点，而非删除节点或替换成其他类型。
- 节点含多个媒体引用时只清理被删除素材的绑定，不误删其他可用媒体。
- 所有指向该素材的生成参考失效，连线保留但不再传递该素材；生成前明确提示缺少参考。
- 已打开画布及时失效，离线画布在重新读取、解析或保存时对账。不得因旧草稿、自动保存、撤销或缓存使删除素材重新可用。
- 服务端必须维护可查询的资产绑定或等效索引，覆盖多张画布、多项目，而不是只改当前打开页面。

建议删除事务提交时立即撤销资产可用性并生成可靠失效事件；文档清理可按后端架构执行，但所有读取、解析、下载与生成均需立即受失效状态约束。既有签名地址与缓存的撤销能力需后端确认，不能只靠前端清空地址宣称删除生效。

## 六、建议接口契约

### 6.1 与当前代码的关系

已核对当前 `src/api/openapi.json`：存在 `/api/assets`、`/api/assets/{asset_id}`、资产下载和删除相关路径，以及 `/api/canvas-documents`、`/api/canvas-documents/{canvas_id}/resolve-assets`。现有恢复／永久删除接口存在，不意味着本期要提供对应产品入口。

`src/api/canvasAssets.js` 当前借用创作上传接口；`src/api/canvas.js` 已封装资产解析。现状不能证明多层目录、原生归属、引用条目、跨项目删除联动均已实现。以下路径和字段是契约建议，应与既有统一资产接口评审合并，避免另造一套不互通的素材身份。

建议统一使用现有鉴权方式和 `authFetch`，在 `src/api` 封装；页面不拼接请求。响应外壳沿用项目正式约定，以下示例仅展示业务数据，不额外规定新的统一外壳。

### 6.2 接口清单

| 方法 | 建议路径 | 关键输入与结果 |
| --- | --- | --- |
| GET | `/api/canvas-asset-library/collections` | `cursor`、`limit`；服务端统一按 `created_at` 倒序分页返回活动、历史及复制集合，含创建时间、根目录编号、项目绑定、权限及版本 |
| PATCH | `/api/canvas-asset-library/collections/{collection_id}` | `name`、`base_revision`、`idempotency_key`；关联集合由服务端同步项目名；历史和复制集合只改自身 |
| POST | `/api/canvas-asset-library/collections/{collection_id}/copies` | `base_revision`、`idempotency_key`；不要求输入名称，服务端按源版本名称追加“-副本”，允许重名、不追加序号；完整独立复制，返回操作编号及最终新集合编号与名称 |
| POST | `/api/canvas-asset-library/collections/{collection_id}/downloads/preview` | 返回范围凭证、可下载数、遗漏数量与原因及明细续取方式 |
| POST | `/api/canvas-asset-library/collections/{collection_id}/downloads` | 预检凭证、`allow_partial`、幂等键；部分下载必须显式确认，返回打包操作编号 |
| GET | `/api/canvas-asset-library/items` | `collection_id`、`parent_id`、`cursor`、`limit`；必须指定该集合根目录或子目录，返回混合网格与下一游标；取消无父目录读取全库顶层语义 |
| GET | `/api/canvas-asset-library/folders/{folder_id}` | 目录、祖先路径、权限与版本 |
| POST | `/api/canvas-asset-library/folders` | 必填 `parent_id`、`name`；只能在现存集合内部创建空普通目录，拒绝空父目录 |
| PATCH | `/api/canvas-asset-library/folders/{folder_id}` | `name`、`base_revision`；拒绝隐藏根目录改名，集合名使用集合接口 |
| POST | `/api/canvas-asset-library/references` | `folder_id`、`asset_ids`、`idempotency_key`；批量添加引用 |
| POST | `/api/canvas-asset-library/moves` | 目录／条目选择、目标目录、版本、幂等键；批量移动 |
| POST | `/api/canvas-asset-library/deletions/preview` | 选择集合；返回范围、预检凭证与过期时间 |
| POST | `/api/canvas-asset-library/deletions/commit` | 预检凭证、幂等键；执行已确认范围 |
| POST | `/api/canvas-asset-library/selections` | `collection_id`、`parent_id`、`scope: directory_children`；返回覆盖未加载条目的选择快照凭证、数量、版本与有效期 |
| GET | `/api/canvas-asset-library/operations/{operation_id}` | 复制、打包和异步删除的统一查询；返回状态、阶段、错误及对应结果 |

素材全局改名建议扩展或复用现有 `PATCH /api/assets/{asset_id}`，明确 `name` 与版本字段。单素材下载复用 `GET /api/assets/{asset_id}/download`；新增集合级打包能力，不能用前端逐个下载冒充压缩包。2026-10-21 确认取消画布资产库本地上传，移除该页面专用的 uploads 和 complete 接口要求；画布自身上传链路及成功后自动入库、失败清理要求保持不变。

以上路径为后端交接提案，不代表已部署。集合列表须独立分页，按 `created_at` 倒序在服务端全量排序，不能由前端仅对已加载数据排序；创建时间相同时须有固定的唯一编号次级排序以保证游标稳定，具体编号排序方向由接口评审确定。改名响应返回最新集合和已同步的项目版本，项目侧改名也须反向同步。副本和历史集合无活动绑定；关联约束保证每个活动项目最多一个活动集合。根目录由服务端生命周期建立，不能通过普通目录接口绕过限制。

操作查询建议统一状态 `pending` / `processing` / `completed` / `failed`，复制结果含 `collection_id`；打包结果含受控 `download_url`、`expires_at`、实际数量、遗漏清单及其续取方式。任务和下载均校验操作者权限，链接过期可重新申请；长期任务可跨刷新按原操作编号查询，超时不自动换键重复创建任务。

项目创建、项目改名、项目删除与自动目录绑定属于服务端生命周期联动，前端不应串联两个独立请求后自行宣称成功；沿用待明确的独立项目契约，不臆定项目接口已经满足。

### 6.3 列表与添加引用样例

列表项建议用 `type` 区分目录和条目，条目内部携带素材摘要；目录分页不能先返回素材、后面又补出子文件夹。服务端提供稳定排序与不透明游标。

```json
{
  "items": [
    {"type": "folder", "id": "folder_1", "collection_id": "collection_1", "name": "角色", "kind": "normal", "revision": 2},
    {"type": "entry", "id": "entry_1", "folder_id": "folder_root", "relation": "reference", "revision": 1,
      "asset": {"id": "asset_1", "name": "角色正面", "media_type": "image", "availability": "ready"}}
  ],
  "next_cursor": null
}
```

添加引用输入建议如下；示例编号只用于说明，真实编号格式遵循正式契约。

```json
{
  "folder_id": "folder_target",
  "asset_ids": ["asset_1", "asset_2"],
  "idempotency_key": "reference-request-1"
}
```

建议返回 `entries` 及已有条目结果，不通过名字去重。来源库尚未统一编号时，应先通过正式解析／登记能力映射到统一 `asset_id`，并检查权限、类型和可用性。

### 6.4 移动与并发

```json
{
  "selection": [
    {"type": "entry", "id": "entry_1", "base_revision": 1},
    {"type": "folder", "id": "folder_2", "base_revision": 3}
  ],
  "target_folder_id": "folder_target",
  "idempotency_key": "move-request-1"
}
```

后端根据条目真实关系判断是移动原生归属还是移动引用，不能信任客户端提交的关系类型。建议批量元数据写入采用全成全败；若实际基础设施只能异步执行，必须返回操作编号和查询契约，前端不得直接显示全部成功。

同目录移动可按无变化成功处理；目标被删、项目根被选中、循环移动或版本冲突则拒绝并刷新。幂等键用于同一次提交重试，不替代版本检查。

后端根据目录真实 `collection_id` 校验所有源和目标，跨集合一律拒绝，即使条目是引用也不能跨集合移动；前端目标选择器仅展示同集合目录。跨集合添加只调用 references，素材原生位置不变。

### 6.5 删除预检与执行样例

预检请求：

```json
{
  "selection": [
    {"type": "folder", "id": "folder_1"},
    {"type": "entry", "id": "entry_2"}
  ]
}
```

显式选择继续使用上述 `selection`。目录全选改为提交 `selection_token`，与显式 `selection` 互斥；凭证由 selections 接口生成并绑定当前目录全部直接条目及范围版本，不受前端分页影响。删除选择中的文件夹仍递归展开。左侧集合删除使用 `selection: [{"type":"collection","id":"collection_1"}]`，服务端覆盖根目录全部层级并在成功后移除集合入口，不调用画布项目删除接口；不新增独立“清空资产”接口。选择凭证失效或范围改变必须重新获取、预检及确认。

预检响应：

```json
{
  "preview_token": "opaque-preview-token",
  "expires_at": "2026-10-19T10:05:00Z",
  "impact": {
    "folder_count": 3,
    "native_asset_count": 5,
    "reference_only_count": 2,
    "affected_project_count": 2,
    "affected_canvas_count": 4,
    "affected_node_count": 7
  },
  "affected_projects": [{"id": "project_b", "name": "乙项目"}],
  "next_projects_cursor": null
}
```

项目摘要分页或截断时须有明确续取能力，不能用首批摘要数量代替真实总数。删除执行只接受服务端预检凭证和本次幂等键，不接受客户端自行重算的数量作为授权依据。

```json
{
  "preview_token": "opaque-preview-token",
  "idempotency_key": "delete-request-1"
}
```

建议返回 `operation_id`、`status`（`completed` / `processing`）、实际影响统计。若允许 `processing`，需同时交付 `GET /api/canvas-asset-library/operations/{operation_id}`，含状态、失败信息和最终统计。客户端超时须查询原操作或同键重试，不得换键重复提交。

预检凭证应绑定操作者、选择集合、素材归属及引用范围版本。预检后的新增收录、目录变化、节点引用变化等如果会改变已确认范围，提交必须返回范围变化错误并重新预检，避免提示仅影响甲项目却实际清空新加入的乙项目。

### 6.6 画布解析与错误建议

沿用现有 `POST /api/canvas-documents/{canvas_id}/resolve-assets`，按已封装的每批最多 200 个素材分批解析。建议响应对每个请求编号明确返回可用性，不因为某个素材不可用而让整张画布读取失败；字段需与现有协议对齐。

建议最少能表达可用、已删除、无权限和不存在；无权限信息不得泄露其他用户素材。画布保存和任务创建也必须校验资产状态，不能仅在读取时校验。生成参考缺失时拒绝使用失效素材，具体错误码纳入正式协议。

| 建议错误码 | 前端行为 |
| --- | --- |
| `FOLDER_NOT_FOUND` / `TARGET_NOT_FOUND` | 刷新路径，提示目标已不存在 |
| `PROJECT_FOLDER_LOCKED` | 提示该项目目录不可执行此改名／移动 |
| `FOLDER_CYCLE` | 保持原位置，提示不能移入自身或子目录 |
| `CROSS_COLLECTION_MOVE_FORBIDDEN` | 提示跨集合仅可添加引用，不自动转为引用或复制 |
| `ROOT_FOLDER_CREATION_FORBIDDEN` | 提示不能自由创建项目级集合或根目录 |
| `COLLECTION_NOT_FOUND` | 刷新左侧列表与当前选择，不把历史集合当不存在项目处理 |
| `SELECTION_EXPIRED` / `SELECTION_SCOPE_CHANGED` | 重新获取全选快照及删除预检，不使用当前页替代 |
| `COPY_SOURCE_UNAVAILABLE` / `COPY_PERMISSION_DENIED` | 整次复制失败，不发布不完整集合 |
| `DOWNLOAD_CONFIRMATION_REQUIRED` / `DOWNLOAD_SCOPE_CHANGED` | 显示遗漏原因，重新取得用户对部分下载的确认 |
| `ASSET_UNAVAILABLE` | 显示空媒体状态，停止下载／添加／生成参考 |
| `PERMISSION_DENIED` | 不改本地成功态，刷新权限 |
| `REVISION_CONFLICT` | 保留用户输入，刷新后重新操作，不静默覆盖 |
| `DELETE_PREVIEW_EXPIRED` / `DELETE_SCOPE_CHANGED` | 重新预检并二次确认 |
| `UNSUPPORTED_MEDIA_TYPE` | 拒绝添加不支持的素材并说明支持范围 |
| `IDEMPOTENCY_CONFLICT` | 不自动换键重试，提示操作状态异常 |

建议返回可追踪的 `request_id`，业务错误码与 HTTP 状态由后端统一映射。网络错误不降级为假列表或假成功。
