## 二、仍需补齐的契约

### 1. 无视觉风格的自由画布项目

产品要求：独立项目包含多画布，项目名与画布名分离。创建自由画布项目不要求用户选择风格，也不在后台默认绑定任何风格。

现有 `visual_style` 必填、非空的约束不满足要求；不能通过传入默认风格或自定义风格提示词绕过。请提供：

- 自由画布正式 `project_type` 值；允许省略风格且不自动绑定风格的最小创建请求和响应。
- 项目列表如何可靠区分自由画布项目。现有列表为裸数组且未提供类型筛选，不自行假设有筛选参数或总数。
- 项目复制保留画布父子关系的行为。目前交接说明复制丢失父子关系，不由前端补造副本掩盖。

首张画布原子参数已明确，无需重新设计。上述满足后，前端接正式项目入口和生命周期。

### 2. 四类自由节点的生成与编辑

现有 Run 使用提示词、配置、结果节点拓扑，与前端文本、图片、视频、音频自由节点不等价。请明确自由节点到 Run 的映射，以及尚未给出的文本生成与图片/视频编辑协议：

- 创建请求、目标节点及源资产关系、能力参数和版本/幂等约束。
- 查询终态与结果永久素材编号、失败和取消表现、刷新后恢复及结果回填示例。
- 编辑结果新增节点、保留源节点，不改变用户既定操作，不维护第二份冲突的画布文档。

前端已封装 Run 查询、取消和只读对账，不代表创建、轮询和回填已接通；不会用旧生成接口冒充新链路。

### 3. 分享导入到指定项目

目前导入请求只有幂等键，没有目标项目参数，默认个人归属不满足要求。请提供指定目标项目的正式请求字段、权限校验、重复请求行为及响应中的项目/画布编号，供前端导航。

不采用先导入个人再猜测移动接口的方案。现有 `client_request_id` 已封装，无需重复新增同类键。
