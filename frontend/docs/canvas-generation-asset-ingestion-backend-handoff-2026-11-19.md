# 画布生成结果统一资产入库与画布集合收录：后端交接

> 日期：2026-11-19
> 状态：需求已确认；前端项目参数已在本地补齐并通过定向验证，尚未完成真实后端联调。
> 范围：画布生成的图片、视频、音频。当前反馈为视频、音频未出现在「资产 → 画布资产」。

## 1. 已确认的目标

**画布生成的每个成功媒体结果必须写入统一资产，并被收录到所属画布项目的「画布资产」集合。**

完整链路：

```text
画布提交生成请求
  → 服务端确定任务所属会话、画布和项目
  → 媒体结果成功并持久化
  → 创建统一资产，取得永久 asset_id
  → 将 asset_id 收录到所属画布项目的资产集合
  → 生成接口 / 任务查询返回稳定资产编号及媒体地址
  → 画布资产列表可查询、查看和下载该结果
```

统一资产记录与集合收录是两个必须完成的环节。仅返回视频 / 音频 URL、仅创建统一资产、仅在画布节点保存结果，都不代表画布资产收录完成。

## 2. 当前事实与待确认原因

### 已确认

- 图片生成原本会传 `project_id`；视频、音频原本只传 `session_id`，遗漏了画布所属项目。
- 前端已修改 `CanvasPage`、`UseCanvasVideoGeneration`、`UseCanvasAudioGeneration`，将真实 `canvas.project_id` 传入生成请求；API 层已有项目参数透传逻辑。
- 视频 / 音频写回画布前，前端要求返回合法 UUID 格式的永久 `asset_id`，不会用任务编号、卡片编号或 URL 替代。
- 前端成功写回后发送 `canvas-assets-changed` 刷新事件；不会额外发起资产创建 / 集合收录请求。刷新通知本身不能创建收录条目。
- 前端当前读取画布集合使用 `GET /api/canvas-assets/collections`，目录内容使用 `GET /api/canvas-asset-library/items`。

### 尚未确认

尚未查询真实后端数据库、任务日志和列表响应，不能将以下任一项当作已证实的唯一根因：

1. 旧请求遗漏项目，服务端未从会话推导项目，导致归属缺失。
2. 已创建统一资产，但未创建画布集合收录条目。
3. 某些视频 / 音频成功分支未执行统一入库逻辑。
4. 收录到了错误项目、错误目录或已隐藏的系统预设目录。
5. 数据已完整收录，但集合 / 目录列表的权限、媒体类型或分页过滤遗漏结果。

请先各取一条实际未显示的视频和音频进行全链路定位，再确认根因。

## 3. 后端实施要求

### 3.1 任务归属

- 接收并持久化 `project_id`、`session_id`，通过可信关系确定来源画布；校验用户对项目、会话、画布的权限及相互归属。
- 多张画布属于同一项目时，共用该项目的画布资产集合，不为每张画布单独建集合。
- 对旧客户端只传 `session_id` 的请求，若可通过唯一可信关系推导项目，则兼容解析；无法确定或字段冲突时返回明确错误，不静默归入错误项目。
- 不按项目名、画布名或文件名推断身份。
- 若后端仍需要额外来源字段，请同步正式 OpenAPI 和前端参数要求，不能依赖未约定字段。

### 3.2 统一资产创建

- 在服务端确认媒体成功且文件可持久访问后，为每个新结果创建统一资产，返回永久 `asset_id`。
- 保留正确所有者、项目归属、媒体类型（`image` / `video` / `audio`）、来源任务及结果身份、成功时间、原文件地址 / 文件引用；宽高、时长、文件大小按媒体实际信息填写。
- 视频有封面时返回 `thumbnail_url` 或 `poster_url`，便于列表仅加载图片。封面处理不应导致已成功的视频永久漏收录。
- 生成新结果不得覆盖旧资产的业务身份；节点替换、未采用结果、节点删除不删除已成功的资产。
- 批量生成逐个收录成功媒体，失败子项不收录；不能因整批部分失败而丢弃成功子项。此处是资产库规则，不复用生成历史可能不同的整批展示规则。
- 不将文本结果、失败结果、临时预览当作成功媒体收录。

### 3.3 画布资产集合收录

- 找到该画布项目的活动关联集合，建立指向统一 `asset_id` 的收录条目。具体表结构由后端确定，但必须可追溯任务、结果、项目、集合和目录。
- 未明确指定有效目标目录时，归入集合根目录；指定目录需属于当前集合且可用。
- 不按媒体类型自动放入旧的「角色、场景、道具、分镜、音频」系统目录，也不重建这些预设目录。当前前端会隐藏对应 `category_key` 的目录入口，归入其中可能造成用户找不到结果。
- 集合不存在时，按现有项目生命周期规则并发安全地建立唯一活动集合及根目录；只收录本次新结果。
- 用户移动已收录条目后，后台重试 / 对账不得将其搬回根目录。
- 用户主动删除收录或集合后，任务回调重放不得将旧结果恢复。后续真正的新素材可按既有规则重建集合。

### 3.4 可靠性与幂等

- 由服务端生成成功处理逻辑完成入库，不能依赖前端在线、结果回填、点击添加到画布或重新打开页面。
- 使用事务或可靠事件与补偿机制保证统一资产与集合收录最终完整；文件处理失败、事务失败及队列失败应可追踪、重试。
- 生成结果按稳定的任务 / 结果身份幂等，集合收录也须防重。重复回调、轮询、工作进程重试不得重复创建资产或条目。
- 明确成功响应与收录完成的时序。若异步收录，需提供可观测状态或明确的重查方式，并在联调时约定可见时限；不能把永久收录失败当作生成已完全交付。

## 4. 必须覆盖的服务端入口

| 入口 | 当前前端调用 | 后端成功处理要求 |
| --- | --- | --- |
| 图片生成 | `POST /api/creation/images/generate` | 每个成功结果统一入库并收录 |
| 视频生成 | `POST /api/creation/videos/generate`，随后查询 `GET /api/creation/videos/tasks/{taskId}` | 视频任务成功处理执行入库 / 收录，结果返回真实 `asset_id` |
| 同步配音 | `POST /api/creation/audios/generate` | 直接成功返回前完成或可靠触发入库 / 收录，响应携带真实 `asset_id` |
| 普通异步配音 | 上述音频接口返回任务，随后查询 `GET /api/creation/audios/tasks/{taskId}` | 异步任务成功处理执行相同入库 / 收录逻辑 |
| 长文本异步配音 | `POST /api/creation/audios/generate-async`，随后查询音频任务 | 与普通配音保持一致，不能遗漏独立 worker / 回调分支 |

建议复用统一的成功结果登记服务，避免各 provider、同步 / 异步分支分别维护而遗漏。具体内部实现由后端选择。

## 5. 返回与列表联调约定

以下为最小字段示意，不替代完整接口响应；沿用正式接口字段，不要求额外增加前端入库调用。

视频任务成功结果至少满足：

```json
{
  "result": {
    "asset_id": "11111111-1111-4111-8111-111111111111",
    "video_url": "https://media.example.invalid/result.mp4",
    "thumbnail_url": "https://media.example.invalid/result.jpg"
  }
}
```

同步音频成功响应至少携带 `asset_id`、`audio_url`；异步音频任务结果在 `result` 中携带上述字段。返回的资产编号须能通过 `GET /api/assets/{asset_id}` 读取到一致的媒体资产详情。

列表联调：

1. `GET /api/canvas-assets/collections` 返回对应画布项目的集合及有效根目录编号。
2. `GET /api/canvas-asset-library/items?collection_id=...&parent_id=...` 返回新生成资产的条目，包含稳定条目身份、`asset_id` 和正确媒体摘要。
3. 项目、目录、媒体类型、权限和游标筛选不漏视频 / 音频；历史系统目录隐藏不能成为新结果的不可见落点。
4. 刷新、重新登录后仍可查询，详情 / 下载地址过期可按资产编号重新解析。

## 6. 本次存量数据排查与修复

排查顺序：

```text
来源画布 → creation_session_id → task_id / 同步生成记录
  → project_id → 生成结果 asset_id → 统一资产记录
  → 项目关联集合 → 收录条目及目录 → 列表查询响应
```

每个样本请记录：任务 / 结果编号、来源会话与画布、预期项目、实际资产项目、资产是否存在、集合及目录、收录是否存在、是否有删除记录、列表是否返回。日志不包含访问令牌或可直接访问的私密签名地址。

修复原则：

- 本次仅针对确认受本缺陷影响的成功生成记录制定显式补偿范围，先输出只读预检清单与数量，再执行可审计、可重试的修复。
- 已存在统一资产时保留原 `asset_id`，仅补缺失归属或收录；资产确实缺失时按原任务 / 结果身份幂等补建。
- 归属不明、跨用户冲突或文件不可用的记录单独列出，不凭名称猜测。
- 排除用户主动删除的资产、收录及集合，不恢复已删除内容；不改变用户整理后的有效目录位置。
- 不将本次缺陷补偿扩展为日常扫描所有旧项目自动补录。既有「首次新素材懒建目录，不扫描补录历史」规则保持适用。
- 输出修复成功、跳过、失败数量及原因，复核修复后列表可见性和重复执行无新增重复条目。

## 7. 验收用例

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| 01 | 画布生成视频 | 有真实统一资产，并在所属项目画布集合可见、可查看和下载 |
| 02 | 同步配音成功 | 同时完成音频资产创建及集合收录 |
| 03 | 普通异步及长文本异步配音 | 两条路径均完成音频资产创建及集合收录 |
| 04 | 图片多结果及部分失败 | 每个成功媒体均收录，失败子项不收录 |
| 05 | 同项目多张画布 | 结果进入同一项目集合，来源身份可追溯 |
| 06 | 不同项目 | 归档正确且无跨项目 / 跨用户泄漏 |
| 07 | 生成中关闭页面、刷新或退出登录 | 后端仍完成入库，重新进入可见 |
| 08 | 重复回调 / 补偿重试 | 同一结果不产生重复资产及重复收录 |
| 09 | 集合首次创建及并发新结果 | 只建一个活动集合和根目录，结果全部可见，不预建五类系统目录 |
| 10 | 已收录结果被节点替换 / 节点删除 | 资产库内容保留 |
| 11 | 用户移动或删除收录后重放旧事件 | 不搬回原目录，不恢复已删除内容 |
| 12 | 本次存量补归档 | 预检范围可审计，缺失结果可见，重复运行无重复，主动删除记录保持删除 |
| 13 | 旧请求仅传会话 / 请求归属冲突 | 可可信推导时正确归属；冲突或不可确定时明确报错 |
