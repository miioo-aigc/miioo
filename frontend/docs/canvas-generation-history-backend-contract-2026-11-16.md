本轮直接读取 `frontend/src/api/openapi.json`，结论如下：

| 能力 | OpenAPI 状态 | 前端处理 |

| 画布详情返回创作会话 | 已声明 `CanvasDocumentDetailResponse.creation_session_id`，且为必填 | 画布生成与编辑使用真实值；缺会话时不提交、不创建运行态 |

| 视频超清、字幕消除、剪辑、抽帧 | 四个 request schema 均已声明可空 `canvas_id` | 画布入口传递，独立创作入口省略 |

| 历史资产可用性 | `AssetSummaryOut` 声明 `media_type` 和 `availability=ready/trashed/forbidden/missing`，并声明展示地址字段 | 不可用资产保留占位，禁止添加或下载 |
| 成功时间 | **缺口：** `CanvasGenerationHistoryItemOut` 当前只有 `created_at`，没有交接要求的 `completed_at` | 不把 `created_at` 冒充成功时间；缺失时归入“未知时间” |
| 扩图来源画布 | **缺口：** `CreationImageGenerateRequest` 和 `OutpaintImageEditRequest` 均未声明 `canvas_id` | 前端按交接向现有生成入口传递 `canvas_id`；后端需在 schema 与请求模型补齐后再联调确认登记 |

## 1. 文档目的

本文汇总画布「生成历史」的产品定义、后端接口语义、数据生命周期、异常规则和联调验收标准。

当前 OpenAPI 已经声明列表和删除接口，但这只表示接口形状存在，不能表示以下能力已完成：

- 成功生成结果的自动登记。
- 二次编辑结果的收录。
- 批次全部成功才收录的原子判断。
- 删除历史后的永久墓碑和回调幂等。
- 跨画布权限校验。
- 完整资产详情、下载和失效地址解析。

后端完成实现后，应以本文的验收场景和真实请求结果作为交付依据。

## 2. 产品定义

### 2.1 历史记录的最小单位

一条生成历史对应一个成功生成或编辑后产生的独立媒体结果，不对应画布节点、生成批次或资产库列表项。

示例：

- 一个节点批量生成 4 张图片，4 张全部成功，应登记 4 条图片历史。
- 删除原节点后，这 4 条历史仍然存在。
- 用户将其中两张分别添加回画布，会生成两个全新的独立节点。
- 同一个历史结果可以重复添加多次，每次都应该创建新的独立节点。

### 2.2 收录范围

| 来源 | 是否收录 | 说明 |
|---|---|---|
| 图片生成 | 是 | 每个成功媒体结果一条记录 |
| 视频生成 | 是 | 每个成功媒体结果一条记录 |
| 音频生成 | 是 | 每个成功媒体结果一条记录 |
| 局部重绘 | 是 | 新产物单独登记，原结果保留 |
| 裁剪 | 是 | 新产物单独登记，原结果保留 |
| 扩图等其他二次编辑 | 是 | 所有支持媒体类型的成功产物均登记 |
| 文本生成 | 否 | 当前生成历史不记录文本 |
| 上传素材 | 否 | 不属于平台生成结果 |
| 普通导入素材 | 否 | 不属于平台生成结果 |
| 普通资产库素材 | 否 | 不能因出现在资产库而自动形成历史 |
| 失败任务 | 否 | 不产生历史 |
| 部分失败批次 | 否 | 即使批次中有成功子项，也整批不登记 |

### 2.3 生命周期

- 生成历史按来源画布持久化。
- 刷新页面、重新登录后记录仍存在。
- 删除节点、替换节点内容、清理画布运行态，都不能级联删除生成历史。
- 删除生成历史只删除历史索引，不删除底层资产、文件、资产库记录或仍在画布上的节点。
- 查询生成历史时不得依赖节点当前是否存在。
- `canvas_id` 是历史归属的稳定依据，添加到其他画布不会改变历史归属。

## 3. 建议确认的产品口径

| 事项 | 建议口径 |
|---|---|
| 类型枚举 | 固定为 `all`、`image`、`video`、`audio`，文本不设枚举 |
| 批次完成时间 | 同批所有记录统一使用批次最终确认全部成功的时间 |
| 视频附属内容 | 封面、缩略图、转码文件、字幕等不单独形成历史 |
| 删除历史 | 记录立即隐藏，保留最小墓碑，防止回调或重放复活 |
| 资产库删除 | 不应静默破坏仍被历史引用的内容；不可恢复时保留“内容不可用”历史 |
| 媒体地址 | `asset_id` 是稳定身份，媒体 URL 是按需生成的短期地址 |
| 日期分组 | 后端返回带时区时间，前端按 `Asia/Shanghai` 分组 |
| 分页排序 | `completed_at` 倒序，并使用稳定唯一键组成不透明游标 |

## 4. 类型参数

建议最终枚举：

```text
all | image | video | audio
```

约定：

- `all` 返回图片、视频和音频，不返回文本。
- 后端遇到未知类型返回 `422`。
- 前端遇到未来新增的未知媒体类型时，应兼容为通用媒体卡片，避免整个历史弹窗渲染失败。
- 不允许通过生成历史接口返回上传、导入或资产库普通素材。

## 5. 成功登记与批次规则

### 5.1 批次原子登记

只有批次内所有结果全部成功，才写入生成历史。

建议判定：

```text
total_count > 0
success_count == total_count
fail_count == 0
```

批次从“运行中”变为“最终成功”后，提交全部历史记录。任何一个结果失败时，整批不登记。

### 5.2 时间字段

建议在响应中新增并使用 `completed_at` 表示：

> 最后确认整批结果全部成功，并且可以进入生成历史的时间。

同一批次的所有记录使用同一个 `completed_at`。列表排序和日期分组使用该字段。

建议同时保留以下后台字段，不要求前端展示：

- `result_completed_at`：单个媒体文件实际完成时间。
- `recorded_at`：历史索引实际写入时间。

这些字段用于排查延迟、回调重放和批次判定问题，不能替代用户可见的 `completed_at`。

### 5.3 二次编辑

以下流程均需确认是否已经接入历史登记：

- 图片局部重绘。
- 图片裁剪。
- 图片扩图或其他生成式编辑。
- 视频二次编辑。
- 音频二次编辑。

每个新产物单独登记，原产物的历史仍然保留。不能按画布节点 ID 或当前节点内容推导历史。

## 6. 视频附属内容

只记录能够作为独立产物使用的媒体主文件。以下附属内容不单独形成历史：

- 视频封面。
- 预览缩略图。
- 转码版本。
- 字幕。
- 音轨信息。
- 播放元数据。

判断标准：

1. 是否有独立资产 ID。
2. 是否能独立添加到画布。
3. 是否作为独立交付物展示。

只有同时满足以上条件，才适合作为独立历史记录。用户单独生成或编辑出一张图片，并且它作为独立图片资产出现时，应登记为图片历史。

## 7. 画布参数与跨画布规则

### 7.1 参数语义

```http
GET /api/canvas-documents/{canvas_id}/generation-history
    ?target_canvas_id={target_canvas_id}
    &type={type}
    &limit={limit}
    &cursor={cursor}
```

| 参数 | 建议语义 |
|---|---|
| `canvas_id` | 历史来源画布，即用户在下拉框中选择的 B |
| `target_canvas_id` | 用户当前所在画布，即打开弹窗的 A |

### 7.2 权限规则

- A 和 B 必须是同一项目内的有效画布。
- 用户必须同时拥有目标画布和来源画布的访问权限。
- 跨项目画布不能出现在画布选择列表中，也不能通过构造请求读取。
- 使用 `target_canvas_id` 不得绕过来源画布权限。
- 在 A 查看 B 的历史并把记录添加到画布时，只把节点加入 A；记录仍归属于 B。
- 删除历史时，删除的是来源画布 B 的历史索引。

### 7.3 建议响应

| 场景 | 状态码 | 建议错误码 |
|---|---:|---|
| 当前用户未登录 | 401 | `AUTH_REQUIRED` |
| 来源画布无权限 | 403 | `SOURCE_CANVAS_FORBIDDEN` |
| 目标画布无权限 | 403 | `TARGET_CANVAS_FORBIDDEN` |
| 来源和目标不属于同一项目 | 403 | `CANVAS_PROJECT_MISMATCH` |
| 来源画布不存在 | 404 | `SOURCE_CANVAS_NOT_FOUND` |
| 目标画布不存在 | 404 | `TARGET_CANVAS_NOT_FOUND` |
| 历史记录不存在 | 404 | `HISTORY_NOT_FOUND` |
| 历史记录不属于来源画布 | 404 | `HISTORY_NOT_FOUND` |
| 游标无效或已损坏 | 422 | `INVALID_CURSOR` |
| 类型枚举无效 | 422 | `INVALID_MEDIA_TYPE` |

错误响应应保留具体原因，前端不能把所有 404/501 都显示成“服务暂未开放”。

## 8. 列表响应契约

建议列表响应保持分页对象结构：

```json
{
  "items": [
    {
      "id": "history-uuid",
      "canvas_id": "source-canvas-uuid",
      "type": "image",
      "asset_id": "asset-uuid",
      "completed_at": "2026-11-16T08:30:00Z",
      "asset": {
        "id": "asset-uuid",
        "name": "生成图片",
        "media_type": "image",
        "availability": "ready",
        "thumbnail_url": "https://...",
        "preview_url": "https://...",
        "original_url": "https://...",
        "download_url": "https://...",
        "width": 1024,
        "height": 1024,
        "duration_ms": null,
        "size_bytes": 524288
      }
    }
  ],
  "next_cursor": "opaque-cursor"
}
```

字段要求：

- `items` 和 `next_cursor` 必须始终存在。
- 没有下一页时 `next_cursor` 为 `null`。
- `asset.id` 必须等于条目中的 `asset_id`。
- `asset.media_type` 必须与条目的 `type` 一致。
- `completed_at` 使用带时区的 ISO 8601 格式。
- 已删除历史不能出现在 `items` 中。
- `availability` 为不可用时，记录仍可存在于历史中，但前端需要禁用不可用操作。

## 9. 排序和游标分页

建议排序：

```text
completed_at DESC,
history_sequence DESC
```

其中 `history_sequence` 是后端生成的稳定唯一顺序值，用于处理同一时间完成的记录。批次内结果还应保持确定的稳定顺序。

游标必须是不透明字符串，内部可以编码：

```text
(completed_at, history_sequence)
```

服务端下一页条件建议：

```text
completed_at < cursor.completed_at
OR (
  completed_at = cursor.completed_at
  AND history_sequence < cursor.history_sequence
)
```

不能使用 offset 分页，避免新记录插入后出现重复或遗漏。

接口需确保：

- `limit` 范围为 1–200，默认 50。
- 同一排序条件下可以连续遍历完整历史。
- 翻页过程中没有重复条目。
- 翻页过程中没有条目因相同时间戳而遗漏。
- 游标不暴露数据库敏感信息。
- 游标损坏或版本不兼容时返回明确 `422 INVALID_CURSOR`。

## 10. 删除历史与墓碑

### 10.1 删除副作用

删除历史必须：

- 立即从所有列表和筛选中消失。
- 不删除资产文件。
- 不删除资产库记录。
- 不删除画布节点。
- 不修改其他画布的历史。
- 不修改原始生成或编辑任务。

### 10.2 幂等

建议重复删除同一历史记录时仍返回 `204`，或返回统一且可识别的“已删除”结果。不能因为客户端重试而报不可恢复错误。

### 10.3 最小墓碑

建议永久保留最小化删除墓碑，至少包含：

- 来源画布 ID。
- 稳定结果唯一标识。
- 删除时间。
- 必要的幂等键。

墓碑随画布或项目永久删除时一起清理。墓碑不复用历史 ID，不长期保存完整媒体副本。

以下流程不能恢复已删除历史：

- 生成成功事件重复消费。
- 异步任务状态回调。
- Run reconcile。
- 后台对账。
- 任务重放。
- 页面刷新或重新登录。

## 11. 资产可用性

`asset_id` 是稳定身份，媒体 URL 不作为持久身份。

建议前端每次打开生成历史时，使用 `asset_id` 批量解析最新媒体视图。短期 URL 过期后应重新解析，不新增历史记录。

建议的资产可用状态：

| `availability` | 历史列表 | 详情 | 添加 | 下载 |
|---|---|---|---|---|
| `ready` | 正常展示 | 正常展示 | 允许 | 允许 |
| `trashed` | 保留并标记不可用 | 展示不可用原因 | 禁用 | 禁用 |
| `forbidden` | 保留占位 | 不返回敏感名称和地址 | 禁用 | 禁用 |
| `missing` | 保留占位 | 展示“内容不可用” | 禁用 | 禁用 |

### 11.1 资产库删除与历史

建议：

- 从资产库删除时，只取消资产库中的普通展示。
- 仍被生成历史引用的文件应继续支持预览、下载和添加到画布。
- 如果产品必须提供“彻底删除文件”，必须明确提示会同时影响生成历史。
- 彻底删除后历史记录仍保留，但显示“内容不可用”，不能静默删除整条历史。
- 删除生成历史不反向删除资产或文件。

### 11.2 下载

下载建议使用以下方式之一，并在 OpenAPI 中明确唯一口径：

1. 使用响应中的有效 `asset.download_url`。
2. 使用带登录鉴权的 `GET /api/assets/{asset_id}/download`。

不能把历史记录 `id` 当作生成文件 ID 或资产 ID 使用。签名 URL 必须遵循有效期，前端不能长期持久化。

## 12. 完整详情

生成历史详情的内容应与资产库详情一致，但去掉二次编辑能力。

- 列表接口可以提供资产摘要。
- 点击卡片后，前端应通过 `asset_id` 获取完整资产详情。
- 详情至少应支持提示词、模型、生成参数、尺寸、时长、文件大小、创建时间等资产库已有信息。
- 历史详情只保留“添加到画布”动作。
- 不展示二次编辑、收藏、移动到其他库等生成历史不需要的动作。
- 若已有独立详情接口可以复用，后端需在 OpenAPI 中写清楚复用关系。

## 13. 幂等与数据完整性

建议使用稳定的结果唯一键保证登记幂等，例如：

```text
task_result_id
generation_result_id
edit_result_id
```

不能只依赖时间、文件名或浏览器回调。

约束：

- 同一成功结果重复回调只产生一条历史。
- 不按 `asset_id` 做全局唯一，避免同一资产在不同画布的合法记录互相覆盖。
- 同一画布批量生成 N 个成功结果，稳定产生 N 条记录。
- 删除墓碑独立于任务状态保存。
- 历史索引与节点生命周期解耦。
- 生成、编辑入口必须能够解析可信的来源画布。

## 15. 联调验收清单

1. 成功生成一张图片，产生一条图片历史，类型筛选和时间排序正确。
2. 成功生成一个视频，产生一条视频历史，封面作为附属内容展示。
3. 成功生成一个音频，产生一条音频历史，可播放、下载并添加到画布。
4. 一次批量生成 4 张图片且全部成功，产生 4 条独立历史。
5. 一次批量生成 4 个结果，其中 3 成功 1 失败，不产生任何历史。
6. 文本生成、上传、导入和失败任务均不产生历史。
7. 删除原节点后，历史仍然存在。
8. 刷新页面和重新登录后，历史仍然存在。
9. 对图片执行局部重绘，新结果产生新历史，原历史仍保留。
10. 对图片执行裁剪，新结果产生新历史，原历史仍保留。
11. 删除历史后，记录立即消失，但资产文件、资产详情和已有画布节点仍可用。
12. 删除历史后重复消费成功事件或执行任务重放，记录不得复活。
13. 同一项目 A/B 画布中，A 请求 B 的历史成功；添加到画布后节点创建在 A，记录仍归属 B。
14. 构造跨项目 B 画布请求时返回 403，且不泄露画布或资产信息。
15. 同一历史结果连续添加两次，前端创建两个独立节点，后端历史数量不变化。
16. 使用 `limit=50` 和 `next_cursor` 遍历超过 50 条历史，无重复、无遗漏。
17. 同一批次多条记录时间相同时，分页顺序稳定，不重复、不遗漏。
18. `preview_url` 或 `download_url` 过期后，前端按 `asset_id` 重新解析成功。
19. `availability=missing` 或 `forbidden` 时，历史仍可见但不可下载、不可添加，并展示不可用原因。
20. 生成历史详情内容与资产库详情一致，只保留“添加到画布”，不出现二次编辑和收藏等动作。
