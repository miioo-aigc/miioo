# 画布生成历史：后端待补齐能力交接

> 本文面向后端实现与联调，依据已确认的产品需求、`frontend/src/api/openapi.json` 当前契约及前端调用现状整理。
> 当前 OpenAPI 已定义列表、删除接口和基础响应模型；这只表示接口契约存在，不代表生成登记、持久化、权限和数据生命周期已经实现或验收。

## 目标与职责边界

生成历史按画布持久化，历史最小单位是成功生成或编辑完成的单个媒体结果，不是节点、批次或资产。删除画布节点、替换节点内容、刷新或重新登录都不应清除历史。用户删除历史只移除历史记录，不应删除资产或影响任何画布节点。

前端负责浏览和筛选历史、下载、删除历史，以及把历史资产作为一个全新且独立的节点插入当前画布。后端不负责创建节点、不定位画布节点，也不对重复添加去重。

## 已有 OpenAPI 契约

当前 `frontend/src/api/openapi.json` 已声明：

```http
GET    /api/canvas-documents/{canvas_id}/generation-history
DELETE /api/canvas-documents/{canvas_id}/generation-history/{history_id}
```

GET 查询参数：

| 参数 | 约定 |
|---|---|
| `target_canvas_id` | 必填。需要后端明确其与路径 `canvas_id` 的关系，尤其 A 画布查看 B 历史的场景。 |
| `type` | `all`、`image`、`video`、`audio`，默认 `all`。 |
| `limit` | 1–200，默认 50。 |
| `cursor` | 可选游标。 |

响应模型为 `{ items: CanvasGenerationHistoryItemOut[], next_cursor: string | null }`。条目必需字段为 `id`、`canvas_id`、`type`、`asset_id`、`created_at`、`asset`；`type` 只允许 image/video/audio。`asset` 使用 `AssetSummaryOut`，包含 `id`、`name`、`media_type`、`availability`，可选的缩略图、预览、封面、原文件、下载地址、宽高、时长和文件大小。删除接口要求 `target_canvas_id`，成功响应为 204。

当前前端请求会传 `target_canvas_id`、`type` 和 `limit=50`，列表 API 收到分页游标参数，但目前前端没有继续请求 `next_cursor`。为使契约端到端可用，需要前端后续完成分页消费；后端仍需保证分页游标稳定、记录不会因分页丢失或重复。

## 后端必须补齐或明确的能力

### 1. 成功结果自动登记

登记必须由服务端在生成/编辑确认成功后完成并持久化，不能依赖浏览器回调，也不能从当前画布节点推导。最低范围：

- 图片、视频、音频生成：每个成功的媒体结果单独一条历史记录。一个全成功批次产生 N 条记录。
- 图片/视频/音频二次编辑的每个新产物单独登记，例如局部重绘、生成式编辑、扩图、裁剪等。原结果记录保留。
- 不登记文本生成、上传素材、导入素材、普通资产库素材、失败任务。
- 部分失败批次不登记任何结果，即使其中有成功子项；只有 `success_count == total_count` 且 `fail_count == 0` 的批次才登记。
- 确认所有画布生成入口和二次编辑入口都能把可信的来源画布关联到产物。OpenAPI 中图片基础编辑请求和编辑结果上传请求可带 `canvas_id`；需检查其他编辑/生成链路是否也有可验证的画布关联。

### 2. 持久化与节点生命周期解耦

- 历史记录在刷新和重新登录后仍存在，并按来源画布查询。
- 删除或替换节点、节点结果回填、运行任务清理均不得级联删除历史。
- 历史删除只移除历史索引/可见性；底层资产、存储文件、已引用该资产的节点均保留。
- 若用户删除历史后发生任务重放、Run reconcile 或后台对账，该记录不得重新出现。
- 明确旧任务/旧生成结果是否回填。若不回填，需告知适用的起始时间；若回填，需保证规则与新生成记录一致且不会误收录上传、文本或部分失败批次。

### 3. 查询语义、排序与分页

- 明确 `canvas_id` 路径参数与 `target_canvas_id` 的用途和校验方式。产品语义是用户在 A 画布弹窗切换至同项目 B 后，读取 B 的历史；点“添加”仍由前端插入当前 A。读取/删除必须作用于明确的来源画布记录。
- 只能查询用户有权访问的画布；跨项目画布不得被枚举或读取。`target_canvas_id` 的校验不得让请求方以目标画布绕过来源画布权限。请在 OpenAPI 描述两个参数并更新接口文档。
- `type=all` 返回全部三种支持媒体，类型筛选准确；永不返回 text。
- 列表按**生成/编辑结果成功时间倒序**稳定排序，不应按任务创建时间或普通登记时间替代。`created_at` 当前 OpenAPI 说明“登记时间（北京时间）”，请确认其业务语义与产品要求相符，并规定带时区的 ISO-8601 格式。
- `limit`、`cursor`、`next_cursor` 必须可连续遍历完整历史，游标应在相同排序下无重复、无遗漏。
- 对已删除记录不返回条目；不允许资产全局去重导致同一媒体在不同画布的合法历史丢失。

### 4. 删除语义与幂等

- 校验当前用户对来源画布及该条历史的删除权限。历史 ID 不存在或不属于来源画布时返回符合统一错误规范的 404/403，不泄露其他用户数据。
- 删除操作只删除历史索引/记录，不得删除资产文件、资产库记录或画布节点引用。
- 明确重复删除行为（建议幂等 204），并保证删除状态不会被事件重放或对账恢复。
- 在 OpenAPI 或后端 API 文档写清楚上述副作用边界；仅声明 204 响应不足以表达该契约。

### 5. 资产展示、重新加入和下载数据

- `asset.id` 必须与条目 `asset_id` 相同，`media_type` 必须与 `type` 相符。
- 历史可添加条目必须有可访问的稳定资产引用，并确保 `availability` 为可用状态；若资产不可访问，需约定过滤或明确错误状态，不能让用户得到无法添加的记录。
- `preview_url`/`thumbnail_url`、`poster_url`、`original_url`、`download_url` 的用途及鉴权/有效期必须明确。短期签名地址不能作为重新登录后的唯一资产身份；客户端需可通过资产 ID 重新解析有效地址。
- 资产历史详情与资产库详情一致。目前 `AssetSummaryOut` 是摘要，不含完整生成提示词、模型和生成参数；请确认前端应通过 `GET /api/assets/{asset_id}` 取完整详情，或在历史响应中提供兼容的详情数据。
- 下载路径要适用于画布生成与编辑产生的资产。若这些结果没有现有 creation image/video/audio ID，需保证 `GET /api/assets/{asset_id}/download` 或 `download_url` 可用，并明确前端应使用哪种方式。

### 6. 幂等与数据完整性

- 生成成功事件、异步回调、Run reconcile、任务重放不得重复建立同一结果记录。建议使用稳定的结果资产 ID 加来源 Run/编辑结果 ID 做幂等键。
- 不按 `asset_id` 全局去重：同一资产若在不同画布分别产生合法记录，应保留各画布的记录。
- 同一画布批量生成 N 个成功结果，按每个产物稳定地产生一条记录；同一批次的部分失败不得产生记录。
- 历史记录的删除状态必须独立于生成任务状态保存。

## 联调验收清单

请后端逐项提供测试结果或可复现请求：

1. 成功生成一张图片、一个视频、一个音频，各出现一条对应历史；各类型筛选正确，时间倒序。
2. 四张图全成功产生四条独立记录；3 成功 1 失败的批次不产生任何记录。
3. 文本生成、上传、导入、失败任务均不产生历史记录。
4. 删除原节点后记录仍存在；刷新、重新登录后仍存在。
5. 对结果执行局部重绘、裁剪/扩图等二次编辑，新结果产生新记录，源历史仍可见。
6. 删除一条历史后它不再出现，但已有画布节点、资产详情、下载仍可用；任务重放后也不重新出现。
7. 同一项目 A/B：从 A 请求 B 的历史成功；在 B 来源记录上执行删除仅影响 B；对跨项目或无权限画布请求应拒绝。
8. `limit` 与 `cursor` 可遍历超过一页的数据，无重复、无遗漏；新记录插入时游标行为稳定。
9. 图片、视频、音频卡片预览、详情、重新加入所需资产字段及下载均有效；过期预览 URL 可重新获取。
10. 检查旧记录回填策略，并明确回填时间范围及排除规则。

## 请后端交付时附上的信息

- 数据表/迁移和索引说明（不需与前端字段同名，但需能说明历史索引独立于资产及节点生命周期）。
- 各生成、编辑入口的登记点及来源画布解析方式。
- 批次全成功判断、幂等键和删除墓碑/软删策略。
- `canvas_id` 与 `target_canvas_id` 的语义、跨项目权限校验方式。
- 旧任务是否回填。
- OpenAPI 中 `created_at` 时区/语义、分页、资产下载和完整详情的最终契约。
- 上述联调验收的请求、响应和验证结果。
