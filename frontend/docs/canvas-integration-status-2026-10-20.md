## 一、边界不变

- 独立项目包含多张画布，项目名称与画布名称分离，不采用画布树替代项目。
- 自由画布不要求选择或绑定任何视觉风格，不传虚构风格、不使用默认风格绕过项目创建约束。
- 契约完整的能力直接对接；缺失参数不猜测，不以旧生成、模拟成功或临时媒体地址冒充正式闭环。
- 分享任何保存状态均可复制，不触发保存；链接打开本站 `/share/canvas/:token`，展示服务端已保存版本。
- 后端材料中其他前端仓库的实现说明，不作为当前仓库已经完成的证据。

## 三、请后端只补这些内容

“待确认”表示现有交付材料不足以安全接线，不断言后端尚未实现。以下不再重复索要已明确的保存幂等、资产四态、导入幂等、项目首张画布原子性、排序请求体及上传归属。可转发后端的精简版本见 [剩余交接事项](canvas-backend-followup-2026-10-20.md)。

| 优先级 | 仍需后端交付 | 前端后续动作 |
| --- | --- | --- |
| 项目入口 | 现协议 `visual_style` 必填且不允许空值，不符合产品边界。需允许自由画布省略风格且不默认绑定，明确 `project_type` 合法值、最小创建请求/响应和项目列表类型区分；项目复制需保留画布父子关系 | 接首页正式项目生命周期，验证项目/画布独立名称和原子首张画布；不复用视频类型，不用自定义风格绕过 |
| 新生成与编辑 | 现有文本/图片/视频/音频自由节点如何映射 Run 的提示词—配置—结果拓扑；文本及图片/视频编辑的创建、源/结果资产关系、参数、终态恢复样例 | 接创建、查询/取消、刷新恢复和结果回填；编辑结果新增节点，保留源节点，不改既定交互 |
| 分享导入 | 现协议未提供目标项目参数，默认个人归属不满足需求；需明确目标项目参数、权限、响应和导航依据 | 接入指定项目的导入操作；不先导入个人再猜测迁移；已补幂等键，无需重复新增 |
| 联调材料 | 同步新增路径和模型至 OpenAPI；提供无敏感凭证的环境/版本/迁移状态及复杂文档、冲突、资产四态响应样例 | 真实保存重开、冲突、分享及跨域验收；不以端点列表作为验收证明 |

已吸收的新约定：创建项目首张画布失败原子回滚；项目删除级联软删画布；排序按 `sort_order` 升序、新建 max+1、复制继承；保存幂等先于版本校验且指纹不含 `base_revision`；Run 创建幂等包含类型/目标/版本；reconcile 只读并返回未对账任务；分享资产超过200返回422而非截断；同账号跨项目可解析，跨账号无权限不泄露名称/地址。

## 四、下一步顺序

1. 用真实画布验收本轮保存→关闭重开→组合/连线/参数/资产恢复，验证409和响应丢失重试；不需要先完成全部项目管理。
2. 后端提供无风格画布项目的合法最小请求后，接首页真实项目入口，再验收项目内多画布管理。模拟编号无法用于真实分享或项目永久上传，不能靠取消前端检查解决。
3. 排序接口已准备，待确认排序交互后接页面；上传项目归属已接，使用正式项目单独验收，不再等待后端补这两个契约。
4. 并行补齐上表自由节点任务映射和导入目标；各项完整后单独接线，不要求产品规则让步。
