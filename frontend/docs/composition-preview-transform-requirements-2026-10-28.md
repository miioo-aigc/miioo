# 剪辑轻量视频预览与素材构图需求

日期：2026-10-28。状态：产品交互规则已逐项确认；以下接口为本需求定义的目标协议，待后端实现、联调与验收，并非现有接口已具备的能力。本文不表示功能已经开发完成。

## 1. 需求背景与目标

剪辑中央预览改用原视频后，清晰度提升，但大文件下载明显拖慢起播。直接使用现有低清预览又可能出现清晰度不足、比例不匹配的问题。需要以独立、保持原始显示比例的轻量预览视频提升加载体验，以原文件完成最终导出。

已实测新附件视频为864×496，不是严格16:9；前5秒未检测到固定内嵌黑边。该素材完整放进16:9画布会产生左右留边。用户另确认1280×720视频进入轨道后已无黑边。因此不能把所有留边归结为剪辑修改了素材比例，或未经证实认定后端转码错误。

目标：默认状态消除比例不匹配造成的画布留边；允许用户主动调整构图；前端预览与后端导出的内容、位置、遮挡和变形一致。预览压缩不得改变素材显示比例。此处“无黑边”指素材未覆盖画布的留边，不承诺自动识别、去除源文件画面内部已经存在的黑色内容。

## 2. 范围与已确认产品规则

适用剪辑页面视频轨道中的视频和图片，每份时间线片段独立记录构图，同一资产多次使用互不影响。视频使用最高720p的压缩预览，图片继续使用原图；视频导出用原视频，图片导出用原图。

本期提供平移、四角等比例缩放、四边非等比例形变，不包含通过拖动控制杆实现镜像翻转。仅支持单个片段的画面变换，多选保留既有批量操作，不显示编辑框及恢复默认铺满按钮。

### 2.1 默认构图与旧草稿

- 新添加的图片、视频：居中、等比例铺满画布，画布之外的内容裁去，不拉伸不变形。比例差异较大时裁切也可能较大，不存在已确认的裁切百分比上限。
- 无留边只约束默认初始状态。用户主动缩小、平移或形变后允许露出背景，不强制纠正。
- 旧草稿没有构图参数的片段：保持旧版完整显示规则，居中等比例适应画布，不因升级自动裁切。
- 黑色画布底色保留。所有可见图层都未覆盖的位置显示黑色。

### 2.2 编辑框与拖拽

编辑框标出素材变换后的完整真实外框，而不是成片画布外框。复用现有图片裁剪弹窗的边框、控制点视觉样式；不能直接复用其移动裁剪区域的业务逻辑。

| 操作 | 行为 |
|---|---|
| 拖动编辑框内部 | 平移素材 |
| 拖动四个角 | 固定对角位置，保持拖拽开始时的当前宽高比缩放；已形变素材不自动恢复原比例 |
| 拖动左右边中点 | 固定对边，单独改变宽度 |
| 拖动上下边中点 | 固定对边，单独改变高度 |
| 控制点接近对边 | 不允许越过对边，不产生负宽高或镜像 |

选中时临时缩小整个编辑视图，让成片画布和素材完整外框均可见、八个控制点可操作。画布外素材内容变暗，明确表示不导出；画布边界保持清晰。拖拽期间冻结编辑视图倍率，结束后才可重新适配；取消选中恢复正常预览。编辑视图倍率不写入素材构图和导出参数。用户将素材移到远处或放大后，需在拖拽结束时重新纳入可编辑视图。

### 2.3 选中、指针与播放

- 保留现状：点击轨道片段时，指针跟随鼠标跳到点击的时间位置，而不是统一跳到片段起点。进入画面编辑状态时暂停播放。
- 指针已位于某片段时间范围、但片段未选中时，双击画布选中鼠标位置命中的最上层、未隐藏且未锁定的图片或视频片段；保持时间位置，暂停，展示编辑框。空白背景不选中。
- 双击命中时退出多选，转为单选。
- 多轨道按真实层级叠加，上层未覆盖处显示下层。轨道直接选中下层素材后展示其编辑框，不临时置顶，不改变真实遮挡。命中计算必须排除画布外仅用于编辑的暗显内容。
- 再次播放隐藏编辑框，保留选择；暂停后仅当所选片段在当前时间可见时显示其编辑框。播放状态采用正常预览视图。
- 编辑框、控制点、暗显区域和加载动画不写入成片。锁定状态的素材参与显示与导出，但不能通过画布选中或编辑。

### 2.4 恢复默认铺满与画布比例切换

右侧信息区在单选图片或视频片段时显示“恢复默认铺满”。点击仅重置当前片段的位置、缩放和形变，恢复居中等比例铺满；不弹确认，支持撤销。旧版片段执行后转为新规则。

切换成片画布比例时，新规则下的全部片段重新自适应，包括已手动调整的片段；旧版未迁移片段继续完整显示。存在手动调整时先提示“切换画面比例将重置素材构图，是否继续？”，取消不做修改，无手动调整直接切换。整次切换支持一次撤销，恢复原比例和全部片段构图。

### 2.5 加载、缓冲与重试

视频预览未就绪时，暂停整个时间线及全部声音，保持当前指针位置。保留已显示画面，首次加载用封面兜底；在中央成片预览区域中心显示现有 `src/components/LoadingAnimation.jsx` 动画，明确告知正在加载，不使用此前建议的旋转圆圈。多层同时等待时只显示一份中央加载提示。

| 状态 | 前端行为 |
|---|---|
| 预览生成中 | 每3秒查处理状态，单轮最多等60秒；就绪后自动加载 |
| 已就绪但视频加载失败 | 额外自动重试3次，分别间隔1、2、4秒；每次重新获取地址 |
| 超出等待或重试限额 | 停止动画，保留封面/已有画面，显示“预览视频暂不可用”和“重试”按钮 |
| 手动重试 | 开始新一轮状态获取、生成等待或播放加载重试 |
| 切换素材或离开页面 | 取消已不需要的请求、计时和续播意图；仍参与当前合成的其他图层不受影响 |

不自动改用原视频，不以低清缩略视频或不合格比例文件兜底。播放中缓冲耗尽、无法继续绘制同步画面时，也暂停全部时钟与声音并显示中央动画；仅等待元数据不能算加载成功，需在目标时间有可显示的解码帧。

用户原本在播放，全部所需可见图层及声音就绪后自动续播；等待期间主动暂停、拖动指针或切换素材，取消原续播意图，以最新操作为准。重试耗尽保持暂停，不跳过片段。图片仍为缩略图临时兜底、原图完整加载后替换；不新增压缩预览图需求。

## 3. 视频预览文件要求

1. 后端在视频入库时异步生成，覆盖上传、分镜生成及其他可进入剪辑的来源。历史素材按需触发补生成，同一资产版本任务去重。
2. 最高720p：以完成旋转和像素比例校正后的显示尺寸为准，长边不超过1280、短边不超过720，且不放大低分辨率源。横向16:9为1280×720，竖向9:16为720×1280。
3. 保持完整画面和显示宽高比，不预先做铺满裁切、不加黑边、不拉伸。864×496可保持864×496并压缩码率，不能因标记为480p而改成另一个比例。
4. 编码尺寸取整不得导致显示比例变化；必要时用正确的像素宽高比标记，使浏览器最终显示比例与原素材一致。禁止用改变画面内容的补边方式凑尺寸。接口须返回明确的显示比例，不能仅提供清晰度档位。
5. 保持时间轴起点、完整时长、画面方向和音画同步。前后端统一按已校正方向和像素比例的显示空间计算构图。
6. 目标格式为浏览器兼容MP4/H.264、音频存在时AAC，启用faststart。播放地址支持Range、206、Content-Type、Content-Length及必要CORS；不能要求前端完整下载成Blob才能起播。
7. 地址具备可用有效期且可刷新；媒体鉴权通过短期签名或同源安全会话完成，不把长期访问令牌暴露在媒体地址中。
8. 本期不承诺固定秒数起播：文件大小、码率和起播耗时须在联调阶段以同源原视频/预览的测试记录核对。具体码率、关键帧间隔和量化性能门槛尚未由产品确认，不写成已确认指标。

## 4. 统一构图协议与计算规则

### 4.1 时间线扩展

在现有时间线的每个图片/视频片段增加 `visual_transform`，作用于片段而非资产。音频和字幕不使用此字段。旧字段 `clip_id/start/duration/offset/track/speed/has_audio` 等保持现有语义。

```json
{
  "type": "video",
  "clip_id": "asset-id",
  "start": 0,
  "duration": 5,
  "offset": 0,
  "track": "V1",
  "speed": 1,
  "has_audio": true,
  "visual_transform": {
    "version": 1,
    "mode": "cover"
  }
}
```

| mode | 语义 |
|---|---|
| 字段缺失或null | 旧草稿兼容，等同legacy_contain |
| legacy_contain | 居中等比例完整显示，随画布变化继续完整显示 |
| cover | 新片段默认，居中等比例铺满；随画布变化重新计算 |
| manual | 用户手动构图，使用下述坐标；切换画布比例时由前端确认并将新规则片段重置为cover |

手动构图示例：

```json
{
  "version": 1,
  "mode": "manual",
  "center_x": 0.5,
  "center_y": 0.5,
  "width": 1.2,
  "height": 1.1
}
```

坐标原点为成片画布左上角，X向右、Y向下。center_x、width以画布宽度归一化，center_y、height以画布高度归一化；不使用浏览器视口、编辑视图或压缩文件像素作基准。中心允许超出0～1，宽高允许大于1，均为有限数值且宽高必须大于0。服务端不得把合法越界位置截成0～1。资源保护上限由后端提出并联调对齐，不得静默钳制导致预览、导出不同。

画布宽高为Cw、Ch，源显示比例R，铺满时：

```text
cover：H = max(Ch, Cw / R)，W = H × R
contain：H = min(Ch, Cw / R)，W = H × R
二者均居中：X = (Cw - W) / 2，Y = (Ch - H) / 2
manual：W = width × Cw，H = height × Ch
X = center_x × Cw - W / 2
Y = center_y × Ch - H / 2
```

后端根据原素材的显示空间映射到该矩形，manual允许非等比例缩放。前端根据预览素材映射到同一矩形；最终都裁在画布边界。显示比例来源必须是可信元数据，禁止从封面尺寸推断。所有参数保留浮点精度，最后光栅化时再取样，禁止前端保存取整后的视口像素。

### 4.2 保存、撤销和迁移

- 平移、缩放、形变拖动实时预览，拖拽完成后纳入现有自动保存；一次拖拽对应一次撤销，不能每次mousemove增加历史记录。
- 保存的是片段构图，不是signed URL、Blob URL、缩略图地址或编辑视图倍率。
- 后端读写原样保留合法构图字段。缺失字段按旧规则解释，不批量重写历史草稿。旧片段手动调整后转manual；执行恢复默认铺满后转cover。
- 新增片段必须显式写cover，不能依赖后端把缺失字段解释为新默认。草稿复制、刷新恢复须保留构图；片段切分继承同一构图，两个新片段后续独立调整。

## 5. 后端接口需求（目标协议）

沿用现有资产身份、项目访问权限与成片接口。新增预览专用接口，不复用含义不明确的缩略图/下载地址。下述路径与字段由本需求直接定义。

### 5.1 获取剪辑预览信息

`GET /api/assets/{asset_id}/composition-preview`

登录鉴权并校验资产访问权限；图片可返回原图信息，视频返回预览状态。示例为视频ready：

```json
{
  "asset_id": "asset-id",
  "asset_type": "video",
  "source_version": "immutable-version",
  "source": {
    "coded_width": 1920,
    "coded_height": 1080,
    "display_aspect_ratio": { "num": 16, "den": 9 },
    "duration_seconds": 5,
    "has_audio": true
  },
  "poster_url": "https://media.example/poster.jpg",
  "preview": {
    "status": "ready",
    "url": "https://media.example/preview.mp4?signature=example",
    "expires_at": "2026-10-28T12:00:00Z",
    "coded_width": 1280,
    "coded_height": 720,
    "display_aspect_ratio": { "num": 16, "den": 9 },
    "duration_seconds": 5,
    "has_audio": true,
    "mime_type": "video/mp4",
    "size_bytes": 1000000,
    "error": null
  }
}
```

`display_aspect_ratio`表示完成旋转和像素比例校正后的显示比例，分子分母为正整数；源与预览必须一致。`source_version`绑定原文件版本，源变化后旧预览立即失效，不能返回其他版本的视频。状态为 `pending/processing/ready/failed`；非ready时url为null，尺寸等未就绪字段可为null；failed返回可展示的中文error.message及稳定error.code。示例大小仅为协议示例，不是性能指标。

图片返回asset_type=image，source提供原图的编码尺寸和校正方向后的显示比例，视频专属时长/音频字段为null；另返回 `original_image_url` 和 `original_image_expires_at`，preview为null。图片不触发视频预览处理。

成功HTTP 200；不存在404、无权限403、登录失效401、处理服务暂不可用503。响应 `Cache-Control: no-store`，确保重取可刷新签名；不能只返回已过期的缓存地址。原视频无需返回供前端自动回退。

### 5.2 创建或重试视频预览任务

`POST /api/assets/{asset_id}/composition-preview`，请求体 `{}`。返回HTTP 202及与GET相同的状态结构；已有可用预览时HTTP 200直接返回ready，已有进行中任务时复用，不重复排队。

资产入库自动触发为主；前端首次查询pending历史素材或用户手动重试failed时调用POST，再按3秒间隔GET等待。播放加载失败时先GET刷新地址，不应每次都重做转码；只有服务端明确failed且需重建时才POST。

错误格式统一：`{"code":"PREVIEW_GENERATION_FAILED","message":"预览视频处理失败，请重试","retryable":true}`。资产非视频返回422 ASSET_TYPE_UNSUPPORTED。任务应有超时终态，不能永久processing。

### 5.3 草稿创建、保存与读取（扩展已有接口）

- `POST /api/projects/{project_id}/compositions`：在timeline片段中接收visual_transform。
- `PATCH /api/projects/{project_id}/compositions/{comp_id}`：同样接收并持久化；画布aspect_ratio和重置后的完整timeline必须一次原子更新，不能先改比例再另存构图。
- `GET /api/projects/{project_id}/compositions?episode_id={episode_id}`：返回的各草稿timeline完整包含已保存的visual_transform，保证刷新、重进和复制后不丢失。当前前端以工程列表恢复草稿，不要求新增单草稿GET。
- 非法版本、缺少manual坐标、非有限数或非正宽高返回422，code为INVALID_VISUAL_TRANSFORM，附具体timeline索引和字段名；不得静默忽略，亦不得保存一半。
- 保持既有音频、字幕、轨道设置和时间参数，不因为加入构图协议而改写。

### 5.4 成片渲染（扩展已有接口）

`POST /api/projects/{project_id}/compositions/{comp_id}/render`

前端先等待全部最新草稿保存成功再发起render，不另传一份可能冲突的构图请求体。后端从该草稿已保存timeline读取构图，接单时冻结工程快照，包括画布、全部片段、轨道设置及源文件版本；后续编辑不得改变已提交任务。沿用现有工程/任务返回结构与进度链路。

后端必须使用clip_id关联的原视频/原图，不使用预览视频、封面或缩略图渲染。根据统一构图矩形依次缩放/形变、定位、在画布范围裁切并按轨道层级合成，继续处理既有时间、速度、声音和字幕规则。素材隐藏不绘制、锁定不影响绘制；沿用当前层级定义，禁止前后端各自反转顺序。

有构图却不支持的服务端应明确返回422 UNSUPPORTED_VISUAL_TRANSFORM，不能成功导出却忽略参数。原文件不可用应明确失败，不静默换成预览文件。预览处理中不阻塞原文件已经可用的导出任务。

## 6. 前端实施边界

实施前基线：`src/components/compositionEditor/PreviewCanvas.jsx` 原按object-contain显示一个活跃画面，本期已升级为多层合成与编辑覆盖层；`src/stores/compositionEditorStore.js` 的片段、撤销历史和serializeTimeline已支持构图；`src/api/compositions.js`沿用timeline透传扩展。

预览元数据和任务请求放API层；预览重试、取消与播放时钟协调复用/扩展现有媒体加载与时钟逻辑；构图数学提取纯工具，编辑框放剪辑业务组件。禁止将取源、拖拽和合成全部堆入页面入口。

已实现的“优先加载原视频”是本需求之前的过渡行为，不能作为本需求验收标准；本期视频将改为明确使用合格预览地址，图片保持原图。只写需求文档不代表已修改这部分业务代码。

## 7. 验收标准

1. 1920×1080原片可返回1280×720预览；864×496源保持其原始显示比例；竖屏、旋转标记和非方形像素素材均无方向/比例错误，不以清晰度名称代替实测。
2. 新增864×496视频到16:9画布默认等比例居中铺满，无画布留边，圆形不被拉椭圆；1280×720素材同样不留边且无需裁去有效画面。
3. 图片原图加载完成后替换临时缩略图，视频首次预览不请求原片全量Blob；Range播放可从目标时间起播。
4. 四角、四边和内部拖动分别符合规则；选中时完整真实外框可操作，取消/播放后正常预览；调整面板宽度不改变保存的构图。
5. 手动缩小允许看到下层；无下层处显示黑底。非等比例形变在导出中准确保留。下层选中不置顶，隐藏/锁定和双击命中符合规则。
6. 同一素材多次使用分别构图；多选不显示编辑框；恢复按钮位于右侧信息区且仅作用当前片段。
7. 旧草稿保持完整显示；旧片段恢复铺满后采用新规则。切换画布比例重置所有新规则片段，确认、取消、一次撤销及刷新恢复均正确。
8. pending/processing、地址过期、网络失败及缓冲耗尽均按约定处理；中央LoadingAnimation可见，全部音画同步等待，无旧请求恢复错误素材的竞态。
9. 精确核对3秒/60秒等待与1、2、4秒三次重试；超限显示重试，离开后停止，任何失败均不自动下载原视频。
10. 对比同一源时间的预览与导出帧：画布内构图、可见内容、形变、层级及裁切边界一致；允许压缩清晰度差异，不允许额外裁切、位置跳变或图层遗漏。正常整数输出尺寸以1个输出像素内的边界取整差异作为联调核对目标，不把编码色差误判成构图差异。
11. 保存失败阻止新导出；导出冻结快照，编辑中的后续修改不污染运行任务；后端不支持参数时明确失败。

## 9. 前端实施记录（2026-10-28，待后端联调及手动验收）
