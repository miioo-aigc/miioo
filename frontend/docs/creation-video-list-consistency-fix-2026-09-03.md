# 创作视频列表与资产库数量不一致修复

## 问题现象

同一账号下，资产库「创作资产 → 视频」列表可以看到 18 个视频，但「创作 → 视频」创作列表少显示 1 个视频。缺失记录不是后端没有返回，而是在创作页的数据适配和 Store 合并过程中被错误合并。

## 根因

本次问题由两处列表口径不一致共同造成：

1. 两个页面的请求参数不同。创作页请求视频历史时传入了 `exclude_hidden=true`，资产库视频列表没有传入该参数，因此两边的候选记录集合可能不同。
2. 创作页对视频做了媒体地址别名去重。接口响应标准化和 Store 写入时，曾按视频地址、预览地址、封面地址等字段判断重复。不同的视频记录可能共用封面、预览地址或转码地址，导致两条真实记录被错误合并成一条。

因此，问题不能只按“列表分页数量不足”处理；需要同时统一查询口径，并修正视频记录的身份判断。

## 修复内容

### 1. 视频历史与资产库查询边界（2026-11-06 更新）

文件：`src/pages/CreationPage.jsx`

- 2026-09-03 曾统一两处查询范围；该规则已被2026-11-06确认的“清空历史但保留资产”需求替代。
- 视频创作首屏与后续分页均传入 `exclude_hidden=true`；资产库不传该参数，保留全部资产。清空历史后两处数量不同属于预期行为。
- 清空复用 `POST /api/creation/history/hide`，请求体为 `{ "tab": "video" }`，不限定分页，不调用删除接口；明确收到成功响应后重置列表、失效缓存及旧分页请求。
- 视频按后端记录编号去重的修复仍保留。图片、配音的历史过滤规则不变。

### 2. 按后端记录身份处理视频去重

文件：`src/utils/creationHistoryAdapter.js`、`src/stores/creationStore.js`

- 视频只有在后端记录 `id` 相同时才合并。
- 没有后端 ID 的不同视频不会再因为媒体地址相同而被吞掉。
- 图片和配音继续沿用原有的媒体别名去重规则，避免改变其他类型历史数据的既有行为。
- 保留刷新后仍在执行任务的 loading 占位卡恢复逻辑。

## 维护边界

- 视频记录的唯一身份以后端记录 ID 为准，视频地址、预览地址和封面地址只用于展示或播放回退，不可作为视频记录的唯一键。
- 列表接口或适配层新增媒体地址字段时，不能把该字段直接加入视频去重键，除非后端明确保证它代表唯一创作记录。
- 若创作页与资产库再次出现数量差异，应先对比请求参数、分页响应原始条数、标准化后的条数和 Store 合并后的条数，定位记录在哪一层被过滤或合并。
