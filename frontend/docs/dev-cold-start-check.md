# 开发环境冷启动检查

更新日期：2026-09-28

## 背景

剧本页面曾出现入口请求成功、内部编辑器依赖返回 504 的问题。生产构建不经过相同的开发预构建流程，不能单独作为此类故障的验收依据。

## 验收命令

```bash
npm run check:dev-cold-start
npm run lint
npm run build
npm run check:architecture
git diff --check
```

新增或修改页面、动态导入、依赖及锁文件、Vite 配置后执行。当前命令已加入本地验收入口，但没有接入远程持续集成，不会自动在每次提交时运行。

## 检查范围

- 先运行检查器单元测试，覆盖依赖 504、旧地址失效、语法错误、网络异常、HTML 回退和循环引用。
- 自动发现 `src/pages` 下的 `.jsx`、`.tsx` 页面，并检查应用入口 `src/main.jsx`。
- 读取项目实际 Vite 配置，使用系统临时目录中的全新缓存，不复用或删除 `node_modules/.vite`。
- 使用 `127.0.0.1:5187` 独立服务，不打开浏览器。端口被占用时直接失败，不停止现有进程。
- 通过实际 HTTP 请求递归检查静态导入、转导出及字面量动态导入，保留依赖版本查询参数。
- 遍历完毕后重新请求原始模块地址，检测后续预构建是否使旧地址失效；不自动重试 504 来掩盖失败。
- 失败时输出模块地址、导入来源和阶段，返回非零退出码；正常或异常结束均关闭服务、删除本次临时缓存。

## 失败处理

先定位失败的模块及其来源，区分服务启动、代码转换、依赖预构建、模块不存在等原因。遇到新依赖的预构建问题时，确认根因后再更新 `vite.config.js` 的 `optimizeDeps.include`，不要通过反复刷新或清缓存把偶发恢复视作修复。

## 边界

这是开发服务器模块加载检查，不执行浏览器中的 React 组件，不验证登录、后端接口、交互或视觉效果。非字面量动态导入、运行时创建的地址和浏览器缓存状态不在本检查覆盖范围内；外部模块或未转换的裸导入会显式报错。仍需手动验证“画布 → 剧本解构 → 返回画布”等关键流程。

首次验收：12 个页面、543 个模块加载和原始地址复查通过。此数量随项目变化，不作为固定断言。
