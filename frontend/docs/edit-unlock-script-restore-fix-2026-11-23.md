# 剧本恢复导致剪辑导航误锁

状态：本地代码修复，待用户跨设备手动验收；未提交、未部署。

## 原因与证据边界

首页原先将 `scriptEpisodes` 同时用于剧本展示与剪辑解锁。剧本页恢复结构工作区时，`onEpisodesChange` 会用结构分集替换该列表，状态可能回到 pending；该回调还递增剧本编辑版本，使详情加载中的 `scriptUnchanged` 为假，跳过正式分集状态接纳。两种返回顺序都可能使服务器已返回 editing 的分集失去剪辑入口。

这是已由代码和定向测试确认的前端缺陷；未读取用户现场接口，不能据此断言服务端没有其他问题。

## 修复

首页新增独立的 `confirmedEditingEpisodes`，只接纳当前项目、当前会话、当前读取版本的服务器分集结果及开始剪辑接口确认结果。剧本编辑版本保护仍用于正文和剧本展示列表，不再阻止剪辑进度接纳。导航和剪辑页共享此列表；取消读取和重新加载时清空确认状态。开始剪辑成功后按分集 ID 更新或追加确认记录。

保持 editing/edited 的按分集解锁规则，不根据本地标记或草稿数量推断解锁，不自动写服务器补状态。页面保留请求、会话与导航编排，本次没有新增组件或迁移 UI。

本文补充 2026-11-03 的修复记录：其中共享 `scriptEpisodes` 且受 `scriptUnchanged` 限制的实现已被本次独立确认列表替代。
