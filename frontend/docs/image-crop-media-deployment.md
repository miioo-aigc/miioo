# 图片裁剪媒体代理部署

更新日期：2026-10-12。

## 修复范围

图片裁剪编辑器读取 `https://www.chengxvblog.top/media/origin/` 图片时，统一转为本站 `/__image-media/media/origin/` 请求。本地由 Vite 代理；生产必须由站点网关代理，不能仅发布静态资源。原始素材地址、业务提交和其他媒体流程不变。其他域名仍需自行提供跨域许可。

保留图片的跨域读取声明，保证画布可以导出。不能用取消声明、禁止跨域检查或不透明请求替代代理。

## 生产部署前提

仓库不包含线上服务器管理权限；以下配置尚未在线部署或验证。

1. 将 `deploy/image-media.nginx.conf` 的规则加入前端站点的 Nginx `server` 块。此路径不能落入单页应用的 HTML 回退规则。
2. 根据服务器系统调整受信任证书包路径，保持上游证书验证开启。示例路径适用于常见 Debian/Ubuntu 环境。
3. 检查配置并重新加载网关，再发布前端。网关先发布可避免新前端遇到缺失路由。
4. 代理必须服务端获取图片字节，不能重定向浏览器到外部域名。检查上游是否有重定向；如有，应由运维配置固定、可信的最终上游，不允许任意 URL 转发。
5. 若生产不是 Nginx，也需部署同等路由：固定 HTTPS 上游、只读方法、保留路径与查询参数、不转发站点凭据、不回传上游 Cookie。不要建立可请求任意地址的开放代理。

## 验收

- 本地重启开发服务后，在素材详情打开原来失败的图片，完成裁剪和保存，确认保存结果可再次打开。
- 在线上重复同一流程；网络请求应为本站 `/__image-media/media/origin/...`，响应为真实图片，不能是 HTML、登录页或外域重定向。
- 验证本地上传图片仍可裁剪，第三方图片地址不会被误改写。
- 本次不自动打开浏览器，交互和线上发布后验收由用户执行。仅构建通过不代表线上代理已部署成功。
