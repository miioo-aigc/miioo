# 图片与视频编辑前后端需求交接

日期：2026-09-15

状态：产品范围已确认；本文中的字段、枚举及接口组织为待前后端落地的契约建议，不表示接口已实现。具体模型 ID 由后端依据实际服务商配置提供。

## 1. 目标与范围

- 编辑生成新资产，保留原资产，不覆盖原文件、不自动替换定稿。
- “原目录”指业务归属：继承源素材所在主体、分镜或创作记录，出现在对应候选列表、结果列表及关联资产入口；不要求文件存储在同一物理目录。
- 业务归属由后端持久化，不能仅由浏览器 IndexedDB 维护；刷新、换设备后仍可从接口查询。
- 源素材可以是先前的编辑结果；每次保存直接父资产关系，并保留最初来源以支持追溯。
- 视频编辑面向平台已有视频，不新增本地视频上传入口。选帧的操作类型为视频编辑，但输出类型为图片。
- 适用于主体候选图、分镜候选图、创作结果、项目主体资产、项目分镜资产、创作资产及相应视频详情入口。

## 2. 公共请求与结果契约

### 2.1 请求字段建议

| 字段 | 约定 |
|---|---|
| `edit_type` | `image_edit` 或 `video_edit`，表示用户发起的编辑操作类别 |
| `edit_mode` | 使用第 3 节稳定枚举，不能使用界面中文作为路由依据 |
| `source_asset_id` | 原始源资产的真实编号，不得用主体、分镜或候选记录编号替代 |
| `model` | 生成类请求携带后端提供的真实模型 ID；上传保存、抽帧保存和确定性剪辑不需要模型 |
| `prompt` | 仅多机位、局部重绘和扩图按各自规则提交；其他模式不传 |
| 操作参数 | 按第 4 节提交，字段放置需在接口契约中固定 |
| 幂等标识 | 每次用户确认操作生成独立标识；网络重试沿用，主动再次生成使用新标识 |

接口可以复用现有生成入口或单独提供编辑入口，但同一模式的验证、提示词策略与归属规则必须唯一。不能以传入 `edit_type` 代替权限校验。

后端从源资产及其关系解析目标归属。如果一个资产存在多个业务挂载位置，允许前端额外传经校验的来源上下文标识以消除歧义；不得由前端传服务器路径或任意指定他人归属。

### 2.2 结果字段建议

结果至少提供 `asset_id`、`media_type`、`source_asset_id`、业务归属、`edit_type`、`edit_mode`、`show_prompt`、`prompt`、原始文件地址、预览地址、宽高、创建时间；视频还提供封面、时长及可用音轨信息。字段命名应与现有资产契约保持一致，新增字段统一约定。

- `show_prompt` 由后端根据模式推导，客户端不得覆盖。
- `show_prompt=false` 时，普通业务响应中的 `prompt` 统一为 `null`，不得在其他面向用户的元数据字段中泄露内部生成提示词。
- `show_prompt=true` 时，仅返回用户填写的提示词，不混入系统补充、供应商包装或继承源资产的旧提示词。
- 内部执行提示词与用户展示提示词分开存储；隐藏展示不等于删除后端执行记录。
- 列表、详情、任务结果、历史恢复使用相同展示策略。旧资产没有编辑字段时继续沿用原展示逻辑。
- 前端按稳定枚举显示“编辑模式——对应中文名称”，不能根据提示词内容猜测模式。
- 选帧图片保留 `edit_type=video_edit`、`edit_mode=frame_extract`、`media_type=image`。

### 2.3 保存与任务生命周期

1. 校验登录权限、源资产可访问性、来源上下文、模型准入和参数。
2. 返回新资产或已受理任务编号；异步任务明确区分等待、执行、成功、失败和取消。
3. 成功时完成文件保存、资产创建和业务关系写入后再报告成功，返回资产及归属。
4. 前端按返回的新资产编号更新列表、展示结果；任务受理不能冒充“结果已保存”。
5. 幂等重试不重复计费、不生成重复资产；查询任务不重新提交生成。
6. 前端失败保留参数、蒙版及选区；已受理任务可在刷新后恢复。关闭弹窗不等于取消服务器任务。
7. 后端提供可识别的参数、权限、模型不可用、额度不足、源文件失效和处理失败错误；保存失败不得宣告任务完整成功。

## 4. 分功能职责与参数

### 4.1 多机位

- 前端：使用现有角度组件和固定提示词拼接逻辑，提交源资产、原图参考、角度生成提示词及固定模型 `sp-gpt-image-2`。
- 后端：按图片生成链路生成新图，保存源关系及归属；内部保留执行提示词，普通资产响应隐藏提示词。
- 前端结果详情仅展示“编辑模式——多机位”，不展示或自动回填内部提示词。
- 现状差距：目前按可用模型与来源参数选择模型，尚未固定本需求模型和统一编辑元数据。

### 4.2 局部重绘与消除笔

- 前端：提交源资产关联的原图、蒙版；局部重绘额外提交用户提示词，消除笔不提交提示词。两者显式区分 `edit_mode`，不得靠空提示词推断。
- 后端：两者调用 image-2 对应局部编辑能力；消除笔注入消除目标、自然补全背景的系统提示词；局部重绘保留用户提示词展示。
- 输出新增到来源业务列表；以蒙版外区域保持、边缘自然及主体一致性作为效果验收项，不把生成式处理描述为绝对像素无损。

蒙版统一协议（前后端实现依据）：

- 使用 PNG 灰度蒙版，宽高与方向规范化后的原图像素完全一致，不得使用界面缩放后的尺寸。
- 白色 255 表示编辑，黑色 0 表示保留；中间灰度表示边缘过渡，透明通道不承载区域语义，导出为不透明蒙版。
- 后端校验格式、解码成功、尺寸一致、有效编辑区域及文件大小，拒绝空蒙版和越界参数。
- 若供应商使用相反颜色或透明蒙版语义，由后端适配；前端不随供应商变化而反转。
- 优先复用现有 `mask_data_url` 接收 PNG；请求大小上限和超限处理在接口契约中明确，大文件可改用上传蒙版资产，不混用未声明格式。

现状：重绘和消除均调用 `/api/creation/images/{id}/erase`，原图经源编号关联，蒙版白色编辑/黑色保留。需要补模式、固定模型、展示策略和后端归属；不能认为现有接口已覆盖这些规则。

### 4.3 图片智能超清

- 前端：提交源资产、原图及目标分辨率；当前界面提供 2K/3K/4K，最终选项须核对 Seedream 5.0 能力。
- 后端：使用已确认 ID，内置保真增强提示词，保持原图主体、构图、色彩和文字，验证实际输出尺寸。
- 需约定 K 档位对应长边像素、比例保持、尺寸对齐和是否允许缩小；不只修改文件的分辨率标签。
- 内容不变是效果目标，生成模型不能保证绝对不改细节；效果不达标不能仅以尺寸达标验收。
- 现状：生成服务尚未接入。

### 4.4 图片扩图

前端提交原图、提示词及以下四个浮点字段，统一使用用户指定名称：

```json
{
  "up_expansion_ratio": 0.25,
  "down_expansion_ratio": 0.25,
  "left_expansion_ratio": 0.25,
  "right_expansion_ratio": 0.25
}
```

- 上、下分别为该边新增像素除以原图高度；左、右分别为该边新增像素除以原图宽度。
- 每项必须是有限数且在 `[0, 2]`，至少一项大于零。
- 总面积倍率 `(1 + left + right) * (1 + up + down)` 不超过 3；示例倍率为 2.25。
- 前端按真实输出几何计算，不使用显示缩放尺寸；后端再次校验、计算最终尺寸，并处理浮点容差和供应商尺寸对齐。
- 后端使用 Kling v3 已确认的扩图模型 ID；前端不再自动选任意支持扩图的模型。
- 用户提示词显示开启，模式为“扩图”；空提示词是否允许由后端能力契约明确。允许为空时仅在内部补默认词，展示不得冒充用户输入。
- 现代码使用 `top_expansion_ratio` / `bottom_expansion_ratio`，须改为 `up_expansion_ratio` / `down_expansion_ratio`。现代码左右对称、上下对称计算；未来允许移动原图时必须分别计算四边。
- 四个字段在请求体顶层还是 `expand_options` 内，由双方在正式接口示例中固定，避免不同入口各自组织。

### 4.5 图片裁剪与翻转

- 前端继续用浏览器导出真实结果文件；裁剪、旋转、水平/垂直翻转不使用生成模型。
- 提交结果文件、源资产编号、编辑类型及模式；建议附操作参数以便追溯，后端不得再重复应用变换。
- 后端校验文件内容、媒体格式、尺寸和大小，创建新图片资产并继承源业务归属。
- 上传成功后前端以远端资产替换本地临时结果；上传失败保留编辑结果供重试。
- 裁剪弹窗包含旋转/翻转时记录整体模式为裁剪；翻转弹窗整体模式为翻转，具体变换保存在操作参数中。
- 现状：主要为本地 PNG 和 IndexedDB 保存，需接入远端资产保存及归属。

### 4.6 视频智能超清

- 前端删除 2K 选项及相关默认值、草稿恢复、请求分支；仅保留 1080P 和 4K。
- 1080P 使用 HappyHorse 1.1，4K 使用 Seedance 2.0；模型系列不是 ID，必须确认真实视频参考子模型及目标输出能力。
- 提交源视频资产、目标分辨率和编辑标识，不提交用户提示词。
- 后端内置保真视频增强提示词；验收分辨率、比例、时长、帧率处理、动作连续性及音轨保留，不允许静默输出低档位并标记高档位。
- 后端若确认指定模型不能实现该能力，作为上线阻塞反馈，不擅自替代模型。
- 现状：界面仍有 1080P/2K/4K，尚未接入生成服务。

### 4.7 视频去字幕

阶段一：整段去字幕。

- 前端发送源视频资产、编辑标识和 `happyhorse-1.0-video-edit`，不发送用户提示词；源文件由后端读取，不要求重复上传。
- 后端内置去字幕提示词，处理原视频并保存新资产，验收字幕消除、背景一致性和音轨保留。
- 当前遮罩不参与模型请求，不能宣称能限制处理区域。推荐暂时禁用或隐藏范围操作；若保留预览，必须明确提示“当前按整段视频处理，框选区域暂不生效”。

阶段二：区域去字幕。

- 最终目标是按照用户遮罩限定区域处理。
- 前端提供相对于真实视频画面的归一化区域坐标；后端校验并适配区域蒙版能力。坐标必须排除播放器留白，旋转方向及全时段生效规则需固定。
- 具体采用模型区域能力或裁切/合成管线待技术验证；不得假定当前模型已有区域能力。
- 验收必须包含框选区域外保持效果，阶段一通过不代表阶段二完成。

### 4.8 视频选帧

- 前端沿用真实原视频解码，生成当前选中帧的原分辨率 PNG；新增保存到平台链路，不能把本地下载当成保存成功。
- 上传图片、源视频资产编号、编辑标识及所选实际帧时间（秒，便于追溯）。
- 后端创建图片资产，继承视频来源业务上下文，返回图片可用归属；图片应进入相应图片候选/图片结果入口，而不是混入只接收视频的列表。
- 保留源视频关联，不能因为输出是图片而把编辑类型改成图片编辑。
- 各来源上下文的视频转图片映射由后端明确；不支持时明确报错，不能仅落文件后丢失业务关系。
- 现状：仅下载 PNG，需增加上传、保存状态、错误处理和列表回填。浏览器解码失败要真实提示，不伪造成功。

### 4.9 视频剪辑

前端提交示例：

```json
{
  "edit_type": "video_edit",
  "edit_mode": "trim",
  "source_asset_id": "源视频资产编号",
  "start_time_seconds": 1.2,
  "end_time_seconds": 5.8
}
```

- 仅单连续区间，不扩展到多段拼接。当前选区精度 0.1 秒，前端内部整数单位提交时除以 10。
- 后端校验有限数、`0 <= start < end <= 原视频时长`，最短区间按当前产品约束为 0.1 秒。
- 约定时间区间为起点包含、终点不包含；真实裁剪按视频帧边界处理并返回实际结果时长。
- 推荐精确裁剪，必要时重新编码；不能未经说明回退到更早关键帧导致多保留前段画面。
- 保持画面方向、合理帧率和音画同步，有音轨则保留对应区间；返回新资产，源视频不变。
- 当前前端只选择/预览范围，保存为未接入提示；后端新增裁剪能力后前端接任务和资产回填。

## 6. 联调验收

- 每个模式验证真实请求模型、参数、源资产及实际返回媒体，不仅检查提示消息。
- 多机位等隐藏模式在列表、详情、任务结果中均不返回内部提示词；重绘/扩图只展示对应用户提示词及正确模式名。
- 六类图片来源及视频入口都验证原业务列表新增、刷新、换设备查询、再次编辑和原资产保留。
- 主体/分镜编辑结果不自动改定稿；选帧结果是可查询图片资产，归属不丢失。
- 蒙版黑白方向、尺寸、空蒙版、边缘过渡分别验证；用真实供应商确认语义。
- 扩图验证单边越界、总面积越界、零扩展、浮点边界和实际输出几何。
- 超清验证实际像素尺寸、内容保真；视频额外验证时长与音轨。
- 剪辑验证首尾边界、非关键帧起点、0.1 秒短区间、无音轨视频、音画同步及实际输出时长。
- 模拟网络中断、重复点击、刷新恢复、任务失败及保存失败，确认不重复计费、不产生重复结果、不虚报保存成功。
- 去字幕阶段一按整段处理验收；区域遮罩功能单独验收，未接通不能标记完成。
