## 目标与约束

- 将 `src/index.css` 中已注册的设计 Token 同步到 Paper，并在不改变既有视觉的前提下批量绑定到设计稿图层。
- 不逐个手动调整，但也不按颜色值进行无差别全局替换；仅绑定数值完全相等、且图层语义明确的属性。

- 本任务仅操作 Paper 设计文件，不修改本地代码、不提交、不推送。

## 暂不自动绑定的范围

| 类型 | 原因 | 后续处理方式 |

| 渐变 | 当前 Token 与实际渐变叠加关系可能不同。 | 按具体组件状态单独确认后处理。 |
| 图片和封面资源 | 不属于 CSS 设计 Token。 | 保留原有资源引用。 |
| 阴影和发光 | 需要结合组件层级判断，不宜按数值批量替换。 | 在弹窗、浮层和强调控件中逐类确认。 |
| 复杂按钮状态 | 同一视觉值可能承担默认、悬停、按下、禁用等不同语义。 | 以完整状态组为单位绑定，不拆散处理。 |

## 恢复执行流程

1. 确认 Paper MCP 周调用额度已恢复，并重新读取 Paper MCP 使用说明和当前文件基本信息。
2. 每次只选择一个画板检索图层，避免全局检索触发结果数量上限而遗漏内容。
3. 按“已确认的安全映射”批量绑定数值和语义都明确的属性；遇到用途不明确的深色背景、渐变或状态色时跳过。
4. 每批更新后抽样读取计算样式，确认设计变量引用已写入且解析值未改变。
5. 尝试获取截图进行视觉复核；若接口仍返回空结果，在本表记录并继续以计算样式作为替代验证。
6. 完成全部范围后结束 Paper 编辑会话，避免留下未关闭的编辑状态。

## 风险与验收口径

- 不以“相同色值”作为唯一绑定依据。例如 `#161616` 可能表示内容区、弹窗、主要按钮或危险按钮背景，必须根据图层用途选择不同 Token。
- 透明白文字必须精确区分：`#FFFFFF99` 对应次要文字，`#FFFFFF66` 对应提示文字，不能混用。
- 失败状态文字应绑定 `--color-text-danger`；失败状态背景、描边与按钮还需在用途明确后分别处理。
- Paper 截图能力恢复前，计算样式校验是当前可用的客观验证方式；恢复后应补做截图抽样，确认没有视觉回归。
