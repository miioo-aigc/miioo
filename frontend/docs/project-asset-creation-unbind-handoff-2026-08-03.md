# 主体图片解除关联交接文档

## 1. 问题标题

从“资产库-项目资产”移除主体图片时，需要根据图片来源决定是删除源资产还是只解除当前主体关联。当前解绑分支在刷新后图片仍重新出现，且此前业务规则未覆盖本地上传和主体页面创作来源。

## 2. 业务背景

用户在主体页面执行以下操作：

1. 新增一个主体；
2. 点击“从资产库选择”；
3. 从资产库选择一张图片添加到主体；
4. 该图片同时出现在：
   - “资产库-项目资产-角色/场景/道具”对应主体卡片中；
   - “资产库-创作资产-图片”列表中。

图片来源可能是以下任意一种：

- 创作资产：当前创作项目生成或上传的创作图片；
- 本项目资产：已经属于当前项目的图片；
- 其他项目资产：从其他项目可复用的已有图片；
- 其他资产库来源：后端允许复用的共享或历史资产。

删除语义按来源区分：

- 本地上传到主体页面的图片：删除源资产，并级联清除所有项目、主体和其他关联；
- 主体页面创作生成的图片：删除源资产，并级联清除所有项目、主体和其他关联；
- 从资产库选择的本项目资产、其他项目资产或创作资产：只解除当前主体与源资产的关联，保留源资产及其他关联。

## 3. 当前现象

- 前端删除操作后，项目资产卡片会立即消失；
- 前端会先从当前列表中移除卡片；
- 但刷新页面后，该图片又重新出现在项目资产中；
- 资产库选择来源：说明解绑关系没有真正持久化，或项目资产查询仍将该资产错误归入项目范围；
- 本地上传/主体页面创作来源：需要确认源资产删除和级联清理是否完成。

## 4. 前端当前实现

相关代码：

- [`src/api/assets.js`](../src/api/assets.js)
- [`src/components/assets/AssetsProjectPanel.jsx`](../src/components/assets/AssetsProjectPanel.jsx)

项目资产主体卡片的移除入口调用：

```js
apiRemoveAssets(records, {
  projectId: activeProject,
  subjectType,
  deleteMode: 'project',
});
```

当前实现需要按以下规则分流：

- `local-upload`：调用源资产删除接口；
- `subject-image`、`subject-generated` 等主体页面创作来源：调用源资产删除接口；
- 从资产库选择的已有资产：只调用资产更新接口解除当前主体绑定；
- 无法确认来源：按主体资产删除处理，直接删除源资产，并由后端级联清理全部关联。

主体页面本地上传时，前端已在 `metadata_json` 写入：

```json
{
  "source_type": "local-upload",
  "origin": "local-upload"
}
```

主体页面 AI 创作生成的资产也必须由后端返回稳定的来源标记，例如 `subject-image` 或 `subject-generated`，不能只依赖图片 URL 或项目 ID 推断。

当前创作资产解绑请求为：

```http
PATCH /api/assets/{asset_id}
Content-Type: application/json
Authorization: Bearer <access_token>
```

```json
{
  "subject_id": null
}
```

OpenAPI 中 `AssetUpdate.subject_id` 明确允许字符串或 `null`。

## 5. 业务不变量与资产所有权

### 5.1 主体图片删除按来源决定行为

```text
主体页面本地上传 / 主体页面创作 = 删除源资产 + 级联清理所有关联
资产库选择已有资产 = 只解除当前主体关联
```

本地上传和主体页面创作的源资产已经被定义为当前主体资产链路产生的资产。用户在项目资产主体卡片中删除它时，源资产本体应被删除，不需要保留其他项目或主体关联；所有关联都必须被同步解除，避免产生失效关系。

从资产库选择的已有资产不属于当前主体独占资产。删除时只能解除当前主体关系，不能影响源项目、创作资产或其他主体的关联。

### 5.2 来源识别要求

后端必须返回稳定、可持久化的来源字段，至少支持：

- `local-upload`：主体页面本地上传；
- `subject-image` 或 `subject-generated`：主体页面创作生成；
- `asset-library`、`creation` 或其他明确值：从资产库选择的已有资产。

不能仅根据 `project_id`、`scope`、图片 URL 或当前是否存在 `subject_id` 判断来源；但如果来源确实无法确认，按本次产品规则必须执行源资产删除，不得退回只解绑。

### 5.3 级联删除要求

删除本地上传或主体页面创作源资产时，后端必须在同一事务或等价一致性流程中：

- 将源资产移入回收站或按现有资产删除语义删除；
- 清理所有项目中的主体绑定关系；
- 清理所有主体候选图引用和主图引用；
- 清理其他引用源，避免任何项目继续返回该资产；
- 不保留指向已删除资产的孤儿关系。

## 6. 后端需要确认的问题

请重点确认以下三点：

### 6.1 是否真正保存了 null

收到以下请求时：

```json
{
  "subject_id": null
}
```

不能因为使用了类似 `exclude_none=true`、`if value is not None` 或只更新非空字段的逻辑而跳过更新。

更新成功后，资产详情必须返回：

```http
GET /api/assets/{asset_id}
```

```json
{
  "id": "asset-id",
  "subject_id": null
}
```

### 6.2 `scope=project` 的查询定义

以下请求：

```http
GET /api/assets?project_id={project_id}&scope=project&category=character
```

不应返回已经解除主体绑定的创作资产。

项目资产查询至少应满足：

```text
project_id = 当前项目
且资产属于项目资产范围
且 subject_id 仍然有效绑定时，才进入主体项目资产卡片
```

如果创作资产和项目资产共用 `project_id`，则不能仅依据 `project_id` 判断资产属于项目资产；还需要依据资产来源、资产作用域或绑定关系判断。

### 6.3 源资产查询边界

以下请求：

```http
GET /api/assets?scope=creation&asset_type=image
```

对于资产库选择的已有资产，解绑后仍应在其原始资产范围中存在。对于本地上传或主体页面创作来源，删除后不应再出现在任何资产列表。

资产库选择来源的解绑只改变主体关联关系，不得触发：

- 资产删除；
- 文件删除；
- 创作历史删除；
- 创作资产回收站状态变化。

本地上传或主体页面创作来源的删除则相反：源资产删除后不应再出现在任何资产列表，并且所有关联关系都必须被清理。

### 6.4 删除接口必须支持级联清理

当删除的是 `local-upload`、`subject-image` 或 `subject-generated` 来源时，后端删除接口必须同步清理所有项目和主体关联：

- 清理其他项目中的主体绑定；
- 清理其他主体的候选图和主图引用；
- 清理分镜、成片或其他资产引用；
- 不保留指向已删除资产的孤儿关系。

如果现有删除接口不具备级联能力，建议增加明确的删除源资产接口，并返回被清理的关联数量，例如：

```json
{
  "deleted_asset_id": "asset-id",
  "cleared_relation_count": 100,
  "success": true
}
```

## 7. 推荐后端实现方案

### 方案 A：修正现有 PATCH 接口

继续使用：

```http
PATCH /api/assets/{asset_id}
```

后端正确处理显式的 `subject_id: null`，并同步修正 `scope=project` 查询逻辑。

优点：无需新增接口，前端改动最小。

### 方案 B：新增明确的解绑接口

如果现有 PATCH 接口无法区分“字段未传入”和“字段显式传 null”，建议新增：

```http
POST /api/assets/{asset_id}/unbind-subject
```

请求：

```json
{
  "project_id": "project-id",
  "subject_id": "subject-id"
}
```

接口行为：

1. 校验资产属于当前用户；
2. 校验资产当前确实绑定指定主体；
3. 只清空主体关联字段；
4. 资产库选择的已有资产只解除当前主体关系并保留源资产；本地上传或主体页面创作来源则删除源资产并级联清理全部关联；
5. 返回解绑后的资产记录；
6. 使项目资产列表缓存失效。

如果采用方案 B，前端需要将创作资产删除分支改为调用该接口。

## 8. 推荐数据状态

解绑前：

```json
{
  "id": "asset-id",
  "project_id": "project-id",
  "subject_id": "subject-id",
  "scope": "creation",
  "source": "creation"
}
```

解绑后：

```json
{
  "id": "asset-id",
  "project_id": "project-id",
  "subject_id": null,
  "scope": "creation",
  "source": "creation"
}
```

资产库选择的已有资产解绑时，`id`、文件地址、项目归属、来源字段、创作历史记录和其他关联不应改变，只解除当前主体关系。

本地上传或主体页面创作来源删除时，源资产及所有关联都应进入删除后的终态，不得继续被任何项目或主体查询到。

如果源资产来自本项目或其他项目，且是通过资产库选择添加到主体，解绑后的示例只改变：

```json
{
  "subject_id": null
}
```

不能把它改成删除、回收站或跨项目迁移。

## 9. 验收用例

### 用例 1：解绑后资产详情

1. 创建或选择一张创作图片；
2. 绑定到主体；
3. 从项目资产中删除该图片；
4. 查询资产详情。

期望：

- HTTP 状态码成功；
- `subject_id` 为 `null`；
- 文件地址不变；
- 资产未进入回收站。

### 用例 2：刷新项目资产列表

1. 完成用例 1；
2. 重新请求项目资产列表；
3. 刷新浏览器后再次请求。

期望：

- 该图片不再出现在主体项目资产卡片中；
- 其他图片不受影响；
- 不需要依赖前端缓存过滤才能达到结果。

### 用例 3：资产库选择的创作资产仍存在

1. 通过资产库选择一张创作图片并绑定到主体；
2. 打开“资产库-创作资产-创作图片”；
3. 刷新页面。

期望：

- 原创作图片仍然存在；
- 图片仍可查看、下载和再次绑定到主体；
- 创作提示词、模型和生成参数仍然保留。

### 用例 4：本地上传源资产直接删除

1. 在主体页面本地上传一张图片；
2. 确认资产来源为 `local-upload`；
3. 从项目资产主体卡片中移除；
4. 查询资产详情、项目资产列表和其他关联。

期望：

- 源资产进入删除终态；
- 所有项目和主体关系都被清理；
- 任何资产列表不再返回该资产；
- 不留下孤儿 `subject_id` 或候选图引用。

### 用例 5：主体页面创作源资产直接删除

1. 在主体页面创作生成一张图片；
2. 确认来源为 `subject-image` 或 `subject-generated`；
3. 从项目资产主体卡片中移除。

期望与用例 4 相同：源资产删除，所有关联级联清理。

### 用例 6：其他项目已有资产只解除关系

1. 准备一张属于其他项目的已有图片；
2. 在当前主体页面通过资产库选择并添加；
3. 从当前项目资产主体卡片中移除；
4. 分别查询当前项目、源项目和资产详情。

期望：

- 当前主体不再关联该图片；
- 源项目中的图片仍存在；
- 图片文件和资产 ID 不变；
- 不影响源项目和其他主体的关联；
- 不进入回收站。

### 用例 7：资产库选择的创作资产只解除关系

1. 通过资产库选择一张创作图片并绑定到主体；
2. 从项目资产主体卡片中移除；
3. 查询资产详情和创作资产列表。

期望：

- 只解除当前主体关系；
- 创作资产仍存在；
- 其他主体或项目关联不受影响。

### 用例 8：来源未知时直接删除

1. 准备一张主体资产记录，后端没有返回可识别来源字段；
2. 从项目资产主体卡片中移除；
3. 查询资产详情、项目资产列表和其他项目关联。

期望：

- 源资产进入删除终态；
- 所有项目、主体和候选图关联被级联清理；
- 任何项目资产接口都不再返回该资产；
- 不允许将未知来源降级为只解绑。

### 用例 9：重复操作幂等

对同一资产重复执行对应操作：

- 资产库选择来源重复解绑不应删除资产；
- 本地上传/主体页面创作来源重复删除应保持成功幂等；
- 来源未知时重复删除应保持成功幂等；
- 不应返回 500；
- 解绑场景最终 `subject_id` 为 `null`；
- 删除场景所有列表都不返回该资产。

## 10. 联调时需要提供的信息

请后端联调时提供：

- `PATCH /api/assets/{asset_id}` 的实际响应体；
- PATCH 后立即调用 `GET /api/assets/{asset_id}` 的响应体；
- PATCH 后调用项目资产列表的响应体或至少确认该资产是否仍被返回；
- 创作资产列表查询的响应体；
- `scope=project` 与 `scope=creation` 的实际筛选定义；
- 是否存在项目资产列表缓存，以及 PATCH 后的缓存失效策略。

## 11. 当前结论

前端已经将“项目资产主体图片移除”调整为按来源分流：本地上传、主体页面创作和来源未知的主体图片删除源资产并级联清理；只有明确识别为资产库选择的已有资产时才解除当前主体关系。后端必须保证删除和级联解绑的一致性。

本问题不能只通过前端删除卡片状态解决。后端必须保证：

```text
主体页面本地上传/创作来源/来源未知：删除源资产并清理全部关联
资产库选择来源：只解除当前主体关联，不删除源资产
```
