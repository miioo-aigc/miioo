# 分镜创作面板参考主体重复展示修复记录

## 问题现象

刷新分镜页面后，主体参考列只有一张手动添加的图片，但打开创作视频面板时，同一张参考主体图片出现两次。

## 根因

创作视频面板初始化参考主体时，会合并两份数据：

```text
当前镜头 mainRefs
已有 creationForm.video.refSubjects
```

刷新恢复过程中，同一张图片可能被后端或前端恢复成两种不同的记录：

- 一条带 `subjectId` 的主体引用；
- 一条带 `assetId` 的资产引用，或只带图片 URL的普通引用。

原有去重主要依据主体 ID、资产 ID或 URL身份键。两条记录身份不同但图片地址相同，因此可以同时进入创作面板；主体参考列本身没有重复，是因为它使用的是当前镜头 `mainRefs` 的已去重结果。

## 修复方式

修改 `src/utils/referenceMediaAdapter.js` 的 `dedupeReferenceMedia`：

1. 继续按主体 ID、资产 ID或 URL身份键去重。
2. 对主体和图片分组额外计算规范化图片路径。
3. 当不同身份记录指向同一图片时，只保留先出现的一条。
4. 使用图片路径而不是完整域名作为比较依据，因此相对地址和完整后端地址也能识别为同一张图片。
5. 不对参考视频和参考音频增加图片路径去重。

当前镜头主体引用在面板初始化时排在旧表单快照之前，因此发生重复时优先保留主体引用，保留主体 ID、主体类型、资产 ID和名称等业务信息。

## 影响范围

- 创作视频面板的主体参考和普通参考图恢复。
- 不改变主体参考列的渲染数据源。
- 不改变主体参考列与创作面板之间的同步保存逻辑。
- 不改变提示词主体绑定和 `video_prompt_mentions` 逻辑。
- 不改变参考视频、参考音频和首尾帧的数据处理。

## 验证

- 用户反馈确认重复发生在创作面板，主体参考列没有重复。
- `npx eslint src/utils/referenceMediaAdapter.js`：通过。
- `npm run build`：通过；仅保留已有分包体积提示。
- `npm run check:architecture`：通过；仅保留已有文件规模提醒。
- `git diff --check`：通过。
