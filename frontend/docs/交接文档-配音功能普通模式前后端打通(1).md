## 1. 功能概述

「创作模块 → 配音生成」提供两种模式：

| 模式 | 入口 | 能力范围 | 字符上限 | 生成通道 |
|------|------|---------|---------|---------|
| **普通模式**（本文档） | `DubbingStudio` 默认卡片 | 仅调整 voice_id、语速、音量、音调 | 前端 1000（`NORMAL_LIMIT`） | 同步 TTS（≤500 字）/ 异步长文本（仅 MiniMax） |
| 专业模式 | `DubbingStudio` 右上角按钮 → `DubbingAdvancedModal` | 完整官方参数（voice_setting / audio_setting / voice_modify / 字幕 / 效果器等） | 直接输入 3000 / 文件 8MB | 同上，参数更全 |

普通模式定位：**最小化配音入口**。用户在输入框填文字 → 选音色 → 调语速/音调/音量 → 一键生成，结果以「音频卡片」落回创作结果流，并持久化为资产（Asset + AudioClip）。

## 4. 前端关键实现

### 4.1 普通模式 payload 构造（`DubbingStudio.jsx`）

`startNormalGeneration()`（行 644-671）：

```js
const payload = {
  prompt,                 // 配音文字
  text: prompt,
  genType: 'dubbing',
  dubbing_mode: 'normal', // 仅前端标记，后端无该字段消费（见 §8 注意事项）
  model,                  // 当前配音模型（来自 modelOptions）
  voice_id: voice.id,     // 由音色弹窗回填（voice_id / provider_voice_id）
  voiceId: voice.id,
  voiceName: voice.name,
  voicePreviewUrl: voice.previewUrl,
  speed,                  // 0.5 - 2.0
  vol: volume,            // 0.01 - 10
  pitch,                  // -12 - 12
  onFail: (fallbackPrompt) => setText(fallbackPrompt || prompt),  // 失败回填文本
};
Promise.resolve(onGenerate?.(payload)).catch(() => setText(prompt));
setText('');
```

- 生成按钮禁用条件：`!disabled && !atConcurrentLimit && text.trim().length > 0`（`canGenerate`）
- 并发提示：`activeCount >= 5` 时显示「当前有 5 个任务正在生成」

### 4.2 音色选择链路（`DubbingVoiceModal.jsx`）

### 5.3 同步生成主流程 `generate_creation_audio`（`creation.py:7436`）

1. **校验**：`text` 非空；`len(text) > 10000` → 400「Text too long, use async」
2. **作用域解析**：`_resolve_creation_scope` → session/shot/project
3. **绑定解析**：`_resolve_audio_binding_context`（`@资产` 提及、reference_audio_url）
4. **凭据**：`get_user_model_provider_credentials(user.id, db, category="voice", requested_model=req.model)` → 无可用模型时 400
5. **音色决策**：
   - `_resolve_creation_audio_reference_voice_binding`：参考音频 → 绑定音色
   - `effective_requested_voice_id = req.voice_id or reference_voice.voice_id or "zh-CN-XiaoxiaoNeural"`
   - `_resolve_creation_audio_voice_context`：系统音色 → 上游 voice_id + 名称
6. **Provider 参数**：`build_tts_provider_options(req, default_voice_id, default_speed, default_emotion)`（`schemas/tts.py:57`）——默认只有 `voice_setting`（voice_id/speed/emotion）；高级参数按字段逐个透传
7. **调上游**：`tts_service.generate(text, api_key, base_url, voice, speed, model, provider_type, provider_options)`
8. **落盘**：`persist_if_external(result["url"], "creation/audio", ...)` → `audio_url`
9. **入库**：`_create_creation_audio_records(...)`（`creation.py:3014`）→ 返回

### 5.4 异步长文本路径 `_create_creation_audio_async_task`（`creation.py:7570`）

- 仅当 `provider_type == 'minimax'` 或 `'onelink' + is_minimax_speech_model(model_id)`，否则 400
- 组装 MiniMax payload：`voice_setting.voice_id/speed/vol:1/pitch:0` + 高级字段
- `create_minimax_async_tts_task(runtime, payload)` → provider `task_id`
- 落 `GenTask(task_type='creation_audio', status='pending', params={...})` → 返回 `CreationTaskResponse`
- `_refresh_creation_audio_task`（7759）后台轮询上游 → 完成后写 AudioClip + Asset

## 8. 注意事项与已知坑

| # | 事项 | 影响 | 建议 |
|---|------|------|------|
| 1 | **普通模式的 vol / pitch 未透传到后端**。`DubbingStudio` payload 有 `vol/pitch`，但 `creation.js` 的 `dubbingBody` 只透传 `speed`，后端 `CreationAudioGenerateRequest` 顶层也没有 `vol/pitch`（只在 `voice_setting` 里有，而普通模式不传 `voice_setting`） | 普通模式「音量/音调」滑块对 MiniMax 等 provider 实际不生效（速度生效） | 若需支持：在 `dubbingBody` 增加 `voice_setting: { voice_id, speed, vol, pitch }` |
| 2 | **`dubbing_mode: 'normal'` 无后端消费**。前端内存 payload 标记，`dubbingBody` 与 `CreationAudioGenerateRequest` 均未定义该字段（Pydantic 默认忽略额外字段） | 普通/高级模式在后端共用 `/audios/generate`，差异仅参数完备度 | 如需区分可显式加字段，或删除前端标记 |
| 3 | **长文本通道限制**：>500 字仅 MiniMax speech 系列（含 OneLinkAI 透传）支持；非 MiniMax 直接报错 `DUBBING_TEXT_TOO_LONG` | 用户用非 MiniMax 模型配长文本会被拦截 | 前端引导切换模型 |
| 4 | **字符上限不一致**：前端普通模式 `NORMAL_LIMIT=1000`，同步接口后端上限 10000 | 前端更严格，行为可控 | 保持前端限制为主 |
| 5 | **同步/异步结果判定**：`/audios/generate` 同步返回已落库记录（`id=clip.id, asset_id, audio_url`），**不是 GenTask**。历史实现曾把 `genData.id` 当 taskId 轮询导致 404（代码注释 1102-1104 已说明） | 勿再引入「同步接口任务化」误判 | 同步返回直接消费；仅当返回真实 `task_id` 才轮询 |
| 6 | **并发上限 5**（`activeCount >= 5`），前端按 tab 计数（image/video/dubbing 独立） | 防止供应商并发滥用 | 后端如需要可再加服务端限流 |
| 7 | 音色显示名：优先 `VOICE_ID_DISPLAY_ALIAS_MAP` 中文别名，其次名称；`voice_id` 为空时确认按钮会拦截 | 兼容多 provider 音色 id 样式 | 新增 provider 音色需补别名映射 |

## 9. 验收建议（部署后手工验证）

1. 创作页切到「配音」tab，确认模型列表来自后端 `voice` 类目（apiListModels）
2. 打开音色弹窗：官方库/收藏/我的音色三 tab 数据正确；试听、收藏可切换
3. 输入 ≤1000 字文字，选择音色，点击生成 → 出现 loading 卡片 → 数秒后变为可播放音频卡片
4. 音频卡片：播放、下载、收藏、删除均可用（走 `/api/creation/audios/*`）
5. 切到「资产库 → 音频」分类，确认生成的配音资产已入库（`GET /api/assets?asset_type=audio`）
6. 输入 >500 字文本 + MiniMax 模型 → 走异步通道，任务完成后卡片刷新
7. 输入 >500 字文本 + 非 MiniMax 模型 → 应提示切换模型
