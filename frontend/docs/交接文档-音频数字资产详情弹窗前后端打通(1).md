# 交接文档：音频数字资产 · 详情弹窗前后端打通方案

> 文档版本：v1.1 ｜ 适用范围：`frontend_new/` + `backend/` ｜ 生成时间：2026-08-21
> 文档性质：现状分析（代码事实）+ 打通方案设计（前端复用/适配 + 后端复用既有能力）+ 验收清单。
> 结论摘要：
> - **创作页配音历史**的音频详情弹窗 `CreationAudioDetailModal` **已实现**（2026-08-21 代码完成，未部署），数据源为 AudioClip 视图。
> - **资产库「音频」分类**的 `AudioCard` **仍无详情弹窗**（点击无响应），本次打通目标即此缺口。

## 1. 背景与现状

### 1.1 音频相关详情弹窗现状

| 场景 | 卡片 | 详情弹窗 | 数据视图 | 打通状态 |
|------|------|---------|---------|---------|
| 创作页 · 配音历史（dubbing tab） | 结果音频卡片 | `CreationAudioDetailModal`（components/，Aug 21 完成） | AudioClip（`/api/creation/audios`） | ✅ 已实现（未部署） |
| **资产库 · 音频分类** | **`AudioCard`（AssetsPage.jsx:301）** | **无** | Asset（`asset_type='audio'`） | ❌ **本次缺口** |
| 资产库 · 图片/视频/分镜 | `AssetCard` / `ProjectAssetCard` | `ImageDetailModal` / `CreationVideoDetailModal` / `ShotDetailModal` 等 | Asset | ✅ 已打通 |

- `AudioCard` 当前只支持：播放（模拟波形）、收藏（星标）、下载、删除、批量选择。
- 卡片 `onClick`（AssetsPage.jsx:339）：`if (batchMode) onSelect?.()` —— **非批量模式下点击无任何响应**。
- 资产库详情打开逻辑集中在 `AssetCard.handleOpen`（AssetsPage.jsx:2125-2140），但音频分类渲染走独立的 `AudioCard` 分支（AssetsPage.jsx:3994-4006），**未接入该逻辑**。

### 1.2 音频数据的双轨视图（务必分清）

| 数据源 | 模型 | 展示场景 | 详情接口 | 详情视图归一 |
|--------|------|---------|---------|-------------|
| **资产库音频资产** | `Asset`（`asset_type='audio'`） | 资产库「音频」分类 | `GET /api/assets/{id}` | 前端 `normalizeAsset`（api/assets.js:404） |
| **创作配音** | `AudioClip`（`source='creation'`） | 创作页配音历史 | `GET /api/creation/audios/{id}` | 前端 `normalizeCreationAudioView`（utils/creationAudioView.js:182） |

- 创作配音入库时**同时写 `AudioClip` + `Asset`**（`_create_creation_audio_records`，creation.py:3014），二者通过 `Asset.metadata_json`（含 `clip_id` 等）关联。
- 资产库「音频」分类展示的是 **Asset 视图**；后端 `build_audio_media_fields`（media_view_models.py:146）已把 `preview_url/download_url` 归一。
- 后端 `_enrich_creation_audio_view`（creation.py，Aug 21 新增）已为 AudioClip 视图注入 `voice_origin / voice_origin_label / pitch / volume / advanced_mode_enabled / advanced_mode_label / human_created_at` 等增强字段——**该能力可直接复用于资产库音频详情的配音字段展示**。

## 3. 后端响应契约（已具备，无需新增路由）

### 3.1 音频资产详情 `GET /api/assets/{id}` → `AssetResponse`

`asset_type='audio'` 时 `_resolve_asset_media_fields`（assets.py:369）走 `build_audio_media_fields`（media_view_models.py:146）：

```python
{
    "thumbnail_url": None,
    "preview_url": preview_url,        # resolve_preview_url(descriptor, fallback=file_url)
    "previewUrl": preview_url,
    "large_url": None, "largeUrl": None,

    "downloadUrl": download_url,
    "poster_url": None, "posterUrl": None,

```

`AssetResponse` 通用字段（`_to_response`，assets.py:439）：`id / user_id / project_id / subject_id / name / asset_type / category / file_url / preview_url / download_url / is_starred / description / model / created_at / metadata_json（脱敏后） / input_prompt / source ...`

> 说明：音频资产的 `preview_url` 与 `file_url` 均指向音频本体；`metadata_json` 中可携带 `duration`、`clip_id`、`voice_name`、`speed`、`emotion` 等创作配音信息（来源为创作时）。

## 4. 前后端打通方案设计

### 4.1 总体思路

> **复用已实现的 `CreationAudioDetailModal` 作为弹窗骨架**，为资产库 Asset 视图做适配；后端零新增路由，复用 `GET /api/assets/{id}`（基础字段）+ 可选 `GET /api/creation/audios/{id}`（配音增强字段）。

```
AudioCard 点击（非批量模式）
   │
   ▼
onOpen(asset) → 打开音频详情弹窗
   │
   ├─ 方案 A（推荐）：改造 CreationAudioDetailModal 增加「Asset 视图」兼容
   │    └─ 卡片数据优先渲染（name/duration/audio_url 首屏零等待）
   │        └─ 后台按数据源补全：
   │            ├─ asset.metadata_json.clip_id 存在（创作配音资产）
   │            │    └─ apiGetCreationAudio(clip_id) → 配音视图增强字段
   │            └─ 否则 apiGetAssetDetail(asset.id) → 资产详情字段
   │
   └─ 方案 B：新建轻量 AudioAssetDetailModal（Asset 视图专用，字段较少）
        └─ 后续如需配音增强再叠加方案 A 的补全逻辑
```

### 4.2 前端改动清单（方案 A，推荐）

| # | 文件 | 改动 | 要点 |
|---|------|------|------|
| 1 | `frontend_new/src/components/CreationAudioDetailModal.jsx` | 增加 `viewMode = 'clip' \| 'asset'` 或自动识别（`audio.asset_id`/`audio.clip_id`）；Asset 视图隐藏配音专属字段为空时的区块 | 该组件 props 已覆盖：`open/audio/favorited/onClose/onDownload/onToggleFavorite/onDelete/onShowToast` |
| 2 | `frontend_new/src/utils/creationAudioView.js` | `normalizeCreationAudioView` 增加 Asset 视图分支（复用 `normalizeAsset` 的音频字段映射） | 参考 api/assets.js normalizeAsset 404 |
| 3 | `frontend_new/src/pages/AssetsPage.jsx` | `AudioCard` 增加 `onOpen` prop；非批量模式点击打开详情（行 339） | 同时把 `asset` 对象透传（当前只传 name/duration） |
| 4 | `frontend_new/src/pages/AssetsPage.jsx` | 渲染分支（3994-4006）给 `AudioCard` 传 `asset={asset}` + `onOpen`；渲染 `<CreationAudioDetailModal>` | 详情数据优先级：卡片 → `apiGetAssetDetail` →（有 clip_id）`apiGetCreationAudio` |
| 5 | `frontend_new/src/api/creation.js` | 复用现有 `apiGetCreationAudio(audioId)`（513） | 无需改动 |

### 4.3 详情弹窗数据装配（伪代码）

```js
function buildAudioDetailPayload(cardAsset) {
  const meta = cardAsset.metadata_json || {};
  const base = {
    id: cardAsset.id,
    audio_url: cardAsset.previewUrl || cardAsset.file_url || '',
    name: cardAsset.name,
    duration: meta.duration ?? cardAsset.duration ?? '',
    model: cardAsset.model || meta.model || '',
    created_at: cardAsset.created_at ?? '',
    is_favorite: cardAsset.starred ?? false,
    text: meta.spoken_text ?? meta.prompt ?? cardAsset.prompt ?? '',
    ...meta,   // voice_name / speed / emotion / pitch / volume / clip_id ...
  };
  return base;
}
// 打开后后台补全：
// 1) 有 meta.clip_id → apiGetCreationAudio(meta.clip_id) → 用配音视图字段覆盖
// 2) 否则 → apiGetAssetDetail(cardAsset.id) → 补 download_url / input_prompt / created_at
```

### 4.4 交互与联动

1. **首屏零等待**：卡片数据已含 name/duration/previewUrl，弹窗立即渲染；完整详情后台补全（`normalizeCreationAudioView` 已在渲染期处理缺失字段）。
2. **播放**：`CreationAudioDetailModal` 内已内置左深色播放区（波形随进度点亮 + 播放控制条），复用即可。
3. **收藏/删除**：沿用 `toggleStar` / `deleteAsset`（AssetsPage.jsx:3568 / 3583），删除后关闭弹窗并刷新列表；删除走 `apiDeleteAsset` → 软删除进回收站。
4. **下载**：走 `apiDownloadAsset(asset.id, { prefer_origin: true, rawResponse: true })`（资产库既有 `downloadAsset`，AssetsPage.jsx:3824）。
5. **批量模式**：批量选择时点击卡片只做选择，不打开详情（与图片卡片行为一致）。
6. **回收站**：`TrashAssetCard`（AssetsPage.jsx:3007）已有 `isAudio` 分支（无缩略图显示空态图标）；详情接入建议二期。

### 4.5 后端改动（可选增强，非必需）

| 级别 | 改动 | 收益 |
|------|------|------|
| **零改动（推荐）** | 复用 `GET /api/assets/{id}` + `GET /api/creation/audios/{id}` | 后端无风险，前端一次落地 |
| 增强 A | `build_audio_media_fields` 或 `_to_response` 从 `metadata_json` 透出 `duration / voice_name / speed / emotion / clip_id` 到 `AssetResponse` | 前端免二次查询，列表即全量 |
| 增强 B | `get_asset` 对 audio 资产自动附带配音视图字段（调用既有 `_enrich_creation_audio_view` 逻辑） | 资产详情与配音详情展示一致 |

> 建议先「零改动」打通，视展示需要再决定是否做增强 A/B。

## 7. 风险与注意事项

| # | 事项 | 说明 |
|---|------|------|
| 1 | 音频资产**不支持媒体派生**（`ensure-media-derivatives` 仅 image/video，assets.py:1005） | 详情弹窗不要对音频调用派生接口；展示用 `preview_url/file_url` |
| 2 | `preview_url` 与 `file_url` 对音频相同 | 不要用 `<img>` 标签加载音频地址（AGENTS.md 媒体语义约束） |
| 3 | **双数据源 id 不同**：资产库卡片 id 是 **Asset.id**，创作配音 id 是 **AudioClip.id** | 详情删除/下载时按数据源选用对应接口，避免 404 |
| 4 | `metadata_json` 后端已脱敏（`redact_subject_generation_metadata`） | 前端仅消费白名单字段，不依赖敏感字段 |
| 5 | 创作配音被删除（AudioClip 软删）后，资产仍可能在回收站 | 配音详情查询 404 时降级为纯 Asset 视图展示 |
| 6 | 本次改动涉及 `CreationAudioDetailModal`（已实现未部署） | 若该组件已部署则直接改造；未部署则与配音详情打通一并上线 |
