# 分镜提示词绑定数据修正计划

## 一、目标与结论

修正分镜创作视频提示词的主体绑定数据，解决以下问题：

```text
第一次绑定主体
→ 删除提示词中的主体标签
→ 再次绑定同一主体
→ 后端 video_prompt_mentions 出现重复记录
```

根据第五个分镜修改前后的数据，已确认：

- `video_prompt` 保存带 `@` 的当前提示词文本；
- `video_prompt_mentions` 表示当前已绑定主体的集合；
- 同一主体在提示词中出现多次时，`video_prompt_mentions` 只保留一条；
- `refSubjects` 表示本次生成可使用的主体参考图，不等于提示词绑定关系；
- 前端可以根据当前提示词重新计算绑定集合，避免沿用历史记录；
- 后端已经支持持久化绑定数据，但正式实现前仍需确认该字段是“覆盖保存”还是“追加保存”。

## 二、数据规则

三类数据职责保持明确：

```text
video_prompt
= 当前视频提示词文本
```

```text
video_prompt_mentions
= 当前提示词中存在的、已经绑定的主体集合
= 按 subject_id 去重
```

```text
refSubjects
= 本次视频生成使用的主体参考图集合
```

具体规则：

1. 同一个主体在提示词中出现多次，只生成一条 `video_prompt_mentions`。
2. 删除提示词中的某个主体标签后，该主体不再出现在当前绑定集合中。
3. 删除后重新绑定同一主体，最终仍只保留一条记录。
4. 只新增主体参考图、但没有插入 `@主体` 标签时，不自动建立提示词绑定。
5. 角色、场景、道具统一使用主体 ID 建立绑定，不能只依赖名称。
6. 提交空数组时，应清除后端旧绑定。

第五个分镜修改后的正确结果应保持为四条：

```text
陆晚儿
沈锋
灾民营地与峡谷窄道
汉剑
```

即使 `@陆晚儿` 和 `@沈锋` 在提示词中各出现两次，也不增加重复记录。

## 三、实现方案

### 1. 提示词编辑器输出当前标签状态

扩展提示词编辑器的变化回调，使其在返回文本的同时，能够提供当前编辑器中仍存在的标签信息。

当前提示词变化时，从编辑器当前内容提取：

```text
标签名称
标签出现顺序
标签是否仍存在
标签对应的主体类型
```

删除标签后，立即以删除后的编辑器内容重新计算，不保留之前的历史标签记录。

不把旧的 `video_prompt_mentions` 当作新增绑定的基础数组，避免出现：

```text
旧绑定 + 新绑定
```

的历史累加。

### 2. 根据主体 ID 生成绑定集合

根据当前提示词中的 `@主体名称`，到当前 `refSubjects` 中查找对应主体。

匹配优先级：

1. 编辑器标签已保存的主体 ID；
2. 当前参考主体中的 `subjectId`；
3. 仅在名称唯一时按名称匹配。

生成后端格式：

```json
{
  "subject_id": "主体 ID",
  "subject_type": "character",
  "name": "主体名称",
  "display": "@主体名称",
  "display_text": "@主体名称"
}
```

前端类型转换：

```text
char  → character
scene → scene
prop  → prop
```

如果发现同名但不同 ID 的主体，不自动猜测，必须优先使用用户选择时记录的主体 ID。

### 3. 按 subject_id 去重

在提交前对绑定数组去重：

```text
同一个 subject_id 只保留一条记录
```

去重只作用于 `video_prompt_mentions`，不修改 `video_prompt` 文本。

例如：

```text
提示词：
@陆晚儿 ... @陆晚儿 ... @汉剑
```

提交：

```json
[
  {
    "subject_id": "陆晚儿 ID",
    "name": "陆晚儿"
  },
  {
    "subject_id": "汉剑 ID",
    "name": "汉剑"
  }
]
```

### 4. 保存时提交完整当前状态

保存视频创作表单时，同时提交：

```text
当前 video_prompt
当前 video_prompt_mentions
当前 refSubjects
其他视频生成参数
```

保存策略必须是完整替换：

```text
当前编辑器状态
→ 重新生成完整 mentions 数组
→ 覆盖提交
```

不能只提交新增标签，也不能把新数组追加到后端已有数组上。

### 5. 刷新与旧数据恢复

页面刷新时：

1. 优先读取后端的 `video_prompt_mentions`；
2. 根据 `subject_id` 关联 `refSubjects`；
3. 恢复提示词中的已有 `@标签`；
4. 对历史重复绑定进行内存去重；
5. 用户再次保存时提交清理后的完整数组。

注意：不能把普通文本中的主体名称全部自动转换成 `@标签`。只有以下情况才视为绑定：

- 用户通过主体候选项主动插入；
- 后端已经明确返回了绑定关系；
- 标签能够和唯一主体 ID 建立对应关系。

## 四、预计修改范围

### `PanelPromptInput.jsx`

负责：

- 识别当前编辑器中的 `@标签`；
- 插入标签；
- 删除标签；
- 在变化回调中提供当前有效标签信息；
- 确保删除标签后不会继续保留旧绑定。

保持现有内容可编辑、原子标签、候选下拉和光标行为不变。

### `GenerateVideoPanel.jsx`

负责：

- 管理视频提示词和主体参考图；
- 接收提示词编辑器的当前标签状态；
- 根据当前标签和主体 ID生成 `video_prompt_mentions`；
- 对 mentions 按主体 ID 去重；
- 将清理后的数据写入视频表单状态。

### `StoryboardPage.jsx`

负责：

- 将最新的视频表单状态传入防抖保存队列；
- 确保连续编辑时只提交最后一次状态；
- 确保切换分镜或关闭弹窗时，不会使用旧镜头状态覆盖当前镜头；
- 继续使用真实的 `storyboard.id` 保存，不以 `shot_number` 作为唯一标识。

### `storyboardDataAdapter.js`

负责：

- 读取后端视频绑定字段；
- 统一主体 ID 和主体类型；
- 刷新恢复时对历史 mentions 去重；
- 保持角色、场景、道具的主体参考数据完整。

### `api/storyboard.js`

负责：

- 将 `video_prompt_mentions` 写入后端认可的字段位置；
- 确认空数组能够清空旧绑定；
- 确认保存请求使用覆盖语义；
- 不改变现有图片提示词、视频参数和主体参考图保存逻辑。

## 五、后端契约确认项

正式修改前必须验证以下接口行为：

1. `video_prompt_mentions` 是否按完整数组覆盖。
2. 提交：

```json
"video_prompt_mentions": []
```

是否可以清除旧绑定。
3. 后端是否会根据 `video_prompt` 再次解析并追加 mentions。
4. 后端最终以哪一个字段为准：
   - 前端提交的 `video_prompt_mentions`；
   - 还是后端从提示词文本重新提取的结果。
5. `video_prompt_mentions` 的实际字段位置：
   - 顶层字段；
   - `gen_params`；
   - `gen_params.creation_form.video`；
   - 或其他接口约定字段。

如果后端只支持追加、不支持覆盖或清空，前端无法独立清除历史重复记录，需要后端提供以下任一能力：

- 完整数组覆盖；
- 空数组清空；
- 按主体 ID 删除绑定；
- 提供专门的提示词绑定更新接口。

## 六、验收场景

1. 第五个分镜初始无视频标签时，绑定数据为空。
2. 手动绑定陆晚儿、沈锋、场景和汉剑后，保存四条唯一记录。
3. `@陆晚儿` 出现两次，`video_prompt_mentions` 仍只有一条陆晚儿。
4. `@沈锋` 出现两次，`video_prompt_mentions` 仍只有一条沈锋。
5. 删除 `@汉剑` 后保存，汉剑从 mentions 中消失。
6. 删除后重新插入 `@汉剑`，最终只保留一条汉剑。
7. 旧数据已有两条汉剑，重新保存后压缩为一条。
8. 清空所有提示词标签后，提交空数组，刷新后不再恢复旧绑定。
9. 仅新增主体参考图但未插入 `@标签`，mentions 不自动增加。
10. 角色、场景、道具混合绑定时，主体类型和主体 ID均正确。
11. 存在同名主体时，使用主体 ID而不是名称猜测。
12. 连续快速编辑提示词，最终只持久化最后一次完整状态。
13. 关闭弹窗后重新打开，提示词和绑定关系保持一致。
14. 切换到其他分镜后，不会把前一个分镜的绑定保存到当前分镜。
15. 页面刷新后，主体参考图、提示词标签和 mentions 保持一致。

## 七、最终评估

这项前端修正总体可行，核心依据是第五个分镜的数据已经证明：

```text
同一主体多次出现在提示词中
但 video_prompt_mentions 按主体去重
```

因此最终实现应采用：

```text
以当前提示词标签为准
按 subject_id 重新生成绑定集合
保存时完整覆盖提交
删除后不保留历史绑定
刷新后按主体 ID恢复
```

前端可以解决“删除后重新绑定导致重复提交”的状态问题。唯一的前置风险是后端是否真正支持完整覆盖和空数组清除；如果后端确认支持，本计划可以直接实施。
