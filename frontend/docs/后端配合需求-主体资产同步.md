# 后端配合需求：主体（角色/场景/道具）与资产库数据一致性

## 背景

主体页面（SubjectPage）与资产库-项目资产（AssetsPage / ProjectAssetsPanel）目前存在数据不一致问题。

资产库的「角色/场景/道具」列表本质上是查询 `GET /api/assets?category=character|scene|prop&subject_id=...`，
再按 `subject_id` 聚合成卡片。卡片的名称/描述来自**资产（图片）记录自身**，
而主体的名称/描述存在 subjects 表，两者没有同步机制。

前端已做的临时兜底：资产库加载后额外拉取 `GET /api/projects/{projectId}/subjects?type=...`，
按 `subject_id` 用主体的名称/描述覆盖卡片展示。这解决了「已有候选图的主体」名称/描述不一致的问题，
但无法解决下面的问题 1（没有 category 资产的主体在资产库中完全不出现）。

## 需要后端解决的问题

### 问题 1（核心，必须后端配合）：上传/选库的参考图未登记为主体 category 资产

复现：
1. 主体页面手动「新增」一个主体卡片（如角色）；
2. 在编辑面板里用「本地上传」或「从资产库选择」给它加图（不使用模型生成）；
3. 打开资产库-项目资产，对应类别下**看不到这个主体卡片**。

原因：
- 手动新增走 `POST /api/projects/{projectId}/subjects`，只建主体记录，不产生资产；
- 之后加的图走：
  - 本地上传：`POST /api/projects/{projectId}/subjects/{subjectId}/reference-images/upload`
  - 从资产库选择：`POST /api/projects/{projectId}/subjects/{subjectId}/reference-images/bind`
- 这两个接口把图登记为**参考图（reference image）**，
  而不是带 `category=character|scene|prop` + `subject_id` 的**候选图资产**；
- 资产库只列 category 资产，因此该主体一条都查不到，整卡缺失。

期望行为（产品需求）：
- 主体**没有任何候选图** → 资产库对应项目里**不出现**该主体卡片（保持现状）；
- 主体**有候选图**（无论该图是模型生成、本地上传、还是从资产库选入候选列表）
  → 资产库中**都要出现**该主体卡片，且名称/描述与主体页面一致。

建议方案（二选一或组合）：

方案 A（推荐）：让「进入主体候选图列表」的图统一登记为该主体的 category 资产
- 当一张图被加入主体的候选图/参考图列表（upload / bind 两个接口），
  同时创建或关联一条 `category=<主体类型>`、`subject_id=<主体ID>` 的资产记录，
  使其能被 `GET /api/assets?category=...&subject_id=...` 查到。
- 这样资产库的「有候选图就出现」逻辑天然成立，前端无需再改。

方案 B：新增/扩展接口，让资产库能按「主体候选图」而非「category 资产」来构建卡片
- 例如 `GET /api/projects/{projectId}/subjects?type=...` 返回中，
  为每个主体附带其候选图/参考图列表（含 url、is_primary、asset_id 等），
  前端改为以主体为源来渲染卡片。
- 此方案改动主要在前端，但需要后端在主体列表接口中补齐图片列表字段。

### 问题 2 / 3：资产名称、描述与主体不同步（前端已兜底，建议后端最终对齐）

现象：
- 手动新增主体 + 模型生成图，资产库能显示，但名称是类似「场景002-生成图」，描述也不是主体的描述；
- 在主体页编辑名称/描述后，资产库卡片不会同步更新。

原因：
- `PATCH /api/projects/{projectId}/subjects/{subjectId}`（更新主体名称/描述/prompt）
  只更新 subjects 表，不回写关联资产；
- 生成图 `POST /api/projects/{projectId}/subjects/{subjectId}/generate-image`
  产出的资产用的是后端自己生成的名称/描述。

前端现状：
- 资产库已在加载后用主体的名称/描述覆盖展示，视觉上已一致。

建议后端最终对齐（可选，让数据层也一致）：
- 更新主体名称/描述时，同步更新该主体下关联资产的 name/description；
- 或：生成/绑定资产时，name/description 默认取主体的 name/description。
- 若采用方案 A/B 以主体为准展示，此项可弱化为「数据整洁性优化」。

## 涉及接口清单（前端当前调用）

| 用途 | 方法 | 路径 |
|---|---|---|
| 主体列表 | GET | `/api/projects/{projectId}/subjects?type=character\|scene\|prop` |
| 主体详情 | GET | `/api/projects/{projectId}/subjects/{subjectId}` |
| 新增主体 | POST | `/api/projects/{projectId}/subjects` |
| 更新主体 | PATCH | `/api/projects/{projectId}/subjects/{subjectId}` |
| 生成主体图 | POST | `/api/projects/{projectId}/subjects/{subjectId}/generate-image` |
| 上传参考图 | POST | `/api/projects/{projectId}/subjects/{subjectId}/reference-images/upload` |
| 绑定参考图 | POST | `/api/projects/{projectId}/subjects/{subjectId}/reference-images/bind` |
| 资产列表 | GET | `/api/assets?project_id=&scope=project&category=character\|scene\|prop` |

## 期望的验收标准

1. 主体无候选图 → 资产库对应类别不显示该主体卡片；
2. 主体有候选图（模型生成 / 本地上传 / 资产库选入）→ 资产库都显示该主体卡片；
3. 资产库卡片的名称/描述与主体页面完全一致，主体页编辑后可同步。

## 优先级

- 问题 1：高（当前功能缺失，用户上传/选库的主体在资产库直接消失）。
- 问题 2/3：中（前端已兜底展示一致，后端对齐属数据整洁性优化）。
