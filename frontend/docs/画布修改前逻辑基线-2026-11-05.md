# 画布修改前逻辑基线

记录日期：2026-11-05。本文记录本轮节点工作流需求改造之前，代码中实际存在的画布交互与数据逻辑，供后续需求回溯、方案比较和回归使用。

> 本文是代码审查快照，不是产品规范，也不代表建议恢复这些行为。若代码后续变化，应按对应版本重新核实，不能只凭本文判断当前线上表现。文中“当前”均指本次静态审查所见的仓库实现。

## 1. 基线结论

原逻辑采取“空节点首次生成可原位填充；已有内容再次生成则创建结果节点”的混合模式。画布将生成历史主要表达为多个节点及其连接，而不是节点内部候选集：

- 图片：已有图片时生成单张或多张，创建一个或多个新图片节点；批量结果独立成卡片并布局。
- 文本：已有正文时创建新的文本结果节点；空文本节点原位回填，但会把输入来源正文和模型输出拼成该节点正文。
- 视频：已有素材时创建新视频节点；空节点原位回填。视频结果为单个结果节点。
- 输入来源通过节点间有向关系记录；部分生成计划会把目标节点自己的既有结果再追加为生成来源。
- 生成结果节点会带有请求配置和来源关系，以便在画布上继续连接、查看和组织。

因此，“有内容时另建结果节点”是原行为的重要特征，但并非绝对规则：是否原位或新建，受节点当前素材或正文是否存在影响。

## 2. 生成行为按节点类型

### 2.1 图片

入口和计划：CanvasImageGeneration.js 中的 planCanvasImageGeneration 校验目标图片节点、提示词、模型和参考图上限。生成数量取参数 count，至少为 1。

输入来源：读取节点 imageSourceIds 指向的文本、图片节点；文本来源取 content，图片来源取 asset。若目标节点自身已有图片 asset.url，计划会把自身图片追加为来源，并将其计入图片参考上限。这意味着既有图片可作为本次生成参考。

结果节点判定：目标已有图片时 createsResult 为真，第一张结果使用新 ID；目标没有图片时，第一张结果复用目标节点 ID。数量超过一时，其余每张均分配新节点 ID。因此：

- 空图片节点单张：原位生成并回填。
- 空图片节点多张：第一张原位回填目标，其余结果新建节点。
- 已有图片节点单张：新建结果节点。
- 已有图片节点多张：每张结果都进入新建结果节点。

生成开始：记录模型、提示词、generating、请求 ID 和来源 ID；关闭输入面板。创建的新结果节点带相同配置及来源信息，并与目标节点保持/加入相同父分组。多结果根据结果数量做纵向或网格布局，必要时避让已有节点并调整分组边界。新结果节点会成为选中节点。

完成回填：结果按预先生成的 ID 和数组索引映射。回调只写入匹配请求 ID 的节点；已有素材节点不会被回调覆盖。缺失的单项结果显示该项未返回的错误。只有目标为空且尚未出现 asset 的位置才会回填。图片资产包含预览/原图 URL、asset_id（若响应提供）、类型和来源。

连线和校验：图片节点可接收文本、图片节点输入；图片参考数量上限来自模型能力。自身结果也计入现有校验逻辑。超过上限的既有连接可保留并标出溢出状态，但会阻止生成。输入关系存于 imageSourceIds，连线由该字段派生。

### 2.2 文本

输入来源：CanvasTextGeneration.js 从 textSourceIds 直接读取上游文本正文，并把目标节点自身 ID 也加入来源列表。只取有正文的文本节点，不递归遍历更上游节点。

结果节点判定：目标有非空正文时创建一个新的文本节点；没有正文时复用目标节点。新建节点放在目标右侧，若与已有节点过近则向下避让，并选中新结果节点。

请求内容：系统提示要求只返回创作正文；用户消息中把来源正文作为 materials，把输入框文字作为 instruction 一并发送。

完成回填：新结果节点正文写模型返回值。若原位生成，当前实现会把计划中的来源正文和模型输出以空行连接后写入目标正文。若目标正文在请求期间被编辑，回调会因内容与执行前快照不一致而放弃覆盖。请求 ID 用于阻止无关回调写入。

连线：文本节点之间可以连线，连接 ID 存入目标 textSourceIds，边由字段派生。文本来源正文进入下游生成请求。

### 2.3 视频

输入来源：CanvasVideoGeneration.js 合并 videoSourceIds、textSourceIds 和按 slot 排序的 referenceInputs。视频、图片、音频来源按资产类型及模型能力校验；文本作为提示材料。目标自身有视频资产时会追加为来源并计入素材数量、类型和总量限制。

模式和参数：校验后端支持的生成模式及其参考模式映射。根据模型、模式和素材能力校验各类型参考数量。特定 Seedance 编辑模式会强制使用自适应比例和默认时长。首帧、尾帧 URL 按模式从图片参考中形成参数。

结果节点判定：目标节点已有 asset.url 时创建一个新的结果视频节点，否则复用目标节点。每次任务单个视频结果。新节点位于目标右侧并避让已有节点，继承模型、提示词、能力、模式和来源 ID，随后被选中。

完成回填：仅当节点 ID 与请求 ID 匹配且当前没有 asset 时写入视频 asset；已有结果不被异步回调覆盖。

连线：文本、图片、视频、音频均可作为视频节点来源（具体是否可用由模型及模式限制）。来源关系有多字段兼容，删除来源时同步从相应字段移除。边由来源字段派生。

### 2.4 音频

音频有独立生成与文本同步逻辑，不应从图片、文本、视频路径推断。此次基线重点是节点工作流输入框所覆盖的图片、文本、视频生成；音频相关逻辑若纳入后续调整，需单独审查其模块和回归范围。

## 3. 输入面板与节点关系

- 输入面板由选中的节点及对应生成器打开；执行时会关闭面板。
- 已有内容再次生成时，新结果节点被选中，符合画布上逐步向右扩展工作流的交互。
- 生成计划会保存提示词、模型、媒体参数、来源快照和请求身份；具体参数的本地持久化仍取决于节点保存字段和面板状态管理。
- 生成节点可使用显式连线输入。连线数据由节点数据中的来源 ID/引用字段派生，不是独立可随意编辑的另一份事实。
- 图片与视频计划会把目标自身已有素材并入本次来源；文本计划把自身正文并入文本来源。这是原逻辑中“已有结果可继续参与下一次生成”的重要机制。
- 下游连线表达引用关系。结果另建节点时可将其继续连接到后续任务，旧节点仍留在画布上。

## 4. 上传、素材导入和编辑

### 4.1 资产写入节点

画布节点资产变更入口位于 CanvasPage.jsx 的 handleNodeAssetChange 等处理逻辑，按节点类型把素材写入所选节点。图像/视频节点已有素材时，界面通常展示该节点当前素材；上传处理包含本地预览和正式上传阶段，因此临时 URL 与可持久化资产不是同一状态。

### 4.2 批量导入

CanvasAssets.js 的导入计划可把有效素材转成节点并安排画布位置。CanvasPage.jsx 的导入流程处理多项素材、节点布局及边界。当前多选导入并不等同于“在既有生成节点内存放多个候选”：会按导入规则创建节点；现有代码路径中可见首项作用于目标节点、后续项新增节点等行为。视频导入还可能根据类型把其他素材作为参考，而非同类视频结果。不能把批量导入直接当成候选管理模块。

### 4.3 图片编辑等工具

图片裁剪等编辑操作存在独立追加节点流程（例如 CanvasImageEdits.js）。不能仅凭生成输入框的结果分支推断工具栏编辑必然原位或必然新增；每种工具需按自身实现确认。

## 5. 画布展示与节点身份

- 普通图片/视频节点主要围绕单个 data.asset 展示；文本节点围绕 data.content 展示。
- 结果节点是普通画布节点：有自己的 ID、位置、选择状态、父分组关系、端口及可能的输入/输出连线。
- 图片批量结果按多个节点布局，通常以少量结果竖排、较多结果网格排列，并根据节点尺寸避让其他内容。
- 收起预览、分组、导航、搜索、下载、分享等功能主要读取节点当前 asset/content，不是一个独立的多候选集合。
- 节点具有生成中、错误、请求 ID 等运行态数据。异步回填根据请求身份限制落点，避免一般情况下写错节点或覆盖用户后来已有的 asset。

## 6. 保存、恢复与历史

- CanvasDocument.js 序列化节点数据并清理临时运行态；媒体持久化依赖资产身份，不应只依赖浏览器临时 URL。
- CanvasAssetResolver.js 主要按节点 data.asset.asset_id 收集和恢复资产视图。单节点单素材是既有主要数据形态。
- 当前画布的历史/撤销机制记录节点或字段变化，但这不等同于产品定义的可浏览生成历史模块。
- 生成中的请求不等同于已完成可恢复任务；保存流程存在生成中暂停保存、异步回填使用 record:false 等处理。
- 图片生成返回的资产编号按结果索引取用；视频回填需要核实正式结果是否含保存要求的永久资产编号，否则可能不能可靠持久化。
- 导入/导出文件、复制粘贴、分享也以普通节点及其素材字段为主要协议；多个候选若不扩展这些协议，不会自动被完整保存或公开。

## 8. 与新版需求的差异记录

| 主题 | 修改前代码基线 | 新需求方向 |
|---|---|---|
| 已有内容再次生成 | 通常新建结果节点 | 在原任务节点内收纳结果 |
| 图片批量 | 多结果拆成多个画布节点 | 多候选留在一个节点，不可拆出 |
| 下游输入 | 通过结果节点连接继续工作 | 节点只输出当前唯一选定定稿 |
| 目标自身结果 | 图片/视频/文本可进入下一次生成来源 | 自身输出不自动成为自身输入 |
| 文本回填 | 空节点可能拼接来源正文和生成正文 | 输出与输入分离，避免自动拼接上游正文 |
| 被替换的旧定稿 | 主要由原有节点留在画布、撤销或既有数据体现；无独立结果历史模块 | 新增节点内结果历史模块，记录并查看旧结果 |
| 结果持久化 | 主要按每个节点单一 asset/content 保存 | 必须扩展为候选、定稿、结果历史及来源记录 |

## 9. 回溯注意事项

1. 需求若改回原行为，应先明确是恢复“已有结果则新建节点”，还是只恢复部分类型；两者不可混称为完全恢复。
2. 图片批量原行为是每张结果对应一个节点，但空目标时第一张复用原节点，因此不是简单的“批量全部新增”。
3. 原结果节点能形成可连线的画布工作流；新版单定稿模型下候选不再有独立身份，不能把两种数据模型只当作卡片布局切换。
4. 原逻辑的自身结果参与输入，和新版“只使用直接上游及显式参考”互相冲突；切回时必须明确参考快照如何处理。
5. 本文列出的是本次审查确认的核心路径，不保证覆盖所有模型、每一种工具、所有异常回调或服务端行为。改需求前应检索代码并确认对应版本，特别核实异步资产编号、失败重试、上传多选、分享可见性及画布文件兼容。
