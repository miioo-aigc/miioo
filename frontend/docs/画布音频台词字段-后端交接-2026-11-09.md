# 画布音频节点台词字段 后端交接

日期：2026-11-09

状态：待后端补齐接口字段。前端未改代码、未联调，不是已修复待验。

涉及接口：`POST /api/canvas-documents/{canvas_id}/resolve-assets`（批量解析画布资产）。

## 一、需求来源

用户反馈：画布音频节点卡片，从资产库选入（或上传）音频后，刚载入时卡片下方能显示台词，刷新画布后台词消失。期望：台词一直不丢。

产品结论：台词属于素材域数据，应始终由后端提供；画布文档只保存素材引用，不复制台词。

## 二、已核实的现状（前端侧证据）

| 环节 | 代码位置 | 行为 |
| --- | --- | --- |
| 选素材时的台词来源 | `src/components/AssetPickerModal.jsx:621`、`:1031` | 配音列表 `GET /api/creation/audios` 的 `text`（项目资产回退 `prompt`）映射为 `transcript` |
| 写入节点 | `src/components/canvas/CanvasAssets.js:20`、`:82` | 台词写入节点 `data.transcript`，并随画布文档一起保存 |
| 刷新时的批量解析 | `src/components/canvas/CanvasAssetResolver.js:36` | 用解析响应重建素材视图，白名单只保留素材编号、类型、名称、媒体地址、宽高时长、可用性 |
| 卡片显示 | `src/components/canvas/CanvasNodeResults.js:150`、`src/components/canvas/AudioCanvasNode.jsx:8` | 按“当前结果 + 素材编号”取台词，解析响应里没有台词字段可读，于是显示为空 |

核心结论：刷新后台词消失，不是前端漏读后端已有字段，而是解析接口没有台词字段。

补充说明：当前节点还会把台词冗余保存到画布文档的 `data.transcript`，但它只保留“最新一次结果”，无法按历史结果各自恢复；这属于前端现有的冗余存储，不作为长期数据源。

现有接口契约（`src/api/openapi.json` 中的定义）：

- `CanvasResolvedAssetItemResponse`：`asset_id / media_type / title / thumbnail_url / preview_url / poster_url / original_url / download_url / width / height / duration_ms / availability`，没有台词、文本或提示词字段。
- `GET /api/assets/{asset_id}`（`AssetResponse`）：只有 `prompt / input_prompt`，没有配音文本 `text`。
- `GET /api/creation/audios/{audio_id}`：有 `text`，但以 `audio_id` 为键；画布文档只保存 `asset_id`，没有 `audio_id`，无法反查。

## 三、需要后端补齐的内容

在 `CanvasResolvedAssetItemResponse` 上新增可空字段：

- 字段名：`transcript`
- 类型：`string | null`
- 语义：该音频素材的台词（配音文本），供画布音频节点展示；不是媒体地址，不参与鉴权。
- 取值优先级（建议，最终由后端确认）：配音记录 `text`（按 `asset_id` 关联）→ 资产 `prompt` → 资产 `input_prompt` → `null`。
- 仅对 `media_type = audio` 返回；图片、视频返回 `null` 或省略。
- 可见性与现有隐私规则一致：`availability` 为 `ready`、`trashed` 时返回台词；`forbidden`、`missing` 时不返回，与现有“不回文件名与媒体地址”保持一致。
- 请求体不变，仍按 `asset_ids` 批量解析，一次请求返回全部台词，不新增逐条查询。

响应示例：

```json
{
  "items": [
    {
      "asset_id": "33333333-3333-4333-8333-333333333333",
      "media_type": "audio",
      "title": "配音-知性女声",
      "availability": "ready",
      "original_url": "/media/xxx.mp3",
      "download_url": "/media/xxx.mp3",
      "transcript": "欢迎来到创作工作室。【轻笑】"
    },
    {
      "asset_id": "44444444-4444-4444-8444-444444444444",
      "media_type": "image",
      "title": "封面",
      "availability": "ready",
      "original_url": "/media/yyy.png",
      "transcript": null
    }
  ],
  "missing_ids": [],
  "forbidden_ids": []
}
```

同步更新后端 OpenAPI 文档，前端会相应同步仓库内的 `src/api/openapi.json` 副本。

## 四、需要后端明确的边界

1. 台词来源优先级（配音文本、`prompt`、`input_prompt`），以及用户自己上传的 mp3 没有文本时返回什么。
2. 素材台词后续被编辑时，解析响应是否跟随最新值。本方案的语义是跟随素材侧，画布刷新后显示最新台词；若产品要求“画布定稿后不再变化”，那就不是本方案，需要单独确认。
3. 空字符串与 `null` 的区别。前端两者都按“不显示台词区域”处理，可以统一返回 `null`。
4. 台词是否需要长度截断。前端按原文显示，用于配音文本预览。

## 六、验收标准

| 场景 | 通过条件 |
| --- | --- |
| 音频节点选入配音素材后刷新画布 | 卡片台词仍显示，且与素材台词一致 |
| 同一节点先后选入多条音频，刷新后切换历史结果 | 每条结果各自显示自己的台词，不互相串 |
| 素材在回收站（`trashed`） | 仍返回台词 |
| 素材无权限或已删除（`forbidden`、`missing`） | 不返回台词，节点按现有规则显示素材不可用 |
| 素材本身没有文本 | `transcript` 为 `null`，卡片不显示台词区，不报错 |
| 非音频素材 | 字段为 `null` 或省略，不影响现有解析与媒体地址 |
| 前端未升级 | 忽略新增字段，行为不变 |
