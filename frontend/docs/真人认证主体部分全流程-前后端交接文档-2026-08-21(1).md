## 1. 术语与核心概念

| 概念 | 说明 |
|------|------|
| 真人素材组（LiveMaterialGroup） | 用户完成 OneLinkAI 真人认证后获得的素材组，`group_type = "LivenessFace"`，`auth_status = "verified"`，可存放多个真人素材（图片/视频）。**主体页归档的目标容器**。 |
| AIGC 素材组 | 无需真人认证、由系统按项目自动创建（`group_type = "AIGC"`，`metadata_json.project_id` 标记项目归属），用于角色定稿图的自动认证与 Seedance 引用。 |
| 真人素材（LiveMaterialAsset） | 组内的单个素材，上游状态 `status ∈ {Processing, Active, Failed}`。主体定稿图归档 / AIGC 自动认证的产物，最终以 `asset://<upstream_asset_id>` 引用进入视频生成。 |
| 认证会话（auth-session） | 扫码认证的一次会话，**存后端进程内存**（`runtime_state.py`），TTL 120s，完成后状态保留 300s。状态：`pending / completed / failed / expired`。 |
| 绑定（subject-binding） | 主体（subject）× 真人素材组的归档关系，前端据此显示角色卡片的真人认证徽章。 |
| 上游 | OneLinkAI（`provider_type = "onelink"`），火山方舟 OpenAPI 形态（`/volc/openapi?Action=...&Version=2024-01-01`）。 |

### 关键状态机

**① 认证会话（链路 A）**
```
pending ──扫码完成、换回 GroupId──▶ completed（携带 group）
   │
   ├──result_code != "10000"──▶ failed（error_message）
   ├──缺 bytedToken────────────▶ failed
   ├──超时（120s）─────────────▶ expired
   └──会话不存在────────────────▶ expired（查询时返回）
```

**② 真人素材状态（asset.status，上游口径）**
```
Processing ──上游审核──▶ Active（可用，可被 Seedance 引用）
              │
              └────────▶ Failed（error_message 为原因）
```

**③ 主体卡片真人认证徽章（链路 B，前端归一）**
```
unverified（无归档）──归档提交──▶ pending（提交中/审核中）──▶ verified / failed
```
- `unverified`：无 binding 或无 asset → 显示「去认证 >」（青色，可点）
- `pending`：asset.status 不在 active/failed 集合，或主体正在提交归档 → 等待中
- `verified`：asset.status ∈ `{active, approved, success, succeeded, completed, ready, done}` → 显示「已认证」（绿色）
- `failed`：asset.status ∈ `{failed, error, rejected, invalid}` → 显示「认证失败」（红色，可点重新认证）

**④ AIGC 素材库同步任务（链路 C，任务制）**
```
pending ──▶ running ──▶ completed / partial / failed
（GenTask.task_type = aigc_asset_library_sync，current_stage 推进：pending→importing→authenticating→终态）
```

## 2. 全流程总览

主体相关的真人认证由**三条相互衔接的链路**组成：

```
┌─ 链路 A：真人素材组扫码认证（资产侧）──────────────────────────────┐
│  前端扫码弹窗 → 手机认证 → 上游回调 → 后端持久化 LivenessFace 组       │
│  （先有「已认证真人」文件夹，主体页才能归档）                          │
└──────────────────────────────────────────────────────────────────┘
                            ▼
┌─ 链路 B：主体页「真人人像认证」（主体定稿图归档 + 状态回显）──────────┐
│  主体页认证模式 → 选已认证真人文件夹 → 归档定稿图 → 轮询素材状态 → 徽章  │
│  GET /subject-bindings / POST /subject-final-assets ⚠️后端待核实     │
└──────────────────────────────────────────────────────────────────┘
                            ▲（并行存在）
┌─ 链路 C：AIGC 素材库自动认证（角色定稿自动入库，Seedance 前置）───────┐
│  定稿/抽主体触发 → 后台任务 CreateAsset → 轮询 GetAsset → asset:// 引用 │
│  POST /aigc-asset-library/sync-subjects（任务制，202）               │
└──────────────────────────────────────────────────────────────────┘
```

> 关系说明：链路 A 是链路 B 的**前置条件**（归档必须选已认证真人组）；链路 C 与链路 B 平行，均为「把角色图像送入上游认证 → 等待 Active → 供 Seedance 引用」，区别是 C 走项目级 AIGC 组自动入库（无需真人扫码），B 走用户真人组手动归档（带真人授权语义）。

## 3. 链路 A：真人素材组扫码认证

### 3.1 前置条件

1. 用户在设置中配置 OneLinkAI 服务商凭证（API Key + Base URL），后端 `get_user_api_key(user_id, db)` 读取；未配置则创建会话/素材时报「未配置 OneLinkAI 服务商」。
2. 后端必须配置 `PUBLIC_BASE_URL`（`settings.effective_public_base_url`），用于生成 `callback_url` 与 `launch_url`。

### 3.2 前后端调用时序

| 步骤 | 端 | 动作 | 接口 / 逻辑 | 代码事实 |
|------|----|------|------------|---------|
| 1 | 前端 | 点「扫码认证」 | `apiCreateLiveMaterialAuthSession({source})` | `liveMaterials.js` `apiCreateLiveMaterialAuthSession` |
| 2 | 后端 | 创建认证会话 | `POST /api/live-materials/auth-sessions` → 上游 `CreateVisualValidateSession`（payload `{CallbackURL}`）→ 内存写会话 state（`status=pending`，TTL 120s） | `live_materials.py` `create_auth_session`；`live_material_runtime.py` `create_live_material_auth_session` |
| 3 | 前端 | 弹二维码（内容 = `launch_url`），起轮询 | `LiveMaterialAuthQrModal` + `createSerialPolling`（2s）调 `apiGetLiveMaterialAuthSessionStatus(sessionId)` | `SeedanceAssetLibraryPanel.jsx`（`handleOpenLiveAuth` / 轮询 effect）、`LiveMaterialPickerModal.jsx` |
| 4 | 手机 | 扫码打开 `launch_url` | `GET /api/live-materials/auth-sessions/{session_id}/launch` → 302 到真实 H5 | `live_materials.py` `launch_auth_session`；`live_material_runtime.py` `resolve_live_material_auth_launch_target` |
| 5 | 上游 | 认证完成回调（三种形态） | 见 3.3 | — |
| 6 | 后端 | 换 GroupId、持久化素材组 | 上游 `GetVisualValidateResult`（payload `{BytedToken}`）→ 按 `upstream_group_id` upsert `LiveMaterialGroup`（`auth_status=verified`）→ 会话置 `completed`（保留 300s） | `live_material_runtime.py` `_complete_live_material_auth_session_with_state` |
| 7 | 前端 | 轮询到 `completed` | 关弹窗、`refreshFolders()` 刷新素材组列表、可选自动选中新组 | `SeedanceAssetLibraryPanel.jsx` 轮询 onResult |

### 3.3 回调三形态（后端兼容）

| 形态 | 触发方 | 接口 | 说明 |
|------|--------|------|------|
| 服务器 Webhook | 上游服务器 | `POST /api/live-materials/auth-sessions/{session_id}/complete` | body `{result_code, byted_token, query_params}`；需当前用户登录态（校验会话 `user_id`） |
| 手机浏览器兜底 | 手机浏览器直接跳到 callback_url | `GET /api/live-materials/auth-sessions/{session_id}/complete` | 复用同一服务逻辑，返回轻量 HTML 结果页（成功/失败，1.2s 后自动跳 `return_path`） |
| 公开回调 | 手机端官网回调页 | `POST /api/live-materials/auth-sessions/{session_id}/complete-public` | **不依赖浏览器登录态**，从会话内存态读取 `user_id`（`complete_live_material_auth_session_public`） |

### 3.4 手机端回调页（前端）

`LiveMaterialAuthCallbackPage.jsx`：
1. 从 URL query 读 `session_id / resultCode / bytedToken / source / project_id / storyboard_id / return_path`
2. 调 `apiCompleteLiveMaterialAuthSessionPublic(...)` → `complete-public`
3. 成功 → `emitLiveMaterialAuthCompleted(result)`（写 `sessionStorage['miioo_live_material_auth_result']` + 派发 `CustomEvent('miioo:live-material-auth-complete')`）→ 600ms 后 `location.replace(redirect_path)`
4. 失败 → 展示错误 + 「返回页面」按钮

### 3.5 会话状态查询契约

`GET /api/live-materials/auth-sessions/{session_id}/status`（需登录，校验会话 user_id）响应：

```json
{
  "session_id": "uuid",
  "status": "pending | completed | failed | expired",
  "group": { "id": "uuid", "upstream_group_id": "...", "provider_type": "onelink",
             "group_type": "LivenessFace", "name": "...", "auth_status": "verified",
             "last_result_code": "10000", "asset_count": 0, "created_at": "...", "updated_at": "..." },
  "redirect_path": "/projects/xxx",
  "error_message": null
}
```

前端归一函数：`normalizeLiveMaterialAuthSessionStatus`（`liveMaterials.js`）。轮询处理：`pending` 继续；`completed` 关弹窗+刷新；`failed`/`expired` 展示 `error_message` 并停止；连续 3 次错误停止。

### 3.6 关键校验（后端）

- 会话不存在 / 已过期（120s）→ `expired` 或直接报错「会话不存在或已过期，请重新发起认证」
- 回调上下文一致性：`query_params` 中 `source / project_id / storyboard_id / return_path` 必须与会话创建时一致，否则 400「真人认证回调上下文与会话不一致」
- `result_code != "10000"` → `failed`（「真人认证未成功，请完成认证后重试」）
- 缺 `byted_token` → `failed`（「缺少 bytedToken，无法换取真人素材组」）
- 上游未返回 `GroupId` → 502「真人认证失败，请稍后重试」

## 4. 链路 B：主体页「真人人像认证」（本次交接核心）

### 4.1 入口与约束

- 主体页（`SubjectPage.jsx`）工具栏「真人人像认证」按钮 → `enterPortraitAuthMode` 进入认证模式（`portraitAuthMode=true`）
- **仅角色 tab 可用**：切到场景/道具 tab 时 toast 拦截「真人人像认证仅支持角色资产」
- 进入认证模式后角色卡片显示认证徽章，普通操作（点击打开详情/语音等）被禁用，卡片交互切换为认证动作
- 提示条：请选择在 AI 生成过程中使用了真人人像作为参考的角色资产进行认证，否则无法使用 Seedance 系列模型生成视频

### 4.2 前端状态来源（两个数据面）

| 数据面 | 拉取接口 | 状态存储 |
|--------|---------|---------|
| 项目 AIGC 素材库认证回显 | `apiGetProjectAigcLibrary(projectId)` → `GET /api/projects/{project_id}/aigc-asset-library` | `aigcLibraryState` |
| 主体 × 真人组归档绑定 | `apiListProjectSubjectLiveMaterialBindings(projectId)` → `GET /api/live-materials/projects/{project_id}/subject-bindings` ⚠️ | `subjectLiveBindingsState`，并构建 `subjectLiveBindingsBySubjectId` Map |

加载时机：`projectId` 变化时并行拉取；绑定拉取后对每个 `pending` 绑定的资产起轮询（见 4.5）。

### 4.3 徽章状态推导（前端归一）

`getLiveMaterialPortraitStatus(binding)`（`SubjectPage.jsx` 顶部常量 + 函数）：

| 判定 | 徽章 | 颜色 | 可点（重新提交） |
|------|------|------|----------------|
| 无 binding / 无 asset | `unverified` | 「去认证 >」 | 青色 #2DC3E1 | ✅ |
| asset.status ∈ `{active, approved, success, succeeded, completed, ready, done}` | `verified` | 「已认证」 | 绿 #52BF92 | ❌ |
| asset.status ∈ `{failed, error, rejected, invalid}` | `failed` | 「认证失败」 | 红 #F75F5F | ✅ |
| 其他（Processing 等）或主体正在提交 | `pending` | 等待中 | — | ❌ |

叠加规则：`getPortraitAuthStatus(subjectId)` 先判 `portraitAuthSubmittingIds` 命中 → `pending`，否则用绑定状态。

### 4.4 归档提交时序

| 步骤 | 端 | 动作 | 接口 / 逻辑 |
|------|----|------|------------|
| 1 | 前端 | 点「去认证 >」→ `handleAuthenticatePortrait` | 校验角色有定稿图（`primaryImageUrl`），否则 toast「请先在角色详情中选择一张定稿图」；开 `LiveMaterialGroupPickerModal` |
| 2 | 前端 | 选真人文件夹弹窗加载 | `apiListLiveMaterialGroups()` → `GET /api/live-materials/groups`，过滤 `group_type != 'AIGC'` 且 `auth_status ∈ {verified, active, completed}` 的真人组；每组装载资产预览图与数量 |
| 3 | 前端 | 确认归档 | `apiBindSubjectFinalAssetToLiveMaterialGroup(groupId, {projectId, subjectId})` → `POST /api/live-materials/groups/{group_id}/subject-final-assets` ⚠️，body `{project_id, subject_id}` |
| 4 | 后端 | （预期）把主体当前 primary 定稿图提交进该真人组并返回绑定 | ⚠️ 本地 backend 未见该路由实现，见第 8 节 |
| 5 | 前端 | 按返回绑定分派 | `verified` → toast 成功「已归档到真人文件夹」；`failed` → toast `asset.error_message`；`pending` → toast「定稿图已存入真人文件夹，正在等待审核…」+ 起轮询 |

提交期间主体进入 `portraitAuthSubmittingIds`（按钮显示「提交中…」），完成后移除。

### 4.5 归档后素材状态轮询

`startSubjectLiveAssetPolling(binding)`（`SubjectPage.jsx`）：
- 触发条件：有 `subjectId` 与 `asset.id` 且 `getLiveMaterialPortraitStatus(binding) === 'pending'`
- 轮询：`createSerialPolling`，间隔 **3s**，调 `apiGetLiveMaterialAsset(assetId, {refresh: true})` → `GET /api/live-materials/assets/{asset_id}?refresh=true`（后端 `refresh_live_material_asset_status` → 上游 `GetAsset`）
- 结束：状态离开 pending → 停轮询；`verified` → toast「已完成真人认证」；`failed` → toast `asset.error_message || '真人认证失败，请重新选择文件夹提交'`
- 生命周期：以 `subjectLiveAssetPollersRef` 管理，按主体维度 stop；组件卸载 / 切换项目时全部 stop（页面卸载只停观察，服务端任务不中断）

### 4.6 定稿图更换的失效策略

`handleSubjectFinalized`：主体更换定稿图后，**旧的真人归档不再代表当前角色** → 停该主体轮询、从 bindings 中移除旧绑定 → 徽章回到 `unverified`，用户需重新选择真人文件夹提交。

## 5. 链路 C：AIGC 素材库自动认证（任务制）

### 5.1 触发时机（纯后端调度 + 前端显式同步）

- 角色定稿（`apiSetPrimarySubjectImage`）成功后自动触发 `auto_dispatch_subject_aigc_asset_sync`（source=`subject_image_auto`）
- 主体抽取完成 / 用户手动「重新认证」→ 前端调 `apiSyncProjectAigcSubjects(projectId, {source})` → `POST /api/projects/{project_id}/aigc-asset-library/sync-subjects`（source=`subject-extraction` / `retry`）

### 5.2 后端调度契约（sync-subjects，202）

- 筛选：仅 `subject.type == 'character'` 且有 primary 定稿图（`Asset.is_primary=true, is_deleted=false`）的主体；scene/prop/type 为空或脏数据一律跳过
- 确保项目级 AIGC 组存在（`create_aigc_asset_group` + `metadata_json.project_id` 标记，与 aigc-asset-library 共用一组）
- 创建 `GenTask`（`aigc_asset_library_sync`，`pending`）→ `dispatch_background_job`（`_run_sync_task`）
- 响应 `{taskId, status, groupId, projectId, totalCount}`（**任务制**，非最终结果，禁止误当完成）

### 5.3 后台任务 `_run_sync_task` 执行逻辑

| 阶段 | 逻辑 |
|------|------|
| importing | 逐主体：已存在素材（`metadata_json.subject_id + primary_asset_id` 匹配）且非 failed → 复用并保留状态；failed → 重新提交；无 → `resolve_auth_ready_public_url`（`/uploads/` 图 → `persist_remote_file` → 对象存储公网 URL；已是 http(s) 直接返回）→ `create_live_material_asset`（上游 `CreateAsset`，`GroupId=AIGC组, URL, AssetType=Image, Name=主体名`） |
| authenticating | 30 轮 × 2s 轮询 `refresh_live_material_asset_status`（上游 `GetAsset`）；终态判定：active 集合 `{active, ready, available, verified}`；failed 集合 `{failed, error, rejected, invalid}`；超时 → failed + 可读错误「上游素材认证超时，素材未变为 Active」 |
| 收口 | `task.status = completed（全成） / partial（部分） / failed（全败）`；`current_stage` 推进 `pending→importing→authenticating→终态`；单主体错误不回滚其它主体 |

### 5.4 前端观察与回显

- `waitForProjectAigcTask(projectId, taskId)`：SSE 唤醒优先、低频读取兜底（`readTask` 轮询 `GET /api/projects/{project_id}/aigc-asset-library/tasks/{task_id}`，8s 起、最大 60s）；**卸载只停止观察，不取消服务端任务**，可凭 taskId 恢复
- 终态后刷新库 `apiGetProjectAigcLibrary` → 主体页 AIGC 素材库面板回显（素材组 ID、认证状态、系统内素材 ID 可复制、`asset://` 引用、重新认证）
- **行为约定（2026-08-11）**：认证轮询到终态后**不自动跳转分镜页、不自动开始抽分镜**；用户留在主体页查看回显，手动点「开始抽分镜」才启动（`Home.jsx` `startProjectAigcSync` 的 `navigate` 默认 `false`）

## 8. ⚠️ 对齐重点与已知缺口（落后工程务必先核实）

1. **`subject-bindings` 与 `subject-final-assets`：本地仓库落后于线上（最高优先级）**
   前端 `liveMaterials.js` 已定义并调用；本地 `backend/app/routers/live_materials.py`（文件日期 07-25）**未包含**这两个路由，但**线上 115 主机已存在**（`GET /api/live-materials/projects/{project_id}/subject-bindings` curl 探测 200/401，路由已注册仅需鉴权）→ **本地 backend 代码落后于线上**。对齐动作：
   - 落后工程先**同步线上 115 的最新 backend 代码**（`backend_releases/` 最新发布 / supervisor 运行目录），以线上实现为准；
   - 若需在本地仓库改造，先把这两个路由实现从线上拉回 `backend/app/routers/live_materials.py` 再动；
   - 参考契约（前端已固化的期望结构）：
     - `GET /api/live-materials/projects/{project_id}/subject-bindings`：返回该用户该项目的绑定数组，每项含 `subjectId / subjectName / subjectType / primaryAssetId / group / asset`
     - `POST /api/live-materials/groups/{group_id}/subject-final-assets`：body `{project_id, subject_id}`，把主体当前 primary 定稿图（`Asset.is_primary=true, is_deleted=false`）提交进真人组（可复用 `create_live_material_asset` + `resolve_auth_ready_public_url`），返回同一绑定结构

2. **active / failed 状态集合口径差异**
   前端 `SubjectPage.jsx`：active = `{active, approved, success, succeeded, completed, ready, done}`，failed = `{failed, error, rejected, invalid}`；
   后端 `live_material_runtime.py`：active = `{active, ready, available, verified}`，failed = `{failed, error, rejected, invalid}`（多了 `available`、少了 `approved/success/succeeded/completed/done`）。
   后端素材序列化时 `status` 原样透传上游值（首字母大写，如 `Active`），前端小写化后比对。对齐时建议统一常量，避免「后端判 active 但前端显示 pending」的窗口。

3. **会话状态存进程内存**：TTL 120s、completed 保留 300s；多实例部署下回调可能落在不同进程 → 确认线上是否单进程 supervisor 部署；若多进程需换共享存储。

4. **上游 Payload 字段坑**：查询/删除素材与素材组时 payload 必须用 `Id`（不是 `AssetId` / `GroupId`）；`GetVisualValidateResult` 用 `BytedToken`。

5. **仅 character 自动认证**：scene / prop / type 为空的历史主体不进 AIGC 自动认证链路（`auto_dispatch_subject_aigc_asset_sync` 明确跳过），但主体页手动归档不限制类型之外的约束（实际入口仅角色 tab）。

6. **任务制语义**：`sync-subjects` 返回 202 + `taskId`，禁止把创建响应当最终结果；任务轮询有 8s→60s 退避 + SSE 唤醒，页面卸载不取消任务。

7. **行为约定**：认证完成不自动跳转分镜（2026-08-11 起），与旧行为（自动打开分镜）不同，落后工程勿按旧版本对齐。

## 10. 配置与运维注意

1. `PUBLIC_BASE_URL` 必须配置，否则无法创建回调地址 / 扫码链接
2. 对象存储写入需启用（`object_storage_write_enabled`），文件上传与 `/uploads/` 图转公网 URL 依赖它

5. 非破坏性部署：用 `deploy_backend_code_preserve_runtime_*.sh`，不覆盖线上 `.env`，保留 uploads 与 .venv
