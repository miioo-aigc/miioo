# 节点工作流修改：冲突与方案讨论

日期：2026-11-05。用途：产品交接，记录最新确认及待设计事项，尚不是完整开发规格。
依据：两版《节点输入框功能修改交接说明》、需求方后续确认及当前画布代码静态审查。未修改业务代码，未进行浏览器或真实生成验证。

## 一、目标理解

根据需求方补充，核心诉求是保留成熟工作流：重复使用时，可以更新固定节点的内容，不因每次生成而不断新增步骤、改变原有连接结构。

需要区分两种目标：
- 保持结构稳定：节点身份、连接关系保持不变，内容允许更新。
- 保留完整版本：历史节点内容、生成配置和当时输入也能恢复。原位更新本身不提供这项能力。

## 二、最新确认：多候选、单一定稿

以下为需求方在产品新版回复后的最新确认，替代此前“每张图片独立成节点”的要求：

- 一个节点代表一个固定任务，单张或批量生成都回到当前节点，不因执行新增节点或连线。
- 多张候选留在同一个节点；提供展开入口，同时查看全部候选，收起时展示当前定稿。
- 候选不能单独取出成为节点，不能单独连接下游；每个节点有且只有一个当前定稿对外输出。首次尚无结果时暂不存在可用定稿。
- 首次生成成功，默认将第一张成功返回的候选设为当前定稿。
- 已有定稿时，再次生成保留旧定稿，由用户明确选择新候选后才切换；此规则同样适用于再次单张生成。
- 更换定稿不改变连线，不自动执行下游；下游再次执行时使用新定稿，已有下游结果保留。
- 文本正文属于输出；上传到生成节点主体的内容属于结果替换，不自动成为自身输入。

此前“批量必须新增独立节点”的冲突已随需求变更解除。“第一张更新当前节点、其余新增同级节点”的旧建议不采用。

当前没有多结果节点的交互设计。本次已扩展为节点结果管理改造，需要设计收起／展开、候选比较、选为定稿、历史批次、生成中和失败状态；候选选定与图片预览应可区分。

## 三、其余需补齐的规则

| 缺口 | 需要明确的行为 |
|---|---|
| 素材与生成节点混用 | 已明确上传到生成节点主体是结果替换；仍需区分独立素材节点入口与明确添加参考的入口。 |
| 草稿与生成记录 | 修改后的草稿、执行快照、旧结果对应的配置需区分；明确刷新后恢复范围。 |
| 执行期间修改 | 改配置、换素材、改连线后，返回结果如何回填，不能覆盖后来编辑的草稿。 |
| 下游依赖 | 上游正在生成时，下游可否使用旧结果；上游替换后不应把旧下游结果误认为已同步。 |
| 参考一致性 | 连线与附件统一校验；模型切换后的无效输入及视频首尾帧顺序需明确。 |
| 文本规则 | 已明确正文是输出；仍需确认只有上游文本时能否不填提示词。 |
| 历史画布 | 旧逻辑自动继承的参考关系如何兼容，不能未经区分自动删除历史连接。 |
| 失败与部分成功 | 保留原结果；批量部分成功时保留成功图片，并说明补生成规则。 |

## 四、两个候选方案

本节仅保留此前讨论，不代表当前实施方案。最新方向采用第二节的多候选、单一定稿模型；不以开关切回旧生成逻辑，也未确认完整的四来源替换菜单。

### 方案一：输入框增加“在当前节点生成”开关，默认开启

- 优势：单张原位更新直接，关闭时可保留既有新增结果流程。
- 局限：多张独立出图仍会新增节点；需明确开启时数量大于一的处理。两个模式也可能采用不同的输入规则，不能只改变结果位置。
- 必须明确：开启时是否排除当前结果作为输入、开关是否按节点保存、历史节点默认状态。默认开启会改变既有用户的执行行为。
- 技术判断：可实现，但涉及生成计划、参考数量校验、回填和保存，不是纯界面修改。

### 方案二：节点增加“替换”入口

来源：本地上传、从资产中选择、从当前画布选择、直接在当前节点生成。

- 优势：将固定工作流节点视为可更新的内容位置，现有探索式生成和批量出图可继续保留；已有上传及资产写入逻辑可部分复用。
- 局限：如果普通发送仍新增节点，则不满足原文“所有输入框执行均原位更新”，需要产品接受调整需求。
- 必须明确：替换只更换内容还是同时替换任务配置；画布选择是复制当时素材还是建立持续引用；直接生成是否只允许单张。
- 技术判断：可实现，但“从当前画布选择”需要补入口；直接原位生成仍需修改生成与回填逻辑。当前上传会先写入本地预览，如要求失败保留旧结果，不能原样复用。

## 五、当前代码依据

- `src/components/canvas/CanvasImageGeneration.js`：已有结果参与自身参考，批量图片分别创建结果节点。
- `src/components/canvas/CanvasVideoGeneration.js`：视频结果目前只回填空素材节点。
- `src/components/canvas/CanvasTextGeneration.js`：文本自身正文参与输入，空节点回填包含上游正文。
- `src/pages/CanvasPage.jsx`、`src/components/canvas/CanvasAssets.js`：已有按节点写入资产的基础逻辑；多选导入会新增节点，替换入口不能直接沿用全部行为。
- `src/components/canvas/UseCanvasMediaControls.js`：部分生成参数保存在组件内部，需补齐任务配置的保存恢复。

## 六、后续设计与规格补齐

- 先补齐多结果节点设计，再实施生成计划、候选回填、定稿选择、下游取值及保存恢复。已有模型请求、上传和素材预览可部分复用。
- 明确历史候选的保存、分批查看与恢复；新版已将旧候选可查看列为验收项，不能整体作为可选配套事项省略。
- 明确失败保留、执行中编辑、输入版本和旧画布兼容；尚未确认的建议不能写成已定规则。
- 节点候选历史不等于整张工作流的历史版本；是否需要恢复整张画布某次运行时的全部内容和配置，仍未确认。
