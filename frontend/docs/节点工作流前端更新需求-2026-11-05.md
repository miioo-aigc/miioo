# 节点工作流前端更新需求

日期：2026-11-05。对象：产品、设计、前端及接口协作人员。

本文根据两版产品交接说明及需求方后续确认整理，作为最新前端交接入口。仅编写文档，未实施业务代码，未打开浏览器或验证真实生成。代码现状以本次静态审查为准。

## 1. 阅读约定与结论

- **已确认**：来自本轮产品回复及需求方明确确认，开发不得沿用已被替代的旧方案。
- **实现约束**：为落实已确认规则需要满足的数据一致性条件；不指定具体视觉形式。
- **建议待确认**：尚未定案的交互、异常策略或范围，不能视为已获批准。

本次不是单纯增加输入框开关，而是“固定任务节点、多候选结果、单一定稿输出”的改造。需要补设计，调整生成、引用、结果存储和恢复。已有模型调用、上传、素材预览等能力可部分复用。

## 2. 目标、范围与非目标

### 2.1 目标

让成熟工作流可重复使用：节点代表稳定任务，生成及定稿更新不改变节点身份和连接结构。候选的查看与选择在节点内完成，画布连接只表达任务之间的输入关系。

### 2.2 本次范围

- 文本、图片、视频节点的输入框只配置和执行当前节点。
- 取消因已有结果而自动创建下一结果节点的行为。
- 图片单张及批量结果进入当前节点，支持候选展开、比较、定稿选择和历史查看。
- 输入与输出分离；上传到生成节点主体是结果替换。
- 配置保存、生成快照、当前定稿、候选与历史批次的保存恢复。
- 相关复制、撤销、导入导出、分组和分享兼容。

### 2.3 不自动纳入的范围

- 不增加“关闭后恢复旧生成行为”的开关。
- 不允许把某个候选拆成独立节点，不允许候选单独连线。
- 不自动执行下游，不自动运行整条工作流。
- 节点历史不等于整张工作流的版本快照；整张工作流按历史运行恢复不在已确认范围。
- 音频节点已有独立生成及文本同步逻辑，本次未确认调整，须回归验证不受共享模块改动影响。
- 图片、视频工具栏中的裁剪、扩图及其他编辑任务是否改为原位结果管理，尚未确认；不得将“输入框执行不新增”直接扩展为所有工具动作。
- 四来源“替换”菜单及“从当前画布选择”未整体确认，不因曾讨论过而自动加入。

## 3. 核心概念

| 概念 | 定义 | 不应混淆的内容 |
|---|---|---|
| 任务节点 | 有稳定身份和输入连接的任务载体 | 不是一张图片或一次请求的临时容器 |
| 配置草稿 | 当前正在编辑的提示词、模型、参数 | 不等于旧定稿的生成配置 |
| 输入素材 | 明确连接的直接上游输出，或主动添加为参考的素材 | 不包含节点自身结果，不自动递归累加祖先素材 |
| 执行快照 | 一次执行实际使用的配置和输入版本 | 发送后不可被后续草稿修改 |
| 候选结果 | 某次生成或结果替换产生的可选内容 | 不拥有画布节点身份和端口 |
| 当前定稿 | 当前节点唯一对外输出的结果 | 可以更换，不表示永久锁定 |
| 候选批次 | 按一次执行或替换操作组织的候选集合 | 不等于旧定稿历史，也不等于撤销栈 |
| 结果历史模块 | 节点内查看曾经作为定稿、后被替换结果的入口 | 不等于候选列表、撤销栈或全工作流历史 |
| 独立素材节点 | 承载导入素材、供其他节点引用的节点 | 与上传内容替换生成节点结果不同 |

同一节点可同时存在“旧定稿、旧定稿的生成记录、新候选、新配置草稿”，这些内容不能靠覆盖同一组字段表达。

## 4. 已确认的产品规则

### 4.1 输入框与创建下一步

1. 首次生成、再次生成和失败重试都执行当前节点，不因执行新增节点或连线。
2. 输入框跟随选中的生成节点，切换或取消选中不丢失已填写草稿。
3. 提示词、模型、比例、分辨率、数量、时长、模式等属于当前任务配置。实际可用参数以模型能力为准。
4. 当前节点有无结果不改变输入框作用对象。
5. 继续加工必须显式创建并连接目标节点。右侧“＋”可完成创建、连线、选中和展开输入框，但不自动执行。
6. 图片数量大于一仍只运行当前任务，不能回退到旧的多节点生成流程。

### 4.2 参考输入

1. 自身定稿、其他候选、历史结果都不自动成为自身参考。
2. 只读取当前任务明确指定的直接输入；不能因上游曾引用其他节点就自动把这些祖先再次提交。
3. 上游作为输入时，只提供其当前定稿，不提供全部候选。
4. 参考区显示、数量限制、首尾帧角色及实际请求材料必须来源一致。
5. 通过连线引入的输入，移除时必须同步断开关系；若界面不允许直接移除，应提供断线入口。
6. 主动添加的参考有移除入口；不得误删其独立素材节点，除非用户另行执行删除节点操作。
7. 文本正文属于输出，不能自动将自身正文作为生成输入，也不能把上游原文直接拼入新输出冒充生成结果。

### 4.3 多候选与定稿

本节的候选比较、默认选定及再次生成后手动选定规则，以图片节点为已确认范围。文本、视频已确认原位执行、不自动新增节点；其新旧结果选择方式仍见第 11 节，不应直接视为已确认采用图片方案。稳定节点身份、单一对外输出及不自动执行下游是共同约束。

1. 一次批量生成的全部有效图片保留在当前节点，支持展开后同时比较。
2. 收起时显示当前定稿；未选中的候选不对外输出。
3. 候选没有独立画布端口，不能拆出、拖出或复制为独立节点。节点整体复制与候选拆出是不同能力。
4. 首次生成成功默认选第一张成功返回的候选。第一张按返回的稳定结果索引确定，不按缩略图加载完成顺序确定。
5. 已有定稿后再次生成，保留旧定稿；即使只生成一张，也由用户明确选择后才切换。
6. 新批次不能覆盖旧批次。旧候选可查看，并可通过明确的定稿选择操作重新使用。
7. 定稿被新结果替换时，原定稿必须保留并进入节点内新增的“结果历史”模块，可查看其内容及必要来源信息；不得因设定新定稿而覆盖或丢失旧定稿。
8. 结果历史模块须支持查看历史结果；历史结果如何重新设为当前定稿，应通过明确操作完成，不能在浏览时自动切换。
9. 预览图片与设为定稿必须是可区分的操作。展开、收起、浏览候选／结果历史及预览不得隐式更换定稿。
10. 不得同时出现两张有效定稿；首次尚无成功结果时允许没有定稿。

### 4.4 上传为结果

1. 上传到生成节点主体的内容用于设为当前结果，不是添加参考。上传入口与添加参考入口需清楚区分。
2. 上传成功后的内容成为定稿，后续下游执行使用它；连接关系不因上传改变。
3. 上传结果须标识真实来源，不能声称由当前提示词和模型生成。原有配置草稿不能因换图无意丢失。
4. 独立上传素材节点与生成节点内替换结果应具有明确的行为区分；具体入口需补设计。
5. 一次选择多个文件用于结果替换时如何处理未确认，不能直接沿用“首项替换、其余新增节点”的旧导入逻辑。

### 4.5 下游读取

1. 所有输出连线连接节点本身，只读取当前定稿。
2. 新候选生成完成但尚未被选为定稿，不改变下游的有效输入。
3. 切换定稿不改线、不自动执行下游，下游已有结果保留。
4. 下游下一次执行使用当时选定的上游定稿，并记录具体结果身份和内容版本。
5. 草稿变化、候选增加、定稿切换应区分；前两者不能误判为有效输出已更新。

## 5. 状态与异常边界

本节区分确认规则与建议。建议项须产品确认后进入最终验收，不应由开发静默选定。

涉及多候选、首次默认选定和再次生成保留旧定稿的条目，按第 4.3 节的图片范围理解；其他类型的选择策略待确认。

| 场景 | 已确认／实现约束 | 建议待确认 |
|---|---|---|
| 无结果首次执行 | 不新增节点；成功后建立候选并默认选择首个有效结果 | 空态及首次加载表现 |
| 有定稿再次执行 | 成功后新增本节点候选，旧定稿不自动改变 | 是否自动展开最新批次 |
| 同节点正在执行 | 阻止重复提交，使用请求身份避免迟到结果误写 | 是否提供取消入口 |
| 多节点并发 | 不应因单节点改造丢失现有请求管理 | 保持现有并发限制，若统一三类限制需另确认 |
| 全部失败 | 失败不能被当成一次定稿切换 | 保留旧定稿、草稿并显示节点级错误与重试；不创建空候选 |
| 部分图片成功 | 成功结果不得丢失，索引不能错配 | 保存成功项并提示实际数量；首次选首个成功项；补生成建立新批次 |
| 空返回或重复回调 | 不生成虚假成功项；同请求结果幂等写入 | 空返回按失败展示 |
| 执行中改草稿 | 执行使用发送快照；返回不能覆盖后来编辑的草稿 | 允许编辑下次配置，界面区分运行配置与当前草稿 |
| 执行中改连线 | 不改变已发请求的输入快照，不得恢复已删连线 | 新连线仅作用于下一次执行 |
| 执行中上传／切换定稿 | 异步响应不能无意覆盖用户后来选定的结果 | 允许操作，完成时只追加候选；需操作序号校验 |
| 上游生成中 | 未切换的旧定稿仍是当前输出 | 有旧定稿则允许下游执行；没有可用定稿则阻止并说明原因 |
| 下游执行中上游切换定稿 | 下游此次仍对应已提交版本，不能改记为新版本 | 返回时标记所依赖输入已更新 |
| 定稿切换后 | 保留旧下游结果，不自动执行 | 直接依赖节点提示输入已更新；祖先变化与直接输入变化区分 |
| 无效／无结果上游 | 不能展示已使用却实际静默省略该必需输入 | 阻止执行并定位缺失项；不自动换成其他候选 |
| 上传失败 | 不能把临时地址当成可持久化结果 | 上传完成并取得有效资产编号后再切换，失败保留旧定稿 |
| 候选删除 | 当前未确认结果删除能力 | 首期不增加；若增加，禁止删除定稿后自动随机选其他图片 |
| 删除节点、离开画布 | 请求与节点／会话绑定，不能回填到其他画布或复活已删节点 | 延续取消和清理策略，不额外承诺刷新续跑 |
| 撤销／重做 | 不能把已返回结果错误关联到另一请求 | 定稿切换、上传替换可撤销；异步候选不因撤销拖动而丢失 |
| 循环连接 | 自引用不允许；更长的环不因本次自动形成或修复 | 是否禁止所有有向环另行确认 |

还需明确：首尾帧顺序、模型切换后的超限输入、必填提示词规则、上传替换旧定稿是否进入历史。统一遵循第 11 节待确认表。

## 6. 必须补齐的设计稿

现有单素材节点样式不能完整覆盖以下交互。设计应沿用项目设计系统，先确定操作、状态和布局，再实现。

| 设计项 | 稿件必须说明的内容 | 类型 |
|---|---|---|
| 收起节点 | 定稿展示、候选数量、展开入口、无定稿状态、生成中标识 | 新设计必需 |
| 候选展开 | 同时查看多图的布局、容器边界、收起、滚动、当前批次与历史入口 | 新设计必需 |
| 选择定稿 | 当前定稿标识、预览与选定分离、选定后的反馈 | 新设计必需 |
| 结果历史模块 | 入口位置、历史记录列表、查看方式、来源与时间信息、空状态、重新设为定稿的明确操作 | 新模块设计必需 |
| 候选批次 | 批次标识、时间、数量、查看和选定候选；当前定稿可能属于旧批次 | 新设计必需，与结果历史模块区分 |
| 生成及错误 | 旧定稿与进度共存、部分成功、失败重试、无结果错误 | 新状态必需，可复用反馈组件 |
| 上传与参考 | 主体上传替换、添加参考、独立素材导入三个入口及反馈的区别 | 交互稿必需 |
| 输入状态 | 配置已改未执行、实际执行记录、模型不可用、超限输入 | 状态设计必需 |
| 下游更新 | 定稿变化后的提示位置、内容和消失条件 | 启用提示方案时必需 |
| 文本／视频 | 新结果等待选定时如何呈现，文本比较／视频预览及历史入口 | 范围待定，不能直接套图片网格 |
| 分享页 | 是否可只读展开候选和历史；不能修改定稿 | 范围确认后补稿 |

展开形式尚未指定：节点尺寸扩展、浮层或侧面板都不是已定设计。必须说明展开是否改变节点布局尺寸、是否遮挡其他节点、是否影响连线锚点和分组边界。无论视觉形式如何，候选仍属于原任务节点。

设计验收需覆盖：1 张、2 张、多张、不同宽高比、最新批次无定稿、旧批次有定稿、加载失败、大量历史、低缩放、展开组及折叠组、窄窗口。图片不因缩略图加载改变选中身份；文字和工具不互相遮挡。

## 7. 前端逻辑改动清单

以下为修改边界，不要求把新功能堆入页面入口，也不指定最终新增组件名。

| 模块／文件 | 当前情况 | 需要调整 |
|---|---|---|
| `CanvasImageGeneration.js` | 自身图片参与输入；多图创建多个节点；仅空素材回填 | 排除自身输出；统一输入源；一节点多结果计划、批次回填与定稿规则；取消结果节点布局 |
| `UseCanvasImageGeneration.js` | 请求对应多个结果节点 | 节点级请求管理；保存完整请求快照；按返回索引收纳候选；支持部分失败和永久编号检查 |
| `CanvasTextGeneration.js` | 自身正文参与输入；有正文创建新节点；空节点拼接上游原文 | 只读明确上游；原位任务；输出仅为模型返回正文；结果与草稿分离 |
| `CanvasVideoGeneration.js`、`UseCanvasVideoGeneration.js` | 自身视频参与参考；有结果新增节点；只回填空素材 | 取消自身输入和自动新增；收纳新结果；统一输入角色顺序；补查结果资产编号 |
| `CanvasCreationPanel.jsx`、`UseCanvasMediaControls.js` | 提示词可同步节点，媒体参数主要由组件内部持有 | 全量草稿写入节点并恢复；发送只读统一快照；生成中状态不丢草稿 |
| `CanvasPromptReferences.js`、`CanvasReferences.js`、`UseCanvasReferences.js` | 展示与请求各自收集输入；存在自身参考 | 共用有效输入解析；直接上游仅取定稿；移除与断线同步；上限只统计输入 |
| `CanvasNodeShell.jsx`、`ImageCanvasNode.jsx` 等 | 单素材展示 | 编排定稿、展开、候选和历史；端口仍属节点；工具默认作用对象明确 |
| `CanvasPage.jsx`、`CanvasAssets.js` | 资产可写入当前节点；多选其余项新增节点 | 区分导入、结果替换和添加参考；不把旧批量导入直接用于新替换 |
| `CanvasDocument.js`、`CanvasAssetResolver.js` | 保存及解析主要围绕当前 `asset` | 保存全部结果资产身份、批次、定稿及快照；按需解析候选资产，兼容旧格式 |
| `CanvasHistory.js`、`CanvasNodeActions.js` | 字段差异历史及节点复制 | 深拷贝候选结构；剥离运行态；结果身份和节点引用映射；撤销不破坏异步结果 |
| `CanvasFile.js` | 文件校验、导入导出依赖节点复制协议 | 校验新结构；保留候选与定稿对应；内部节点引用重映射；兼容旧文件 |
| `CanvasShareDocument.js`、`SharedCanvasNode.jsx` | 公开资产按单个 `assetId` 匹配 | 至少正确展示保存的定稿；候选和历史曝光范围须先确认 |
| 分组、导航器、搜索、预览及编辑工具 | 大量读取 `data.asset` 或 `content` | 统一读取当前定稿投影；候选不计作节点；展开不破坏分组、定位和端口 |

保留单份 `asset`／`content` 作为当前定稿兼容投影是可选实现方式，不是产品数据格式要求。如采用，必须由定稿统一派生，不能与候选中的内容各自更新。

## 8. 数据与接口约束

### 8.1 建议的数据职责

字段名称由实现确定，以下仅表达职责，不是现有后端接口。

| 数据 | 必要信息 |
|---|---|
| 草稿 | 提示词及富文本引用身份、模型、有效参数、输入关系 |
| 候选批次 | 稳定批次编号、请求编号、时间、状态、请求数量、结果列表 |
| 执行快照 | 实际模型及参数、提示词、输入节点／结果身份、资产编号或文本版本 |
| 结果 | 稳定结果编号、所属批次、返回索引、类型、内容／永久资产编号、来源 |
| 定稿 | 选定结果编号及可区分每次有效输出变化的版本信息 |
| 结果历史 | 曾任定稿且后被替换结果的稳定引用、替换时间及可追溯来源；资产不得因不再是定稿而释放 |
| 依赖记录 | 下游本次生成使用了哪个上游的哪个定稿版本 |
| 临时界面状态 | 展开、预览、加载、请求控制器；不得误存可执行函数或临时地址 |

同一素材在不同批次出现时，结果身份与资产身份可不同；不得仅凭图片地址去重掉真实执行记录。定稿编号必须指向有效结果。

### 8.2 保存与恢复

- 必须恢复草稿、候选批次、结果历史和当前定稿；仅保存当前图片无法满足历史验收。
- 永久资产编号是保存依据，临时预览地址不能代替。候选同样需要资产解析，不能只解析当前定稿。
- 不应把运行中的请求控制器、加载状态作为可恢复任务保存；刷新续跑能力须另确认。
- 现有保存会排除运行态，且生成中暂停保存；新增历史后需明确批次终态和失败状态保存方式。
- 多资产列表能否由现有文档协议保存、资产接口能否返回全部编号、分享接口能否授权解析候选，需前后端核实；不得预先声称纯前端可全部完成。
- 当前视频回填未完整携带永久资产编号，现有保存对此有校验；必须核实真实响应和接线，避免新结果仍不能保存。
- 任一候选无法持久化时不得悄悄丢弃并提示保存成功；如何提示、重试或保留待保存内容需确定。
- 不自动裁剪历史；容量上限、分页、删除和存储成本须评估，明确后才能制定保留策略。
- 结果历史模块中的旧定稿记录不得仅依赖撤销栈保存；撤销记录过期或被清理，不得导致产品历史消失。

### 8.3 老数据兼容

- 旧节点只有单份素材或正文时，可映射为一份既有结果及当前定稿，不凭空补造历史模型参数。
- 无法证明来源的旧内容标为既有内容，不伪称某次生成。
- 保留旧节点身份、位置和既有连接，不自动合并旧批量结果节点。
- 旧链路中自动继承的参考不能未经区分删除；新执行不再额外加入自身输出，但现有显式引用需保持可见。
- 新旧文档及文件格式需要版本判断；无法识别的新结构不能被旧读取逻辑静默降级后覆盖保存。

## 9. 跨功能边界

- 复制整个节点应得到独立任务状态，不能共享可变候选数组或复制运行中请求；是否携带全部历史需确认。
- 复制节点后，执行快照中的历史来源身份不能被误改为“这次已重新生成”；可执行输入连接与历史来源记录应分开。
- 候选展开不增加节点数量，不影响导航器条目、节点编号和自动布局统计。
- 分组折叠预览、下载、图片编辑和视频工具默认应读取当前定稿；候选级工具是否提供须设计确认。
- 分享只读页不得提供改定稿或生成操作；是否公开非定稿候选和历史必须明确，不能因保存了就全部公开。
- 上传仅接受目标节点允许的结果类型；视频参考可接受图片，不代表图片可当作视频节点的最终视频结果。
- 图片尺寸变化后，节点及端口尺寸要同步；展开比较的尺寸变化不能误写为任务连接变化。
- 本次不允许候选拆出，但不能误删已有“复制整个节点”功能；两者需在交互与代码中区分。

## 10. 验收清单

### 10.1 已确认规则验收

1. 空图片节点执行单张生成：节点编号不变，节点及连线数量不增加，成功结果成为定稿。
2. 空图片节点执行多张生成：全部有效图片属于同节点，展开可同时比较，默认第一张为定稿。
3. 缩略图加载顺序变化不改变默认定稿；结果索引缺项不发生错配。
4. 已有定稿再次生成一张或多张：旧定稿保持，新结果可查看，用户明确选择后才切换。
5. 切换定稿后，原定稿仍能从结果历史模块找到并查看；再次切换时，新被替换的定稿也进入历史，不覆盖既有历史记录。
6. 从结果历史查看旧结果不会自动切换定稿；用户明确执行恢复／设为定稿后才改变节点输出。
7. 收起、展开、预览和切换候选批次不隐式改变定稿；任意时刻最多一份有效定稿。
8. 候选无独立端口，不能取出成为节点；展开不增加节点和连线。
9. 建立“原图甲→生成节点乙”，执行乙不把乙自身结果加入参考，界面参考与请求实际材料一致。
10. 乙有多张候选时，下游丙只接收乙的定稿；乙增加新候选但不换定稿时，丙输入不变。
11. 乙切换定稿后，丙旧结果保留、不自动执行；丙再次执行使用新定稿。
12. 上传到乙主体的内容成为乙结果，不进入参考区，不改变连接；添加参考入口仍只更新输入。
13. 文本执行不使用自身正文，不把上游原文拼到返回正文中；结果保留在原节点。
14. 图片连接视频节点后，视频执行不新增节点，自身旧视频不自动进入参考。
15. 切换节点再返回，提示词、模型及各项参数草稿保持；保存后重开可恢复候选批次、结果历史及定稿。
16. 使用右侧“＋”创建目标节点只创建、连线并选中，不自动发请求。

### 10.2 一致性与回归验收

1. 快速重复提交、迟到回调、节点删除和画布切换不会重复写入或串写其他节点。
2. 执行记录与实际提交对应，后续草稿编辑不能改写旧记录。
3. 模型切换后的非法输入有明确反馈，不静默遗漏；首尾帧展示顺序与实际提交相同。
4. 旧画布及旧导出文件不丢内容和连接，不自动合并历史节点。
5. 复制、粘贴、撤销、重做、导入、导出不产生无效定稿编号或共享可变状态。
6. 资产恢复失败明确显示，不自动换定稿；分享页按确定的公开范围正确展示定稿。
7. 分组、导航、预览、下载及现有音频功能正常；候选不混入节点统计。
8. 部分成功、上传失败、执行中编辑、运行中刷新等按最终确认的第 5 节策略验收。

视觉效果由需求方手动验证，不自动打开浏览器。实施后应按仓库要求完成定向检查、构建和必要逻辑测试；本次仅写文档，不报告上述检查已通过。

## 11. 设计前需定案的事项

| 优先级 | 待确认事项 | 推荐方向，未定案 |
|---|---|---|
| 必须先定 | 文本、视频再次生成是否同样等待用户选定新结果 | 统一“有定稿不自动替换”；为文本／视频补适合的比较入口 |
| 必须先定 | 展开形式及历史批次展示方式 | 先定节点尺寸、滚动与分组边界，避免开发自行选布局 |
| 必须先定 | 失败和部分成功规则 | 保留定稿及草稿；成功项留存，失败项明确提示 |
| 必须先定 | 执行中是否允许改草稿、连线、上传和定稿 | 允许但使用不可变执行快照及操作版本保护 |
| 必须先定 | 上传旧定稿是否保留、多个文件如何处理 | 建议保留旧结果并写入结果历史；替换限定单份，批量上传另走独立导入 |
| 必须先定 | 独立素材与生成节点的识别和转换 | 显式身份或明确操作语义，不仅凭有无图片判断 |
| 必须先定 | 下游无可用输入及上游生成中如何处理 | 有旧定稿可用，无可用定稿阻止执行 |
| 必须先定 | 历史保存协议及资产编号是否支持 | 先核实接口，不用仅存当前图替代完整需求 |
| 需定范围 | 只有上游文本是否允许提示词为空 | 按明确任务规则与模型能力校验，不统一强制非空 |
| 需定范围 | 输入更新提示传播范围 | 先做直接依赖版本比较；不把祖先变化等同于直接输入已变 |
| 需定范围 | 分享公开候选还是只公开定稿 | 默认只公开定稿，候选公开另定范围 |
| 需定范围 | 节点复制是否携带全部候选及结果历史、历史容量上限 | 明确复制和保留策略，不静默清理 |
| 需定范围 | 裁剪／扩图等编辑结果是否进入本节点 | 保留现有行为，若统一需另列设计和验收 |

## 12. 建议实施顺序

1. 产品确认第 11 节的关键行为，设计补齐第 6 节；核实候选保存及资产接口。
2. 确定结果、批次、定稿及执行快照的数据职责，先打通保存恢复和旧数据兼容。
3. 统一直接输入解析和模型校验，拆开配置草稿与实际执行快照。
4. 调整图片单张／批量任务，再接入多结果节点展示及定稿选择。
5. 调整文本、视频原位任务与结果选择，接入上传结果替换。
6. 补齐复制、历史、文件、分组及分享兼容，执行第 10 节验收。

不得先发布“前端显示已有多图，但刷新只剩定稿”的半成品，也不得在缺设计时自行完成候选交互定案。
