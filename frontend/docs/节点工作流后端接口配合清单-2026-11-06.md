# 节点工作流后端接口配合清单

日期：2026-11-06

状态说明：下文区分“需要补齐”与“现有能力待确认”。没有真实联调证据的项目不等于后端一定缺失；建议接口名称和字段不是已发布协议，不要求后端重复建设已有能力。

用途：供后端评估并补齐画布节点“同节点多批次结果、历史记录、当前定稿、任务保护和上游版本标识”所需的接口能力。

## 一、前端已实现的交互

当前节点已经具备以下前端逻辑：

- 节点结果入口打开临时浮层。
- 浮层同时查看当前批次和历史批次，按最新批次到早期批次展示。
- 图片同一批次可查看多个候选，但只能显式选择其中一个作为当前定稿。
- 候选图没有独立端口，不能单独取出成为新节点。
- 新批次成功后覆盖节点当前显示内容，旧批次进入历史。
- 文本、视频、单张图片同样采用新结果覆盖旧结果。
- 2026-11-06 最新补充：音频也采用原节点覆盖、旧结果保留历史，支持试听和恢复。文本节点隐藏历史与替换入口，不删除内部已有结果数据。图片、视频、音频支持同类型单素材替换。
- 音频生成响应（含异步任务终态）须提供真实永久资产编号 `asset_id`，前端不得以生成记录编号或媒体 URL 伪造。若缺少永久编号，前端保留原结果并提示失败；需后端联调验证。音频历史素材也需被画布保存与授权解析接口支持。
- 全部失败保留旧定稿；部分成功保留有效图片候选。
- 当前节点不作为自身下一次生成的参考输入。
- 生成、上传替换、图片编辑、视频编辑均写回原节点并形成结果批次。

以上内容目前是前端行为，仍需后端接口保存、读取、授权和并发校验配合，不能只依赖浏览器内存。

## 二、必须补齐或确认的接口能力

### 1. 画布文档保存与读取

请确认现有画布文档接口是否能够完整保存并原样返回以下节点字段：

- `nodeResults.version`
- `nodeResults.batches`
- 每个批次的稳定编号（前端批次对象使用 `id`）、提交时间、完成时间、来源、请求数量、任务 ID 集合
- 每个结果的稳定编号（前端结果对象使用 `id`）、稳定索引、结果类型、永久 `assetId`，文本结果的正文 `content`
- `nodeResults.currentResultId`
- 当前选择记录及选择时间
- 生成时的输入快照，包括提示词、模型、参数和输入素材稳定身份
- 上游依赖版本或输入版本

要求：

- 不能因为字段未进入后端白名单而静默丢弃历史。
- 字段超限时必须明确返回失败原因，不能裁掉旧批次后返回成功。
- 保存成功响应必须能证明新增历史已经持久化。
- 需要支持旧节点数据读取；旧节点只能迁移为一个已有结果，不得凭空生成历史批次。

建议确认：文档字段白名单、单节点历史数量上限、单画布总历史数量上限、单次请求体大小上限、schema 版本和迁移策略。

产品要求保留全部历史，不自动清理。若文档存在容量上限，应采用独立历史存储及分页等方式承载，不能将“限制数量并删除旧结果”作为默认实现。

### 2. 历史结果分页与查询

当前前端浮层已预留分页能力，但尚未接入真实分页服务，需要后端确认是否提供独立历史查询接口。

至少需要明确：

- 是否随画布文档一次返回全部历史，还是按节点分页。
- 推荐接口形式：按 `canvasId`、`nodeId` 查询批次。
- 排序必须稳定，默认按批次完成时间或提交序号倒序。
- 返回 `items`、`total`、`nextCursor` 或等价分页字段。
- 分页期间新批次产生时，旧游标是否仍然有效。
- 当前定稿是否单独返回，还是由批次结果中的 `currentResultId` 判断。
- 结果被删除、失效或无权限时的状态格式。

历史查看接口不能只返回临时 URL，必须返回永久资产身份及其可解析状态。

### 3. 资产解析与授权

当前结果、候选结果和历史结果都可能需要展示，因此资产解析接口必须支持非当前结果。

每个资产至少需要返回：

- 永久 `assetId`。
- 媒体类型。
- `availability`，建议至少支持 `ready`、`missing`、`forbidden`、`trashed`。
- 可用的原图、下载、预览、缩略图或视频封面地址。
- 宽、高、时长等媒体信息。

要求：

- 不能用任务 ID、节点 ID、临时 URL代替永久资产 ID。
- 历史资产无权限或已不存在时，要返回明确状态，不能返回空成功。
- 资产解析应支持批量查询，前端当前按每批最多 200 个资产请求。
- 地址需要有明确有效期和刷新策略。

### 4. 生成任务受理与任务 ID

前端当前需要区分“请求已发出”和“服务端已正式受理”。

请确认：

- 图片、视频、文本生成分别在什么时机返回真实任务 ID。
- 一次请求生成多个图片候选时，是一个任务 ID 还是多个任务 ID。
- 是否有统一的 `submissionId` 或 `runId` 关联一次节点生成。
- 任务 ID 返回不完整时，前端应如何判断受理失败。
- 文本接口目前没有明确的真实任务 ID，需要确认是否补充。

前端不能使用本地请求 ID 解除节点锁定，也不能使用画布运行 ID冒充生成任务 ID。

### 5. 任务取消接口

产品规则要求：删除正在生成的节点时发送取消指令；取消失败不提示用户；没有任务 ID 时，任务 ID 后续返回仍需补取消。

请提供或确认统一取消接口：

- 按真实生成任务 ID 取消。
- 支持一个节点对应多个任务 ID。
- 支持已创建任务和请求已提交但尚未分配任务 ID的取消或幂等终止。
- 重复取消必须幂等。
- 返回任务最终状态或明确的已接受取消状态。
- 取消接口鉴权范围与任务所属项目、画布、节点校验。

当前文档中存在旧版生成任务取消接口和画布 Run 取消接口，但尚未确认它们适用于当前画布生成任务，不能直接替代。

### 6. 上游输入版本与更新标识

产品要求：上游节点当前内容变化后，直接下游需要明确显示“上游内容已更新”；下游成功使用最新输入后清除标识。

建议后端为每个节点结果提供稳定版本字段，例如：

- `outputVersion` 或单调递增的 `contentVersion`。
- 版本必须随当前定稿变化而变化，包括新批次覆盖、手动切换候选、上传替换和编辑结果；只有浏览历史、刷新媒体地址时不改变版本。
- 下游执行快照保存 `inputNodeId`、`inputOutputVersion`、`inputResultId`、`inputAssetId`。
- 返回当前上游版本与下游最近一次成功执行版本的比较结果，或允许前端可靠比较。
- 历史恢复、刷新和跨设备打开后，标识不能被前端重新计算错误清除。

清除条件必须比较下游本次成功执行使用的输入版本与上游当前版本。如果下游取得任务 ID后上游再次更新，即使下游随后成功，也不能清除这次新更新的标识。失败不能清除；不自动触发下游重跑，不向非直接下游递归传播。

仅比较 URL、文件名或前端时间戳不可靠。

### 7. 分享与公开读取

分享页只允许展示当前定稿，不允许公开：

- 候选结果。
- 历史批次。
- 未公开或无权限资产。
- 开发草稿、任务 ID、内部运行状态和运行态资产映射。

必须由服务端接口过滤，而不是只依赖前端隐藏。请确认分享读取接口的返回结构、资产授权校验和缓存失效策略。

### 8. 并发、版本冲突与保存顺序

需要支持以下保护：

- 同一节点并发写入时，后写请求不能静默覆盖较新的结果历史。
- 保存请求应携带文档版本、节点版本或等价的 `If-Match` 条件。
- 版本冲突要返回明确错误，前端再进行合并或提示。
- 异步生成结果回写时，服务端应校验节点仍存在、请求仍有效、任务属于当前节点。
- 删除节点后，迟到结果不能重新创建节点或恢复旧结果。
- 撤销不能删除已经异步追加且仍有效的历史批次；服务端不能把前端旧快照提交等同于显式删除历史。

## 三、建议后端提供的接口清单

具体 URL 可按现有服务规范调整，以下是能力清单：

| 能力 | 建议接口 | 关键请求 | 关键响应 |
|---|---|---|---|
| 保存画布节点结果 | 现有画布保存接口扩展 | 文档版本、节点结果、当前选择 | 新文档版本、持久化确认 |
| 读取画布节点结果 | 现有画布读取接口扩展 | `canvasId` | 完整历史、当前定稿、依赖版本 |
| 查询节点历史 | 节点历史分页接口 | `canvasId`、`nodeId`、游标 | 批次列表、总数、下一游标 |
| 批量解析资产 | 现有资产解析接口扩展 | `assetIds[]` | 资产状态、永久身份、媒体地址 |
| 取消生成任务 | 统一任务取消接口 | `taskIds[]`、节点和画布身份 | 接受取消、最终状态或幂等结果 |
| 查询任务受理状态 | 任务状态接口 | `submissionId` 或 `taskIds[]` | 受理状态、任务 ID、结果资产 |
| 分享读取 | 分享接口扩展 | 分享身份 | 仅当前定稿及公开资产 |
| 版本冲突检查 | 保存接口内置或独立接口 | 文档/节点版本 | 新版本或冲突信息 |

## 四、后端联调验收样例

请至少使用以下数据验证一次完整往返：

1. 一个图片节点生成两批结果：第一批 3 张，第二批 2 张。
2. 第二批默认第一张为当前定稿，手动切换为第二张。
3. 保存、刷新、重新读取，确认两批历史、当前选择和资产预览均一致。
4. 再次生成成功后，确认第三批覆盖当前投影，但前两批仍可查询。
5. 模拟部分成功和全部失败，确认历史及当前定稿不被错误清空。
6. 删除生成中的节点，确认任务取消；随后模拟迟到结果，确认不会复活节点。
7. 修改上游当前结果，确认直接下游出现更新标识；下游使用最新结果成功后标识清除。
8. 打开分享链接，确认只能看到当前定稿，不能通过接口或资产地址访问候选和历史。
