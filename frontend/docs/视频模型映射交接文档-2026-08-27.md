# 视频模型映射交接文档（generation_reference_mode_map）

> 版本：2026-08-27（与 152 测试环境已部署代码一致）
> 适用：后端模型能力维护、前端创作模块（miioo-feat-frontend_V1.1）联调
> 数据源：`backend/app/services/model_capabilities.py` `VIDEO_MODEL_CAPABILITIES`（.venv 实测提取，57 个声明 → 合并别名后 50 个展示项）

## 1. 交接导览

1. **核心字段**：每个视频模型的 `capabilities` 内含 `supported_generation_modes`（能怎么生成）、`reference_modes`（素材怎么喂）、`generation_reference_mode_map`（生成模式→参考模式 一对一绑定）。
2. **前端消费**：`GET /api/models` → `capabilities.generation_reference_mode_map` → 按素材推导 `generation_mode` → 取 `map[generation_mode]` 作为 `reference_mode` → 随请求发送（值允许 `string | null`）。
3. **铁律**：纯文本 `text_to_video → null`（不能归一化成 `full`）；`start_end → start_end`（不能强映射 `first_frame`/`last_frame`）；一个生成模式只对应一个参考模式；多个生成模式可共用同一参考模式。
4. **能力下线**：2026-08-27 起 Vidu 多帧/参考生视频下线（`supported_generation_modes=[]`、map 为空）；Kling `multi_shot` 下线（无模型声明）。残留请求由校验层 400 拒绝。

## 2. 生成模式语义基准（协议 3.2）

| generation_mode | reference_mode | 含义 |
|---|---|---|
| `text_to_video` | `null` | 纯文本输入，无素材绑定 |
| `first_frame` | `first_frame` | 1 张图作首帧 |
| `last_frame` | `last_frame` | 1 张图作尾帧 |
| `start_end` | `start_end` | 2 张图作首帧+尾帧 |
| `reference_subjects` | `multi_image` | N 张图主体/风格参考（不含视频、音频） |
| `video_ref` | `video_ref` | 1 段视频参考 |
| `video_edit` | `video_ref` | 1 段待编辑视频（+可选图/音频） |
| `full` | `full` | 图+视频+音频混合池（仅 Seedance 系列真实支持） |
| `multi_shot` / `multiframe` | — | 已下线，无模型声明 |

## 5. 2026-08-26/27 变更交接要点

| 变更 | 说明 |
|---|---|
| 语义修正 `reference_subjects` | 由 `null`/`full` 统一改为 `multi_image`（纯 N 图主体参考）；`multi_shot` 由 `first_frame` 改为 `null`（settings 开关，不参与路由） |
| `start_end` 语义 | 保持 `start_end → start_end`，适配层负责厂商字段转换，不改公共协议 |
| 新增 OneLinkAI 真实 ID | `kling-v2.5-turbo`（点号）、`kling-video-o1`、Kling 专项 5 个（motion/lipsync/avatar/extend/multi-elements）、Vidu 真实 ID 系列（viduq3-pro/turbo/pro-fast、viduq1-classic、vidu-q2-pro/fast、video-viduq3-pro） |
| Kling V3 Omni | 新增 `video_ref`（视频参考）：`max_reference_videos=1`、`supports_reference_video=True`、map 增 `video_ref→video_ref` |
| Kling V3 主入口 | `max_reference_images` 2→4（multi-image2video 端点恢复直连） |
| 能力下线 | Vidu：`viduq2-pro`/`viduq2-turbo`（多帧）、`viduq3`/`viduq3-mix`（参考生视频）→ `modes=[]`；Kling：`multi_shot` 全部移除 |
| 空能力语义 | `_build_video_capability` 显式传 `[]` = 无能力，不再被 `or ["full"]` 改写（2026-08-27 修复） |
| `null` 处理 | 生成接口 `reference_mode` 显式 `null` 原样保留，不归一化 `full`；未传时仅旧调用方走推断 |

## 7. 联调验收清单

1. `GET /api/models` 返回每个视频模型 `generation_reference_mode_map`，键覆盖 `supported_generation_modes`。
2. 前端按映射发请求：纯文本带 `reference_mode: null`；首帧/首尾帧/多图参考/视频编辑各带对应值。
3. 生成接口接受每个合法组合并真正进入厂商任务（不只是过参数校验）。
4. `reference_mode` 与映射不一致时返回明确 400（如 `REFERENCE_MODE_MISMATCH`）。
5. 已下线模型（Vidu 多帧/参考生视频）前端不展示或置灰，残留请求 400。
6. 完成全部验收后，删除前端残留的本地兜底映射。
