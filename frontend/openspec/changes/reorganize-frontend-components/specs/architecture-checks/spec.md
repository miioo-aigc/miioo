## ADDED Requirements

### Requirement: 项目必须提供架构检查命令
项目 SHALL 提供可本地执行的架构检查命令，用于检查页面规模、目录命名和基础依赖边界，并输出可定位的文件路径和原因。

#### Scenario: 执行架构检查
- **WHEN** 开发者运行 `npm run check:architecture`
- **THEN** 工具检查项目约定并以非零退出码报告阻断级违规

### Requirement: 页面规模检查必须分级
页面规模检查 MUST 区分告警和阻断，当前历史页面超出建议规模时输出告警，不阻断开发；未来若引入新页面硬阈值，必须先定义显式豁免格式和原因记录。不得通过删除有效代码或压缩可读性来规避检查。

#### Scenario: 复杂旧页面仍未迁移
- **WHEN** 旧页面超过建议行数但尚未进入迁移阶段
- **THEN** 检查输出告警和迁移提示，不阻断现有开发

#### Scenario: 当前新页面超过警告线
- **WHEN** 新增页面超过 300 行页面入口警告线，且项目尚未启用新页面硬阈值
- **THEN** 检查命令输出可定位的告警，开发者必须在迁移记录中说明原因和下一步，不以非零退出码阻断历史迁移

### Requirement: 架构检查必须接入项目脚本
架构检查 MUST 在 `package.json` 中有稳定的脚本入口，并可与 `npm run lint` 和 `npm run build` 独立执行。

#### Scenario: 新环境执行检查
- **WHEN** 开发者在已安装依赖的项目根目录执行检查
- **THEN** 不需要额外的全局工具或网络请求即可完成检查
