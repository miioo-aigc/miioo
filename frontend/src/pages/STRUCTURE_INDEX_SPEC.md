# 页面文件结构索引规范

> 文档类型：大型页面和组件的阅读索引规则
> 最后更新：2026-07-15

## 1. 目的

结构索引是大型文件的代码地图，用于让 AI 和开发者在修改前先知道状态、数据流、组件、函数和副作用在哪里。它不是变更日志，也不能替代代码本身。

## 2. 适用范围

| 文件行数 | 要求 |
|---:|---|
| 少于 300 行 | 通常不要求索引；已有索引时继续维护 |
| 300–800 行 | 建议维护索引 |
| 800–3000 行 | 必须维护索引 |
| 超过 3000 行 | 必须维护索引，并在迁移记录中写明拆分计划 |

组件文件同样适用，不只限于 `src/pages/`。

## 3. 索引格式

索引必须是文件第一个注释块，紧贴第一行，使用 JSDoc：

```jsx
/**
 * @file SubjectPage.jsx
 * @structure-index
 *
 * ─── 状态与数据流 ─────────────────────────────── L1–L80
 *   页面状态           当前标签、主体列表和编辑面板状态       L20
 *
 * ─── 页面入口 ─────────────────────────────────── L81–L200
 *   SubjectPage()      页面级状态和业务区块编排               L81
 *
 * ─── 更新记录 ───────────────────────────────────
 *   2026-07-15         抽离 SubjectToolbar，更新行号
 */
```

索引结束后直接接 `import`。不要在索引和 import 之间插入代码或另一个注释块。

## 4. 必须记录的内容

按文件实际内容选择分组，至少覆盖以下存在的项目：

- 全局常量和纯工具函数；
- API、Store 或外部数据入口；
- 局部 UI、业务区块和弹窗；
- 页面入口或默认导出组件；
- 状态、setter、关键函数、副作用、定时器、事件监听和清理逻辑；
- 新增、删除、移动的组件或 Hook。

页面入口的状态顺序固定为：状态 → 函数 → 副作用。函数说明应写清调用 API、更新状态、缓存或回调的主要作用。

## 5. 行号要求

- 行号必须是当前文件的真实行号，格式为 `L行号` 或 `L起始行–结束行`。
- 只标注定义起始行也可以；跨越超过 50 行的代码块建议标注结束行。
- 修改、移动、删除任意代码后，必须重新核对受影响条目，不得保留“约”“大概”等模糊位置。
- 如果一次变更使索引难以维护，应优先考虑拆分文件，而不是删除索引。

## 6. 读取规则

1. 打开大型页面或组件前，先读取顶部结构索引。
2. 根据索引定位需要的区块，再阅读实现和调用关系。
3. 如果文件没有索引，先按任务范围建立代码地图；只有用户明确要求时才新增正式索引。
4. 发现索引与代码不一致时，先修正索引再继续依赖它分析。

## 7. 修改规则

每次修改后必须：

1. 更新新增、删除或移动的条目；
2. 更新状态、函数、副作用的真实行号；
3. 在“更新记录”末尾追加当前日期和变更说明；
4. 检查索引是否仍是第一个注释块；
5. 对页面执行引用安全检查、构建和相关架构检查。

索引更新是页面或大型组件任务的完成条件。未同步索引时，不得在进度文档中标记该文件迁移完成。
