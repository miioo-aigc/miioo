# 后端配合需求：真人认证扫码回调重构

## 官方标准流程（来自 OneLinkAI 官方文档）

```
Step 1  前端创建真人认证 H5 链接
Step 2  用户完成认证 → ByteDance 服务器向「业务方 callback」POST bytedToken
Step 3  业务方后端 使用 bytedToken 调用 ByteDance API 换取 GroupId
Step 4  上传素材 URL 创建 Asset
Step 5  轮询素材状态，直到 Active 可用
```

**Step 2 和 Step 3 都在服务端完成，前端无法参与。**

---

## 当前问题

### 问题一：`/complete` 要求 Bearer 鉴权，但正确的触发方应该是 ByteDance 服务器

现有 `/api/live-materials/auth-sessions/{session_id}/complete` 接口：
- 要求 `Authorization: Bearer <access_token>`
- 本意是让前端（手机浏览器回跳后）调用

**但这不符合官方流程。** ByteDance 在 Step 2 是直接 POST 给业务方后端，不是给手机浏览器，也不带用户的 Bearer token。后端应该有一个**无用户鉴权**的 Webhook 接收接口供 ByteDance 调用，然后用收到的 `bytedToken` 去换 GroupId（Step 3），再入库。

### 问题二：`callback_url` 字段描述错误

`LiveMaterialAuthSessionCreateResponse.callback_url` 文档描述为"认证完成后的**前端**回跳地址"，这是误导性的。根据官方流程，它应该是提交给 ByteDance 的**后端 Webhook 地址**（ByteDance 服务器来 POST，不是手机浏览器跳转）。

### 问题三：前端没有办法独立完成 Step 3

Step 3 "使用 bytedToken 获取 GroupId"需要 ByteDance API 密钥，只能在后端调用，前端无法做到。

---

## 需要后端修改 / 新增的内容

### 1. 修改 `/complete` 接口：去掉 Bearer 鉴权，改为接受 ByteDance 回调

**当前**：`POST /api/live-materials/auth-sessions/{session_id}/complete`，需要 Bearer token，由前端调用。

**期望**：这个接口（或新增一个）作为 ByteDance Webhook 接收端，**不要求用户 Bearer token**，改用 `session_id` 关联用户，内部鉴权（例如签名校验或白名单 IP）。

接口收到 ByteDance 的回调后，后端自行完成：
1. 用 `bytedToken` 调用 ByteDance API 换取 GroupId（Step 3）
2. 将 group 持久化到数据库（关联到该 `session_id` 对应的用户）
3. 将 session 状态更新为 `completed`

### 2. 新增会话状态查询接口（必须）

PC 端需要轮询这个接口来感知"手机已完成认证"：

```
GET /api/live-materials/auth-sessions/{session_id}/status
Authorization: Bearer <access_token>（PC 端调用，有 token）
```

**Response：**
```json
{
  "status": "pending" | "completed" | "failed",
  "group": { ...LiveMaterialGroupResponse } | null
}
```

- `pending`：用户还未完成扫码认证
- `completed`：认证通过，group 已入库，`group` 字段返回完整数据
- `failed`：认证失败或超时，`group` 为 null

PC 端每 3 秒轮询此接口，替代现有的轮询 `/groups` 列表（不可靠）。

### 3. `return_path` 字段可废弃

后端不再需要把手机浏览器重定向到前端。手机上只需 ByteDance 的页面显示"验证成功"后关闭即可。前端创建会话时不再传 `return_path`。

---

## 正确的完整流程（修改后）

```
PC 端：
  1. 调 POST /auth-sessions → 拿到 session_id 和 launch_url（二维码内容）
  2. 展示二维码
  3. 开始每 3s 轮询 GET /auth-sessions/{session_id}/status

手机端：
  4. 扫码 → 打开 launch_url → ByteDance H5 → 完成人脸识别

ByteDance 服务器：
  5. POST bytedToken 到我们后端的 Webhook（callback_url）

我们的后端：
  6. 收到 bytedToken → 换取 GroupId → 入库 → session 状态改为 completed

PC 端：
  7. 轮询拿到 status=completed + group 数据 → 弹窗跳转到命名步骤

手机端：
  8. ByteDance 页面显示"验证成功"，用户关闭即可，无需做任何跳转
```

---

## 前端配合改动（后端完成后同步修改）

1. `handleAddNew`：
   - 创建会话时不传 `return_path`
   - 轮询改为 `GET /auth-sessions/{session_id}/status`，检测 `status === 'completed'`，取 `group` 数据

2. `App.jsx`：整段 `live_material_callback` useEffect 删除

3. `CreationPage.jsx`：移除 `_t` token 注入逻辑（当前的安全兜底方案）

4. `liveMaterials.js`：`apiCompleteLiveMaterialAuthSession` 可删除（前端不再调用）

---

## 当前临时状态（后端修复前）

前端目前的兜底方案：在 `return_path` URL 里附带 `_t=<access_token>`，手机跳回后带着 token 调 `/complete`。这方案有安全风险（token 暴露在 URL 里），**后端完成 Webhook 改造后必须移除**。
