# 视频模型接入优化方案 - 实施计划文件

> 文档状态：已实施，待产品联调验收
> 适用范围：创作页面 - 视频创作  
> 最后更新：2026-08-20  
> 数据依据：`/Users/suzylee/Desktop/后端提供的视频模型数据.json`

## 1. 背景与目标

创作页需要根据后端返回的视频模型及其能力，向用户提供统一、可理解的创作方式，并将用户选择的参考模式和实际上传素材转换为厂商模型真实支持的 `generation_mode`。

当前实现同时使用 `reference_modes`、`supported_generation_modes`、素材类型和模型 ID 特判判断生成方式，存在以下问题：

1. `reference_modes` 的历史数据不统一，不能可靠代表厂商真实能力。
2. 普通模型有参考素材时可能被统一设置为 `full`，未严格校验模型是否支持。
3. Kling V3 Omni 在请求组装阶段存在模型 ID 特判，能力判断没有形成统一规则。
4. 前端目前只有“全能参考”和“首尾帧”，无法明确表达 `multi_shot` 的用户意图。
5. 音频上传入口主要依赖通用能力字段，缺少 Seedance 系列专属门禁和提交校验。

本次优化目标：

- 以 `supported_generation_modes` 作为视频模型真实生成能力的唯一判断依据。
- 建立“全能参考、智能多帧、首尾帧”三种稳定的前端参考模式。
- 根据当前模型、前端参考模式和实际素材，确定唯一、合法的 `generation_mode`。
- 在模型切换、素材上传和提交三个阶段阻止无效组合。
- 将通用能力路由与厂商请求参数适配分离，逐步移除散落的模型 ID 特判。

## 2. 已确认的产品原则

### 2.1 能力数据真源

1. `supported_generation_modes` 是厂商真实生成能力的唯一判断依据。
2. `reference_modes` 只作为后端历史展示字段保留，不参与新增参考模式的能力判定，也不能补充或覆盖 `supported_generation_modes`。
3. 如果 `reference_modes` 声明了某项能力，但 `supported_generation_modes` 未声明，前端按“不支持”处理。
4. 示例：Seedance 的 `reference_modes` 中虽然存在 `last_frame`，但 `supported_generation_modes` 不包含 `last_frame`，因此 Seedance 不允许仅上传尾帧生成。

### 2.2 模型与参考模式的关系

1. 模型是一级选择，参考模式是当前模型能力下的二级选择。
2. 模型下拉菜单始终展示全部可用视频模型，不因当前参考模式过滤模型。
3. 参考模式下拉菜单只展示当前模型真实支持的模式。
4. 用户切换模型后，如果新模型不支持当前参考模式，前端自动切换到新模型实际支持的模式。
5. 自动回退优先级为：
   - 当前模式仍受支持：保持当前模式。
   - 当前模式不受支持，但支持全能参考：切换到全能参考。
   - 不支持全能参考，但支持首尾帧：切换到首尾帧。
   - 仅支持智能多帧：切换到智能多帧。
6. 模式自动切换后显示轻量提示，明确说明切换原因和目标模式。

### 2.3 三种前端参考模式

| 前端模式 | 前端枚举建议 | 产品语义 | 主要生成能力 |
|---|---|---|---|
| 全能参考 | `all` | 文字、主体图片、参考视频、音频或综合素材创作 | `full`、`text_to_video`、`reference_subjects`、`video_ref`、`video_edit` |
| 智能多帧 | `multi_shot` | 用户主动选择多镜头/多帧生成意图 | 固定为 `multi_shot` |
| 首尾帧 | `frame` | 用户明确指定首帧、尾帧或首尾帧 | `first_frame`、`last_frame`、`start_end` |

### 2.4 智能多帧规则

1. 只有当前模型的 `supported_generation_modes` 包含 `multi_shot` 时，参考模式下拉菜单才显示“智能多帧”。
2. “智能多帧”由用户手动选择，不由前端根据图片数量自动触发。
3. 用户选择“智能多帧”后，`generation_mode` 固定为 `multi_shot`。
4. 一张图片或多张图片都允许使用智能多帧，不设置“至少两张图片”的全局限制。
5. 不得将智能多帧静默降级为 `reference_subjects`、`first_frame` 或其他能力。
6. 厂商对素材数量、格式的额外限制以后续结构化能力字段或明确接口契约为准。

### 2.5 首尾帧规则

首尾帧模式只判断两个独立槽位，不参与全能参考的素材推断：

| 首帧状态 | 尾帧状态 | 候选 `generation_mode` |
|---:|---:|---|
| `1` | `0` | `first_frame` |
| `0` | `1` | `last_frame` |
| `1` | `1` | `start_end` |
| `0` | `0` | 不允许提交 |

候选能力生成后，必须再次检查其是否存在于当前模型的 `supported_generation_modes`：

- 支持候选能力：允许提交。
- 不支持候选能力：阻止提交并提示用户调整素材或更换模型。
- 不允许静默丢弃尾帧，也不允许把 `start_end` 自动降级为 `first_frame`。
- Seedance 支持 `first_frame` 和 `start_end`，不支持 `last_frame`；因此 `[0, 1]` 必须阻止提交。

### 2.6 Seedance 系列规则

1. Seedance 系列模型选择“全能参考”时，默认并固定使用 `generation_mode = full`。
2. Seedance 全能参考不再根据实际素材细分为 `text_to_video` 或 `video_ref`。
3. Seedance 的首尾帧模式仍按 `[首帧, 尾帧]` 数组判断，并严格校验 `supported_generation_modes`。
4. Seedance 系列是当前唯一允许上传音频参考素材的视频模型系列。
5. Seedance 系列识别优先使用后端结构化能力；在后端尚无稳定系列字段时，可将标准化后的 `model_id` 前缀作为集中式兼容规则，但不得把判断散落在 UI 和 API 文件中。

### 2.7 音频素材规则

1. 只有 Seedance 系列允许在视频创作中上传或选择音频素材。
2. 其他视频模型在本地上传入口和资产选择器中均不得提供音频选项。
3. 用户从 Seedance 切换到非 Seedance 模型时，不删除已选择的音频草稿，但当前模型提交时不得发送该音频。
4. 如果当前模式或当前模型存在不兼容音频，提交前必须阻止请求并提示移除音频或切换到 Seedance。
5. API 请求组装层再次执行音频门禁，避免旧草稿、历史回填或异常状态绕过 UI 限制。

## 3. 模式可见性判定

### 3.1 全能参考

满足以下任一条件时显示“全能参考”：

```text
supported_generation_modes 包含以下至少一项：
full
text_to_video
reference_subjects
video_ref
video_edit
```

注意：显示“全能参考”只代表当前模型至少支持一种全能参考流程，不代表它支持全能参考中的任意素材组合。实际提交仍需执行素材能力路由。

### 3.2 智能多帧

```text
supported_generation_modes 包含 multi_shot
```

### 3.3 首尾帧

```text
supported_generation_modes 包含以下至少一项：
first_frame
last_frame
start_end
```

## 4. 全能参考能力路由

### 4.1 标准化输入特征

全能参考不直接使用简单的四位布尔数组作为最终能力判断，而是先形成可扩展的输入特征。四位数组可作为调试和测试摘要：

```text
[文字, 图片, 视频, 音频]
```

实际路由建议使用：

```js
{
  hasPrompt: true,
  imageCount: 2,
  videoCount: 0,
  audioCount: 0,
  liveMaterialCount: 0,
}
```

首帧和尾帧不计入全能参考的普通图片数量，也不进入全能参考路由。

### 4.2 已确认的通用路由

能力路由必须先处理模型系列规则，再处理通用规则，并最终与 `supported_generation_modes` 求交：

| 模型/输入条件 | 目标能力 | 说明 |
|---|---|---|
| Seedance 系列 + 全能参考 | `full` | 不再细分纯文字、视频或音频输入 |
| 非 Seedance + 仅文字 | `text_to_video` | 当前模型必须明确支持 |
| 非 Seedance + 一张或多张图片 | `reference_subjects` | 全能参考中的图片表达主体/参考意图，不使用 `multi_shot` |
| 非 Seedance + 视频，支持 `video_edit` | `video_edit` | 当前数据中没有模型同时支持 `video_edit` 和 `video_ref` |
| 非 Seedance + 视频，支持 `video_ref` | `video_ref` | 当前模型必须明确支持 |
| 非 Seedance + 综合素材，且支持 `full` | `full` | 仅在模型明确声明 `full` 时使用 |

### 4.3 无法路由的处理

以下场景不得猜测或静默降级：

1. 输入素材对应的候选能力不在当前模型的 `supported_generation_modes` 中。
2. 非 Seedance 模型包含音频素材。
3. 仅有图片，但当前模型既不支持 `reference_subjects`，也不属于固定走 `full` 的 Seedance 系列。
4. 仅有视频，但当前模型不支持 `video_edit`、`video_ref` 或经过明确确认的 `full`。
5. 混合素材无法映射到当前模型声明的真实能力。

处理方式：前端阻止提交，说明当前模型不支持这组素材，并建议用户调整素材、参考模式或模型。

## 5. 请求参数原则

### 5.1 `generation_mode`

1. 必须由统一能力路由器返回。
2. 返回值必须存在于当前模型的 `supported_generation_modes`。
3. 禁止在 API 请求组装阶段根据模型 ID重新猜测能力。

### 5.2 `reference_mode`

1. 不再作为真实生成能力的判断来源。
2. 仅在后端接口契约明确要求时发送兼容值。
3. 前端模式 `all`、`multi_shot`、`frame` 不直接等同于后端历史 `reference_modes`。
4. 对 Kling V3 Omni 等特殊后端契约，保留必要的参数适配，但适配层不得改变已经确定的 `generation_mode`。

### 5.3 素材字段

1. 普通图片、视频和音频继续通过统一 `attachments` 传递，并保留现有独立 URL/asset ID 兼容字段。
2. 首尾帧使用独立的首帧、尾帧 URL 和 asset ID 字段，不混入普通参考图语义。
3. `multi_shot` 所需的额外布尔标记或厂商参数由请求适配层补充。
4. 厂商适配只负责参数形态，不负责重新决定用户意图和生成能力。

## 6. 状态与交互设计

### 6.1 模型切换

模型变化后执行：

```text
读取 supported_generation_modes
→ 计算新模型可用参考模式
→ 校验当前参考模式
→ 保持或按既定优先级回退
→ 校验当前模式素材
→ 必要时提示用户
```

### 6.2 模式素材草稿

1. 三种参考模式分别保存自己的素材草稿。
2. 模式切换时不把普通参考图片自动解释为首帧或尾帧。
3. 模型切换导致模式自动回退时，不删除原模式草稿。
4. 提交时只读取和发送当前参考模式对应的素材。
5. 切回原模式时恢复该模式此前的素材状态。

### 6.3 上传入口

1. 全能参考：根据当前模型开放图片、视频、音频类型。
2. 智能多帧：开放其请求契约允许的图片输入，不根据图片数量切换能力。
3. 首尾帧：只展示首帧、尾帧两个独立图片槽位。
4. 非 Seedance：上传选择和资产选择器均排除音频。
5. Seedance：全能参考允许音频；其他模式是否展示音频入口由当前模式素材契约决定，不因模型支持音频就无条件在所有模式开放。

## 7. 技术实施步骤

### 阶段一：现状盘点与边界冻结

1. 梳理创作页视频模型加载、参数适配、模式状态、文件上传、历史回填和提交链路。
2. 全局盘点 `reference_modes`、`supported_generation_modes`、`generation_mode`、`reference_mode` 的读取与写入位置。
3. 明确本期只修改创作页视频创作，不同步改造分镜页、主体页等其他入口。
4. 对照 18 个后端模型生成能力矩阵，形成实施测试夹具。

### 阶段二：建立视频能力领域工具

建议在 `src/utils/` 或创作业务域内新增纯函数模块，职责包括：

1. 标准化 `supported_generation_modes`。
2. 判断 Seedance 系列。
3. 根据模型能力生成可用前端参考模式。
4. 根据新模型能力计算模式回退结果。
5. 提取当前模式的标准化素材特征。
6. 根据参考模式、素材特征和模型能力解析 `generation_mode`。
7. 返回结构化成功结果或可展示的失败原因。

该模块不得依赖 React 组件、页面状态或 API 请求实现，以便进行表驱动测试和跨入口复用。

### 阶段三：改造模型适配

1. 在模型选项和能力映射中保留完整 `supported_generation_modes`。
2. 用统一工具计算 `availableReferenceModes`。
3. 停止使用 `reference_modes` 生成“全能参考/首尾帧”选项。
4. 移除 `actualAllRefMode`、`actualFrameRefMode` 对新增逻辑的主导作用；如后端兼容仍需使用，限制在请求适配层。
5. 增加 Seedance 音频支持标记，优先读取可靠结构化能力，并保留集中式系列识别兜底。

### 阶段四：改造参考模式和模型切换交互

1. 新增“智能多帧”选项。
2. 根据当前模型能力动态显示三种参考模式。
3. 模型下拉始终保持完整模型列表。
4. 实现当前模式兼容性检查和自动回退优先级。
5. 自动切换时显示轻量提示。
6. 确保模式变化不会错误清空或转换素材。

### 阶段五：改造上传和资产选择门禁

1. 根据模型系列和当前模式计算允许上传的素材类型。
2. 只有 Seedance 全能参考允许音频上传和音频资产选择。
3. 非 Seedance 在文件选择、拖拽、资产选择和历史回填后提交四条路径上均禁止音频。
4. 对已有不兼容音频草稿进行保留但禁用提交，不静默删除。
5. 对文件类型、数量等后续厂商约束预留结构化校验接口。

### 阶段六：实现统一能力路由

1. 智能多帧固定返回 `multi_shot`。
2. 首尾帧按 `[首帧, 尾帧]` 返回 `first_frame`、`last_frame` 或 `start_end`。
3. Seedance 全能参考固定返回 `full`。
4. 非 Seedance 全能参考按文字、图片、视频、音频和综合素材进行能力匹配。
5. 所有结果与 `supported_generation_modes` 进行最终校验。
6. 无匹配时返回明确错误，不发送请求。

### 阶段七：重构视频请求组装

1. 页面或输入组件在提交前调用统一能力路由器。
2. 将确定后的 `generation_mode` 传给 API 层。
3. API 层只进行上传、字段组装和厂商参数适配。
4. 移除 Kling V3 Omni 通过模型 ID重新推断 `generation_mode` 的逻辑。
5. 保留 Kling Omni `reference_mode` 空值、`multi_shot` 标记等经后端契约确认仍必要的参数适配。
6. 增加 API 层最终能力校验和 Seedance 音频门禁，防止异常状态绕过前端。

### 阶段八：历史回填与草稿兼容

1. 将历史记录中的 `generation_mode` 和素材字段还原为对应前端模式。
2. `multi_shot` 历史记录回填到智能多帧。
3. `first_frame`、`last_frame`、`start_end` 回填到首尾帧及对应槽位。
4. 其他能力回填到全能参考。
5. 历史数据与当前模型能力冲突时保留素材，但在提交前提示并要求调整。
6. 旧草稿缺少能力字段时使用保守兼容策略，不通过 `reference_modes` 补造厂商能力。

### 阶段九：测试与验收

1. 为模式可见性、模式回退、素材特征和能力路由增加表驱动测试。
2. 覆盖后端当前 18 个视频模型及代表性素材组合。
3. 覆盖 UI 上传门禁、资产选择门禁、历史回填和 API 最终校验。
4. 验证现有图片、配音、音乐创作流程不受影响。
5. 执行项目规定的完整验收命令。

## 10. 风险与控制措施

| 风险 | 控制措施 |
|---|---|
| 后端 `supported_generation_modes` 数据错误 | 前端严格按数据工作；记录异常模型并推动后端修正，不用 `reference_modes` 静默补偿 |
| 同名能力的厂商请求字段不同 | 通用路由和厂商请求适配分层 |
| 模式切换导致素材角色误解 | 各模式独立草稿，不自动转换素材角色 |
| 旧历史数据缺少真实能力字段 | 保守回填，提交前按当前模型能力重新校验 |
| 音频从旧草稿绕过 UI | 上传、资产选择、提交、API 四层门禁 |
| Kling 特判迁移引发回归 | 先建立表驱动用例，再替换旧分支，保留必要参数适配 |
| 全能参考名称让用户误以为支持任意素材 | 在上传入口和提交校验中只开放当前模型真实支持的素材，并提供明确错误提示 |

## 12. 完成标准
