# 视频模型生成模式与参考模式协议缺失及能力补全清单

> 交接日期：2026-08-20  
> 涉及接口：视频模型能力接口、`POST /api/creation/videos/generate`  
> 交接对象：后端模型能力与视频生成接口维护同学  
> 当前状态：前端已增加临时硬编码映射，等待后端补齐正式能力协议后移除兜底

## 1. 交接结论

当前问题不是前端无法识别模型的 `generation_mode`，而是部分视频模型虽然已经通过 `supported_generation_modes` 声明了生成能力，但后端没有完整、准确地提供这些生成模式对应的 `reference_mode`。

因此，前端在确定真实生成模式后，仍无法稳定构造后端可以接受的请求。当前部分模型只能通过语义不准确的临时映射通过后端校验，例如：

- 纯文本生成被临时映射到 `first_frame` 或 `full`；
- `start_end` 被临时映射到 `first_frame` 或 `last_frame`；
- `reference_subjects` 被临时映射到 `first_frame`；
- 多个业务语义不同的生成模式被迫共用后端当前可接受的参考模式。

这些映射只能作为联调期兼容措施，不能作为最终协议。后端需要为每个模型返回完整、真实、可调用的“生成模式 → 参考模式”映射，并补充当前缺失的参考模式及校验能力。

## 2. 请求字段

`POST /api/creation/videos/generate` 中：

- `generation_mode` 来源于当前模型的 `supported_generation_modes`，必须存在且不可为空；
- `reference_mode` 来源于当前模型的正式映射，字段必须发送，值允许为 `string | null`；
- 一个 `generation_mode` 在同一模型下只对应一个 `reference_mode`；
- 多个 `generation_mode` 可以共同对应同一个 `reference_mode`，例如不同全能参考能力都可以映射到 `full`；

## 3. 当前协议缺口

### 3.1 缺少模型级合法映射

后端当前分别返回 `supported_generation_modes` 和 `reference_modes`，但两个独立列表无法说明每个生成模式应该搭配哪个参考模式。

前端需要后端为每个模型返回完整映射：

```json
{
  "generation_reference_mode_map": {
    "text_to_video": null,
    "first_frame": "first_frame",
    "last_frame": "last_frame",
    "start_end": "start_end",
    "reference_subjects": "full",
    "video_ref": "video_ref",
    "video_edit": "video_ref",
    "multi_shot": "full"
  }
}
```

以上只用于说明字段结构，不是所有模型共用的默认映射。每个模型的实际值必须由后端根据真实厂商能力和后端适配逻辑提供。

### 3.2 部分参考模式缺失

当前有些模型已经声明支持某个 `generation_mode`，但没有对应且可被生成接口接受的 `reference_mode`。这会形成“能力接口声明可用，生成接口无法调用”的断链。

已确认需要补全的基础语义：

| 生成模式 | 应表达的参考模式 | 说明 |
|---|---|---|
| `text_to_video` | `null` | 纯文本输入，没有素材绑定 |
| `first_frame` | `first_frame` | 一张图片作为首帧 |
| `last_frame` | `last_frame` | 一张图片作为尾帧 |
| `start_end` | `start_end` | 两张图片分别作为首帧和尾帧 |

其中 `start_end` 就是首尾帧参考，不能因为后端暂未提供该参考模式而强制映射为 `first_frame`、`last_frame` 或 `video_ref`。厂商内部字段不同，应由后端适配层转换，不应改变前后端公共协议的业务语义。

`reference_subjects`、`video_ref`、`video_edit`、`multi_shot` 和 `full` 的参考模式需要逐模型确认。若多个生成模式使用相同的全能素材绑定方式，可以共同映射到 `full`。

### 3.3 `null` 被错误处理为 `full`

纯文本请求没有参考素材，正式协议应发送：

```json
{
  "generation_mode": "text_to_video",
  "reference_mode": null
}
```

此前 Kling V3 请求未发送 `reference_mode` 时，后端返回“模型不支持 `full` 参考模式”，说明缺失值曾被默认处理成 `full`。

后端需要支持显式 `null`：

- 不得将 `null`、缺失值或空值自动归一化为 `full`；
- 当模型映射中 `text_to_video -> null` 时，应允许请求通过；
- `reference_mode=null` 时不执行字符串枚举校验，但仍需校验该生成模式的正式映射确实为 `null`。

### 3.4 能力声明与接口校验没有形成闭环

对于每个模型，以下三处必须使用同一份配置或同一数据源：

1. 能力接口返回的 `supported_generation_modes`；
2. 能力接口返回的 `generation_reference_mode_map` 和 `reference_modes`；
3. 视频生成接口对 `generation_mode`、`reference_mode` 及二者组合的校验。

任何已经出现在 `supported_generation_modes` 中的值，都必须存在于映射的键中，并且对应组合能够真正进入厂商调用链路。

## 5. 后端需要补全的能力

### 5.1 新增完整映射字段

在每个视频模型能力数据中新增：

```json
{
  "generation_reference_mode_map": {
    "生成模式": "参考模式或 null"
  }
}
```

约束：

- 键必须完整覆盖 `supported_generation_modes`；
- 值只能是 `string | null`，不能是数组；
- 非空值必须出现在该模型的 `reference_modes` 中；
- 每个生成模式只能有一个映射值；
- 多个生成模式允许映射到同一个参考模式；
- 映射必须与生成接口实际接受的组合完全一致。

### 5.2 补齐参考模式枚举和校验

- 支持 `reference_mode: null` 表达纯文本无素材绑定；
- 补充模型真实支持的 `first_frame`、`last_frame`、`start_end`；
- 逐模型确认全能参考相关生成模式应对应 `full`、`video_ref` 或其他真实参考模式；
- 不使用与业务语义不一致的字符串只为通过接口校验；
- 厂商字段转换放在后端适配层处理。

### 5.3 修正生成接口校验

生成接口需要按以下顺序校验：

1. `generation_mode` 是否存在于模型的 `supported_generation_modes`；
2. `generation_reference_mode_map` 是否包含该生成模式；
3. 请求中的 `reference_mode` 是否与映射值严格一致，包括 `null`；
4. 素材类型和数量是否符合该生成模式；
5. 映射后的参数是否能被对应厂商适配器处理。

### 5.4 增加能力配置完整性检查

后端新增或修改模型时，建议自动检查：

- 每个 `supported_generation_modes` 是否都有映射；
- 每个非空映射值是否存在于 `reference_modes`；
- 生成接口是否接受映射中的组合；
- 厂商适配层是否能够处理该组合；
- 纯文本模式是否正确保留 `reference_mode=null`；
- 首帧、尾帧和首尾帧语义是否与字段名称一致。

## 6. 已有联调证据

Kling V3 已验证以下现象：

| generation_mode | reference_mode | 结果 |
|---|---|---|
| `text_to_video` | 未发送，后端按 `full` 处理 | 400，不支持 `full` |
| `text_to_video` | `text_to_video` | 400，不支持该参考模式 |
| `reference_subjects` | `reference_subjects` | 400，不支持该参考模式 |
| `first_frame` | `first_frame` | 请求可以提交 |

这些结果说明：

- 后端会独立校验 `reference_mode`；
- `reference_mode` 不能直接复制 `generation_mode`；
- 缺少映射时，前端无法仅通过两个独立能力列表推导合法组合；
- 当前核心问题是参考模式及其模型级合法映射不完整。

## 7. 联合验收标准

后端补全能力后，前后端按每个模型的全部 `supported_generation_modes` 逐项验收：

1. 能力接口返回完整 `generation_reference_mode_map`；
2. 映射键完整覆盖 `supported_generation_modes`；
3. 前端按映射发送请求，不依赖本地硬编码；
4. 生成接口接受每一个合法组合；
5. 不合法组合返回明确的期望值；
6. 请求能够真正进入厂商任务并完成，而不只是通过参数校验；
7. 前端确认后，删除对应模型的本地兜底映射。

## 8. 本次需要后端确认的清单

- 是否同意新增并返回 `generation_reference_mode_map`；
- 是否同意 `reference_mode` 字段必传、值允许为 `null`；
- 是否能够保证 `null` 不再被转换成 `full`；
- 是否能够补齐 `start_end` 等当前缺失的参考模式；
- 是否能够逐模型确认当前临时兜底表中的正式映射；
- 是否能够保证能力接口、生成接口校验和厂商适配器使用同一份映射配置；
- 后端完成补全后，提供一份可用于前后端联合验收的模型映射数据。
