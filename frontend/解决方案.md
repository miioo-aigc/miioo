## Bug 1：资产选择器展示未完成的占位卡，选中后系统崩溃

### 问题现象
在图片创作模式下发送生成请求后，立即切换到视频创作并打开「从资产库添加参考图」弹窗，会看到刚才图片请求的占位卡（图片尚未生成落地）。点击该占位卡后系统崩溃。

### 根本原因
`AssetPickerModal` 的数据来源有两条路径：

1. **Store 路径**：通过 `creationStore` 的 `generationsByTab` + `generationsToFlatList` 转换。`generationsToFlatList` 把 `card.imageUrl || card.poster || null` 映射为 `url`，处于 `status: 'loading'` 的卡片 `imageUrl` 为 `null`，产生 `url: null` 的占位条目。
2. **API 路径**：通过 `normalizeCreativeItem` 处理接口返回数据，同样可能产生 `url: null` 的条目。

两条路径都没有在进入渲染列表前过滤掉 URL 为空的条目，导致占位卡出现在选择器中。选中后下游代码对 `null` URL 的处理缺失，引发崩溃。

### 正确行为
资产选择器只展示已真正落地（有有效 URL）的资产。生成中的占位卡不出现在选择器列表里。

### 修改位置
`src/components/AssetPickerModal.jsx`

**Store 路径**（`creativeAssets` useMemo）：
```js
// 图片
.filter(item => !!item.url)

// 视频
.filter(item => !!(item.url || item.posterUrl))
```

**API 路径**（`normalizeCreativeItem` 之后）：
```js
.filter(item => type === 'audio' || !!(item.url || item.posterUrl))
```
音频类型不要求预览图 URL，故跳过过滤。

### 边界条件
- 音频资产没有预览图，不能用 URL 是否存在来过滤，保持原逻辑。
- 视频资产可能只有 `posterUrl`（缩略图），没有视频本体 URL，只要两者有其一即视为已落地。
- Store 路径和 API 路径都需要过滤，两条路径在不同场景下分别生效。

### 回归测试
1. 发送图片创作请求 → 立即打开资产选择器 → 确认选择器中不出现占位卡。
2. 等待图片生成完成 → 打开资产选择器 → 确认图片正常出现、可选中。
3. 音频资产可以在资产选择器中正常显示和选择。

### 验证结果
`npm run build` 通过，无新增错误。

## Bug 2：点击发送后提示词和参考素材被清空；切换页面/Tab 后内容丢失

### 问题现象
- 在创作页面输入提示词并上传参考图后，点击发送按钮，提示词文本和参考素材立即被清空。
- 在图片/视频/配音 Tab 之间切换，已上传的参考素材被清空。
- 切换到资产库、项目等其他页面再切回创作页，所有输入内容全部丢失。

### 根本原因
三个独立原因分别导致三种丢失场景：

1. **发送后清空**：`handleSend()` 内在请求发出后立即执行了一整块清空逻辑（清 innerHTML、`setFiles([])`、重置首尾帧、配音参数等 9 个 state）。
2. **切换 Tab 清空**：`useEffect(() => { setFiles([]); setFirstFrameFile(null); setLastFrameFile(null); }, [genType])` 在每次切换 Tab 时强制清空所有附件。
3. **切换页面清空**：`Home.jsx` 用条件渲染 `{activeKey === 'create' && <CreationPage />}`，离开创作页时组件被卸载，所有 React state 随之销毁。

### 正确行为
- 发送成功后内容保留在输入框，便于用户连续创作或微调再发。
- 图片/视频/配音 Tab 切换时，已上传的参考素材尽量保留（各 Tab 共享同一份 `files` state）。
- 切换到其他页面再切回，输入框内容（提示词、附件）完整保留。

### 修改位置

**`src/pages/Home.jsx`**：将 `CreationPage` 从条件渲染改为始终挂载 + `display:none` 切换：
```jsx
<div style={{ display: activeKey === 'create' ? 'flex' : 'none', flexDirection: 'column', position: 'absolute', inset: 0 }}>
  <CreationPage ... />
</div>
```

**`src/pages/CreationPage.jsx` — `handleSend()`**：移除发送后的清空块：
```js
// 发送后不主动清空输入框和附件，保留内容便于连续创作
```
失败时的 `onFail` 回调（从 `savedContentRef` 恢复）保留原位，现在相当于幂等操作，不影响逻辑。

**`src/pages/CreationPage.jsx` — genType useEffect**：移除 Tab 切换时清空附件的副作用：
```js
// genType 切换时不再清空附件，保留用户已上传的参考素材
```

### 边界条件
- `display:none` 方案保持组件树常驻内存，适用于该场景；若将来 `CreationPage` 内存占用成为问题，需改为序列化 state 到外部 store 再重建的方式。
- 首尾帧模式切换（`handleRefModeChange`）有独立的帧槽位迁移逻辑，不受影响。
- 配音模式的声音参数（`selectedVoiceId`、`selectedVoiceName`、`dubbingSpeed`、`dubbingEmotion`）同样不再被发送清空，Tab 切换也不影响。

### 回归测试
1. 输入提示词 + 上传参考图 → 点击发送 → 确认内容保留在输入框。
2. 切换图片/视频/配音 Tab → 确认已上传的参考素材不被清空。
3. 在创作页输入内容 → 切换到资产库页 → 切回创作页 → 确认内容完整保留。
4. 发送失败场景：手动断网或触发错误 → 确认内容不丢失，Toast 正常显示。

### 验证结果
`npm run build` 通过，无新增错误。

## Bug 3：参考图删除后，提示词中对应的 @ 标签未联动删除；同名文件互相误删

### 问题现象
两个关联症状：

1. **标签不删**：上传参考图 A 并在提示词中 `@A`，点击参考图卡片上的删除按钮后，编辑器里的 `@A` 标签**没有被删除**，形成悬空标签（指向已不存在的文件）。
2. **标签删错**：上传参考图 A、B，分别 `@A` 和 `@B`，删除参考图 B 时，A 的标签也被一并删掉。

反向操作（在提示词编辑器中手动删除 `@` 标签）不应影响参考图列表——这是正确行为，单向约束，维持不变。

### 根本原因
两个叠加问题：

**1. DOM 操作放在 `setFiles` updater 内**

`handleRemoveFile` 原本把删除 DOM 标签的逻辑写在 `setFiles` 的 updater 函数体内：

```js
setFiles((prev) => {
  const file = prev[index];
  if (file && editorRef.current) {
    editorRef.current.querySelectorAll('[data-file-ref]').forEach(tag => {
      if (tag.dataset.fileRef === file.name) tag.remove(); // ← updater 内操作 DOM
    });
  }
  return prev.filter((_, i) => i !== index);
});
```

React 18 updater 是纯函数语义，Strict Mode 下会被调用两次，执行时机不可预期。DOM side effect 放在 updater 内不可靠，导致标签实际未被删除（症状 1）。

**2. 用 `file.name` 作为匹配键**

`buildTagElement` 用 `file.name` 写 `data-file-ref`，`handleRemoveFile` 也用 `file.name` 匹配 DOM 标签。同名文件无法区分，删一个会把所有同名标签全删（症状 2）。

### 正确行为
参考图与 `@` 标签是**单向映射**关系：

| 操作 | 期望行为 |
|------|---------|
| 删除参考图卡片 | 提示词中对应的 `@` 标签同步删除 |
| 删除提示词中的 `@` 标签 | 参考图卡片**不受影响** |

### 修改位置
`src/pages/CreationPage.jsx`

**a. 将 DOM 操作移出 updater**，在事件处理函数体内同步执行：

```js
const handleRemoveFile = (index) => {
  const file = files[index]; // 直接读当前 state，不进 updater
  if (file) {
    if (file._objectUrl) URL.revokeObjectURL(file._objectUrl);
    if (file.previewUrl?.startsWith('blob:')) URL.revokeObjectURL(file.previewUrl);
    if (editorRef.current) {
      const matchKey = file._uid || file.name;
      editorRef.current.querySelectorAll('[data-file-ref]').forEach((tag) => {
        if (tag.dataset.fileRef === matchKey) tag.remove();
      });
      setHasContent((editorRef.current.innerText ?? '').trim().length > 0);
    }
  }
  setFiles((prev) => prev.filter((_, i) => i !== index));
};
```

**b. 引入 `_uid` 唯一标识**，`makeUid()` 提升为模块级函数（供 `InputCard` 内外共用）：

```js
function makeUid() {
  return Math.random().toString(36).slice(2, 10) + Date.now().toString(36);
}
```

所有文件进入 `files` 列表的 7 个入口均补 `_uid`：本地上传（`handleFileSelect`）、资产库选取（`handleAssetConfirm`）、创作历史「用作参考图」（`onUseAsRef`）、reEdit 预填（`prefillData.files`）、首尾帧迁移回普通参考图、liveMats（真人素材）、粘贴上传。

`buildTagElement` 改用 `file._uid || file.name` 写 `data-file-ref`，匹配时同样使用此键。

反向方向（标签内 × 按钮的 `mousedown`）只操作 DOM，不触碰 `files` state，单向约束天然成立。

### 边界条件
- 未被 `@` 引用的参考图删除时，`querySelectorAll` 匹配不到任何节点，操作幂等，无副作用。
- 历史遗留 file 对象（如 `savedContentRef` 恢复的旧 files）可能没有 `_uid`，兜底用 `file.name` 匹配，不会崩溃，但同名多文件仍会被一并删除（极端降级场景，可接受）。
- `_uid` 只在前端运行时存在，不参与任何接口参数。

### 回归测试
1. 上传参考图 A → `@A` → 删除参考图 A → 确认 `@A` 标签消失。
2. 上传参考图 A、B → 分别 `@A` 和 `@B` → 删除 B → 确认只有 `@B` 被删，`@A` 保留。
3. 上传两张**同名**图片 → 分别 `@` 两张 → 删除第一张 → 确认只有第一张标签被删，第二张标签保留。
4. 在编辑器中点击 `@` 标签的 × 按钮删除标签 → 确认参考图卡片**不被删除**。
5. 删除所有参考图 → 确认编辑器内所有 `@` 标签清除，`hasContent` 状态正确更新。

### 验证结果
`npm run build` 通过，无新增错误。

## Bug 4：创作历史图片「用作参考图」时，文件名固定为 `creation.png`

### 问题现象
在创作历史中点击图片卡片上的「用作参考图」，该图片以 `creation.png` 的文件名添加到参考图列表，`@` 标签也统一显示为 `creation`。多张不同图片用作参考图时，名称完全相同，无法区分来源。

### 根本原因
`onUseAsRef` 回调中硬编码了 `name: 'creation.png'`，未使用卡片上已有的 `card.prompt` 字段。

### 正确行为
文件名取该图片生成时提示词的前 6 个有效字符（去除文件名非法字符），兜底为 `creation`。

### 修改位置
`src/pages/CreationPage.jsx`，`onUseAsRef` 回调：

```js
const promptSlug = (card.prompt || '')
  .replace(/[\\/:*?"<>|\s]+/g, '')
  .slice(0, 6) || 'creation';
const newFile = { name: `${promptSlug}.png`, _uid: makeUid(), ... };
```

### 边界条件
- 提示词全为特殊字符时，`replace` 后为空字符串，兜底为 `creation`。
- 提示词长度不足 6 字时，取实际长度，不补全。
- 文件名仅用于前端显示，不影响后端接口参数（图片 URL 和 `assetId` 不变）。

### 回归测试
1. 提示词为「一只在海边奔跑的猫」→ 用作参考图 → 确认显示为 `一只在海边.png`。
2. 提示词为空或全特殊字符 → 确认兜底为 `creation.png`。
3. 同一张图片两次「用作参考图」→ 确认两个条目 `_uid` 不同，互不干扰。

### 验证结果
`npm run build` 通过，无新增错误。

## Bug 5：图片和视频创作共用输入内容，切换模式后提示词和参考素材互相覆盖

### 问题现象
在图片创作模式下输入提示词 AAA 并上传参考图 A001，切换到视频创作模式后继续输入提示词 BBB 并上传参考视频 B001。再次切回图片或视频模式时，输入框和参考素材无法分别恢复，两个模式的内容会互相覆盖或显示错误。

### 根本原因
`InputCard` 原本只有一份本地输入状态（提示词编辑器、`files`、首尾帧文件等）。切换生成类型时组件会按 `genType` 重挂载，若没有按类型保存草稿，旧模式的输入内容无法恢复；同时切换页面时还可能因为组件卸载导致本地 state 丢失。

### 正确行为
- 图片模式独立保存图片提示词和参考图，切回图片模式时恢复 AAA 和 A001。
- 视频模式独立保存视频提示词和参考视频，切回视频模式时恢复 BBB 和 B001。
- 图片和视频之间切换不会互相覆盖；切换到其他页面再返回时，各模式的草稿仍然保留。
- 富文本提示词中的 `@` 参考素材标签、普通参考素材、视频首尾帧和视频参考模式与对应类型草稿同步恢复。

### 修改位置

**`src/pages/CreationPage.jsx`**：在页面级增加按生成类型分桶的 `inputDrafts`，分别保存 `image`、`video`、`dubbing` 的 `prompt`、`promptHTML`、参考素材、首尾帧和参考模式；通过 `handleDraftChange` 接收 `InputCard` 的输入变更。

**`InputCard`**：接收当前类型的 `draft` 和 `onDraftChange`，输入变更、发送前和素材变化时回写对应类型草稿；切换 `genType` 或重新挂载时，恢复该类型草稿，并重建富文本中的 `@` 标签节点。

**`CreationResultState` / `CreationEmptyState`**：将当前类型草稿和回写回调透传给 `InputCard`，确保结果态和空状态使用同一份类型隔离数据。

**`src/pages/Home.jsx`**：创作页保持挂载，仅通过 `display: none` 切换页面可见性，避免离开创作页时输入组件卸载。

### 边界条件
- 没有历史草稿时使用空提示词、空参考素材和默认参数，不影响首次进入创作页。
- 恢复富文本内容时会重新创建 `@` 标签的交互节点，避免仅恢复 `innerHTML` 后标签失去点击和删除能力。
- 切换视频参考模式时，首尾帧与普通参考素材仍按原有迁移逻辑处理，并写回视频草稿。
- 配音草稿也使用独立分桶，保持原有声音和输入状态隔离，不与图片、视频互相影响。

### 回归测试
1. 图片模式输入 AAA、上传 A001 → 切换视频模式 → 确认输入框为空。
2. 视频模式输入 BBB、上传 B001 → 切回图片模式 → 确认恢复 AAA 和 A001。
3. 再切换到视频模式 → 确认恢复 BBB 和 B001。
4. 在创作页输入图片和视频草稿 → 切换到资产库或项目页面 → 返回创作页 → 确认两种模式的内容分别保留。
5. 恢复包含 `@` 标签的草稿 → 确认标签可正常显示、点击和删除。

### 验证结果
`npm run build` 通过，`git diff --check` 通过，无新增错误。

## Bug 6：图片和视频创作最大并发数量上限为 5，无法满足连续创作需求

### 问题现象
图片和视频创作同时进行的任务数量达到 5 个后，发送按钮被禁用，用户必须等待已有任务完成后才能继续提交新的创作请求，无法满足需要同时进行更多创作任务的场景。

### 根本原因
`InputCard` 的并发限制逻辑将图片、视频和配音统一按 5 个任务判断。达到限制后，`canSend` 返回 `false`，发送按钮同时显示“当前有 5 个任务进行中”的提示。

### 正确行为
- 图片创作最多允许 10 个任务同时进行。
- 视频创作最多允许 10 个任务同时进行。
- 配音创作继续保持最多 5 个任务同时进行，避免改变原有规则。
- 达到对应类型上限时，发送按钮禁用并显示准确的上限数量。

### 修改位置
`src/pages/CreationPage.jsx`，`InputCard` 内的并发限制和发送按钮提示：

```js
const concurrentLimit = genType === 'dubbing' ? 5 : 10;
const atConcurrentLimit = activeCount >= concurrentLimit;
const canSend = !disabled && !atConcurrentLimit && (...);
```

发送按钮达到上限时复用 `concurrentLimit` 生成提示文案，图片和视频显示 10，配音显示 5。

### 边界条件
- 并发数量按生成类型分别统计，图片任务不会占用视频任务的并发名额，反之亦然。
- 配音上限保持为 5，不因图片和视频上限调整而变化。
- 并发数未达到上限时，发送按钮沿用原有的内容校验和禁用逻辑。

### 回归测试
1. 图片模式连续提交 10 个任务 → 确认第 10 个可以提交，第 11 个被拦截并提示当前有 10 个任务进行中。
2. 视频模式连续提交 10 个任务 → 确认第 10 个可以提交，第 11 个被拦截并提示当前有 10 个任务进行中。
3. 图片已有 10 个任务时切换到视频模式 → 确认视频仍可提交至 10 个任务。
4. 配音模式提交 5 个任务 → 确认第 6 个仍按原规则被拦截并提示当前有 5 个任务进行中。

### 验证结果
`npm run build` 通过，`git diff --check` 通过。构建仅保留原有警告：`src/api/config.js` 存在动态与静态导入，JS 包体积超过 500 kB。
